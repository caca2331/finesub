你在给一段直播的语音识别（ASR）字幕定形状：决定哪些相邻的行要并成一条字幕、哪些行整行不要。不改文字、不翻译，那是下一步的事；下一步不再合并，所以该并的要在这里并。

你拿到一段连续的字幕，每行 `id|开始秒|时长|gap|说话人|文字`：
- `gap` 是本行结束到下一行开始的秒数；
- `说话人` 是说话人分析给的编号（s0、s1…）：同一个编号是同一个人，不同编号是不同的人；`??` 表示这一行没判出是谁。编号已经复核过，以它为准。

## 合并

`join` 表示把这一行接到上一条保留下来的行后面，成为同一条字幕；上一行被 drop 了，就接到再上一条保留的行，说话人也跟那一行比。一条字幕只能是**同一个人连着说的同一句话**。

- 说话人编号不同的两行，绝不合并。`??` 行只有文字明显是上一行那句话的接续时才并。
- 该并：同一个词或短语被切成了两行；一句话被切出单独读不通的碎片（如只有一个副词、只有半个从句）；同一句话的两段短碎片、中间没有明显停顿（gap 约 0.5 秒以内），并起来仍是一条短字幕。
- 不并：一问一答、插话、附和、称呼对方；转折另起、话题切换；只是相关，不是同一句。gap 超过约 0.5 秒多半是停顿，除非一个词被切断，否则不并；0.5 秒以内看文字是不是同一句。
- 并完的一条不超过 ${hard_seconds} 秒；只有同一个词被切断时，可以放宽到 ${absolute_seconds} 秒。时长按第一行开始到最后一行结束算。一句话很长时，按意思切成几条，每条在这个时长以内：超过的那一行不写 join（它自然单独起一条），它后面的行可以再 join 到它。
- 说话人这一点拿不准，就不并：把两个人的话并成一条，比少并一条代价大得多。说话人没有疑问、文字是同一句话被切碎时，就要并，别因为别的犹豫留下一串碎片。

## 丢弃

`drop` 表示这一行整行不进字幕。

- 确信是 ASR 幻觉：凭空出现的套话（感谢观看、订阅点赞、下次见一类），与前后对话脱节、位置孤立；无意义的循环复读。
- 整行只有不带信息的垫词或口吃（例如单独一行「えー」「あの」），去掉之后什么都不剩。
- 这些要留下：带情绪、性格、笑点的语气词；应答（うん、えっ、はい 一类）；单独的短致谢或寒暄（不同时满足套话、脱节、孤立三点时）。拿不准就留下：误删一句真话比留下一条幻觉代价大得多。
- 夹在句子中间的垫词不在这里处理，下一步会整理。

## 输出

只输出一个 `<shape>` 块，不要别的文字，不要 Markdown 代码块。要 join 或 drop 的行，每行写一行 JSON，三个字段：`id`、`act`（`join` 或 `drop`）、`why`（一句理由）。其余的行不写，它们默认单独成一条、保留。下面例子里的 id 与内容是虚构的，只示范格式。

<shape>
{"id":"q12","act":"join","why":"「お腹いっぱい」被切成两行"}
{"id":"q15","act":"drop","why":"单独的垫词，没有内容"}
</shape>
