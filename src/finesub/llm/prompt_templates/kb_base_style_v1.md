你在为字幕知识库里的一套翻译风格做一次性迁移。风格会注入给翻译字幕的模型：「约定」节的每一行是它要遵守的一条规则，「正例」「反例」用同一个 `[标记]` 演示对应的约定。

程序自带一套「出厂默认」风格（`<factory_default>`），用户没选风格时用它。下面 `<style_entry>` 是用户自己的一套风格，它写成时还没有出厂默认。这次要做的：把出厂默认里这套风格还没说到、又不和它冲突的约定补进去，让这套风格也有这些基础口味。

`<style_entry>` 里每行末尾的 `<!-- @k数字 -->` 是句柄，不是内容；标题行末尾那个 `$entry_handle` 指这套风格本身。

<style_entry>
$entry_text
</style_entry>

<factory_default>
$factory_text
</factory_default>

逐条看出厂默认「约定」节的每一行，按下面的顺序判断，取第一个成立的：

1. 这套风格的「约定」节里已经有同一个 `[标记]`：不加，也不拿来比内容。同一个标记说明用户已经管着这件事，按用户写的来。
2. 这套风格的「约定」节已经说了同样的意思（换了说法、换了标记也算）：不加。
3. 这一行**主要要求的事**和这套风格的某条约定相反：不加。相反有两种：两条同时照做，总有一条做不到（比如一条要保留口头禅、另一条要删掉）；或者一条要往某个方向做，另一条限制往这个方向做（比如一条要大胆意译，另一条要贴近原文），哪怕能凑出一个两边都勉强满足的折中，也算相反。拿不准算不算相反，也不加。
4. 主要要求的事不相反，只有附带的限定或其中一个分句相反（比如「可以 A，但不要 B」，而这套风格要 B；并列的几项里只有一项相反，也算这种；相反照第 3 条的两种算）：去掉相反的那部分，剩下的写成通顺的一句，不添原文没有的意思，标记不变。拿不准某个附带的限定算不算相反，按相反处理，去掉它。剩下的这句再从第 2 条起判一遍：已经说过的、仍然相反的、拿不准的，都不加。
5. 其余：原样加进「约定」节，标记和文字都不改。

另外：

- 这套风格已有的行一条都不改、不删、不挪。
- 出厂默认的正例、反例，只在对应的约定加进来时一起加，原样照抄，标记不变。约定没加，它的例子也不加；约定只加了一部分时，例子演示的若是去掉的那部分，也不加。
- 不碰「档案」节。
- 各节还能加的行数：$limits。要加的超过某节剩下的行数时，按出厂默认里的先后，只加放得下的。

输出：

`<knowledge_proposals>` 块里是要加的行，每条 JSON 只加一行，样子是：
{"op":"append_lines","entry":"$entry_handle","section":"约定|正例|反例 选一","content":"要加的那一行，以 [标记] 开头","reason":"为什么加；只加了一部分时写明去掉了哪部分"}
`content` 不带行尾的 `<!-- @k… -->`。一行都不加时写 `<knowledge_proposals></knowledge_proposals>`。

`<skipped>` 块里是出厂默认里没加的行，每条 JSON 记一行，样子是：
{"label":"出厂默认那一行的标记","section":"约定|正例|反例 选一","why":"$skip_reasons 选一","line":"这套风格里让你判成重复、相反或拿不准的那一行"}
- 只加了一部分的约定也在这里记一条，why 写「部分相反」；它的例子因为演示的是去掉的部分而没加时，why 也写「部分相反」。
- `line` 照抄 `<style_entry>` 里的那一行，不带行尾的 `<!-- @k… -->`；why 是「约定没加」或「放不下」时写 `""`。
- 出厂默认的行全都加了时写 `<skipped></skipped>`。

除了 `<knowledge_proposals>`、`<skipped>` 这两个块，不要输出别的内容。
