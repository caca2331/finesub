短片段合并策略（仅作用于 `<translated>`）：
合并必要性判据：只有当**不合并会严重影响字幕阅读体验或语义准确**（典型：同一个词/短语被切断成不可读碎片）时，合并才是必须的；其余一切合并都只是可选优化，存疑一律保持分开。
1. 直接在 `<translated>` 中逐条纠错、翻译并按需合并。终稿以合并后时长/字数为准；harness 不会提供合并候选。通常只使用单源；同一句被切开时最多合并两个连续源。三源仅限 filler 三明治（两段正句碎片夹一个 ≤${thr_filler_max_chars} 字纯语气词/口吃碎片，合计 ≤${thr_sandwich_max_seconds} 秒、合并后 ≤${thr_sandwich_max_chars} 字）；其余三源及以上禁止。至少 2/3 的源片段通常无需合并。
2. 只有相邻片段确属同一语义单元、且合并后不触发**硬门槛**（加权字数 >${thr_hard_chars} 或跨度 >${thr_hard_seconds} 秒）时才合并。相邻、连贯、同一句或话题相关都不构成合并理由。越过硬门槛原则上必须拆开；唯一可特批的是同一个词或不可拆固定短语被源切断，且须说明理由（capableB 写在 note，capableC 写在前置 `#` 注释）。即使特批，加权字数 >${thr_absolute_chars} 或跨度 >${thr_absolute_seconds} 秒也触发**绝对门槛**，任何情况都必须拒绝。
3. **换人说话绝不合并**：依据$speaker_basis判断说话人，一旦是不同人（问答、插话、旁白与台词交替等），即使相邻、gap 极小、语义相关也必须分开；无法确认是否同一人时按不同人处理。此外有明显停顿、转折、情绪变化、话题切换，或仅仅“相关”而非同一句时，也保持分开。ASR 质量差或连续弱信息的区间尤其不要打包。
4. **合并行检查**：已合并行先检查末源是否更宜独立或留给后句；若是则 void 并缩窄范围。越过 ${thr_hard_chars} 字/${thr_hard_seconds} 秒硬门槛时，只要不是同一个词或不可拆固定短语被切断，就必须拆回多条；越过 ${thr_absolute_chars} 字/${thr_absolute_seconds} 秒绝对门槛时无条件拆回。合并行 note 可短写“词中接回”等结论。

补充：应合并 = 近邻碎片、$merge_connect_basis明确组成同一句且为同一人连续发声；应保持分开 = 换人说话（存疑亦按换人）、仅相关、明显停顿、转折另起或问答轮替；源数遵守上述合并规则。
