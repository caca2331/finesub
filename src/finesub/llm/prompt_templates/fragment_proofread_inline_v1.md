你刚交的 `<translated>` 通过了本地校验。交卷之前再校对一遍：把它当成一段字幕成品，从头到尾重读，找出错误并改掉；不改字幕的划分。

下面「改什么」「不改」两节原是写给单独校对成品的人的，对你来说：
- 「识别原文」是 `<asr_result>` 里那一行的 ASR 原文；「纠错文」「译文」「把握」「备注」是你 `<translated>` 里那一行的 `corrected_text`、`translation`、`conf`、`note`；
- 「序号」是那一行的 `position`，合并行是它那一串源序号；
- 「资料」「翻译风格」是${instructions}与${first_message}里给你的背景资料、知识库词条与翻译风格；「标题带『专名与术语』的段」对你是背景资料 JSON 里的 `entities`、`terminology` 两个列表与知识库词条里的专名，「识别常见的听错」是其中的 `asr_risks` 列表；
- `字/秒` 是译文的字数（英文字母、数字和标点算半个字）除以这一行在时间轴上的跨度（首源开始到末源结束）；超过线的行脚本已经点出来了，见后面的点名。

$criteria

## 脚本点名的行

脚本只查两件事：读速（第 2 条）和资料里定好的专名在译文里有没有出现（第 3 条）。点名只是提示，不是校对的范围：意思译错、听错这些脚本查不出，没点名的行照样要读；点了名的行也不一定要改（例如译文用代词承接了前面的人名，或原文的专名本来就该按上下文译成别的说法）。
$flagged

## 输出

答案是一个 `<patch>` 块，块外不写说明文字。本地会把它叠到你刚交的 `<translated>` 上，再整份校验：
1. 第一行原样写 header：`$output_csv_header`。
2. 只写改了的行。每行的 `type` 与 `position` 照抄原行，一个字也不改（合并行照抄那一串源序号）；要改的是 `corrected_text`、`translation`，$copied 照抄，`note` 按下一条重写。$speaker_kept
3. `note` 写「类别编号：理由」，类别是上面「改什么」的编号（1–6），一行改了几处时写最要紧的那个；理由一句话，里面不要用 `|`。例如：`2：原译 1.2 秒 14 个字，删掉重复的「真的」`。
4. 不写 `discard` 行，不合并、不拆开，也不写没改的行。没有要改的行时，`<patch>` 里只写 header 一行。
5. 不写 `<translated>`，其它块不必重交，本地沿用你刚才那份的。这一轮的答案以本条为准，代替${instructions}里交完整 `<translated>` 终稿的要求。
