精修字幕的噪音（必须谨慎对待）：
1. 精修字幕可能包含非音频内容（注释、屏幕文字、补充说明），可能拆行/合行/删行，也可能刻意跳过部分内容；时间轴可能与机器字幕存在整体偏移。
2. 精修行与 final 行不保证一一对应。只把时间重叠且内容明确对应的 final↔refined 差异当作纠错/翻译错误的证据；找不到明确对应关系的行（仅精修侧或仅机器侧）默认忽略，不得当作误听或错译的证据。

证据使用规则（按优先级）：
1. refined 与 final 的明确对应差异是最高优先级证据：既提炼知识（固定译名、人物/事件信息），也提炼这套风格的成类做法。注意：精修不是逐字对照的标准答案，精修者有意译、润色乃至信达雅重写的自由——差异不等于机器译错，也不要默认差异是 ASR 误听（判定标准见下方风格条目规则）。
2. `<feedback_slice>` 与 `<research_feedback>` 的 hint 指明方向；与精修差异或调查材料相互印证后写入。调查材料中带 `[unresolved]` 标记的结论是未经证实的猜测，不得作为任何提案的依据。
3. raw 与 final 的差异反映机器自己的修正，可信度次之，用作旁证。
4. `<kb_entries>` 中标注"（本任务前序块已更新）"的条目，只在出现新增证据时才再次更新；标注"（库中暂无）"的条目如证据充分可新建。
5. hint 带 `sub` 字段的（主词条-子词条定位），一律作为母词条的行级更新（append_lines / update）处理，禁止为 `sub` 新建独立词条。

$knowledge_structure

翻译风格条目（category `style`）：
1. 上面 `<kb_entries>` 里**至多有一个** `style` 条目：本次可写的那套风格（任务用 `--style`
   点名；点了多套时只有第一套会出现在这里）。风格类的更新**只写进它**，用它的行句柄
   （`@k…`）定位。没有 style 条目时本节不适用：**不要为此新建条目**，也不要去改别的类别
   ——一套风格由人建立并点名，不由本任务发明。你能动的只有它的行（`append_lines` 加、
   `update` 改、`remove` 删）；退休或改名整个条目不是本任务的权限。
2. 收录对象是**成类的做法**：这套风格反复出现的处理方式（句式取舍、语气与语域、称谓与
   自称、引号/标点习惯、长度与拆并）。判定前先排除两种：(a) 精修只是一次更凝练传神的
   意译，换个句子未必还这么做——差异≠约定；(b) 具体专有名词的误听或误译个例——那是词条
   的职责（写 knowledge_hints 让对应词条收录），不是风格。
3. 写法：一条约定一行，`append_lines` 进 `约定` 节，行首带一个 `[标记]` 作短名（如
   `[自称转换]`）；要举例就用**同一个标记**写进 `正例` / `反例`，两边都是 `原文 → 译文`
   ——反例箭头右边写那个**不该出现的译文本身**，不是「为什么不行」。
4. **每节都有上限**（预览里每节的「上限」行写着最多多少行、每行最多多少字，超了整批被
   拒）。满了还要加，就用基础 op 组合：`update` 改写一条、`remove` 删掉一条、或把两条并成
   一条再 `append_lines` 新的一条。加之前先自问：这条比现有哪一条更值得占位置？
5. **只动本次注入的那个 style 条目里的行。** 没出现在预览里的条目和行，你没有依据判断
   它们该不该留。
6. 不必每次都产出：这套风格里已经写清楚的做法不要换个说法再提一遍，没有新东西就输出空的
   `<knowledge_proposals>`。

收录边界示例（人造，展示判定，不要照抄内容）：
- ✅ 约定：`[自称转换] 说话者用自己名字自指时译文改用「我」`——同一段素材里反复出现，
  换个素材还成立。
- ✅ 正例：`[自称转换] Nono酱小时候被说是大总统 → 我小时候被夸过是「大总统」`——箭头两边
  只差这条约定演示的那件事。
- ❌ 不收：机器译「温格雷特号」、精修是「维恩歌莱号」——专名译名个例，写 knowledge_hints
  让对应词条收录。
- ❌ 不收：「这句精修更传神」——说不出是哪一类做法，就不是约定。
