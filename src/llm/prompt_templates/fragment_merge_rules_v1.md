短片段合并策略（仅作用于 `<translated>`）：
合并必要性判据：只有当**不合并会严重影响字幕阅读体验或语义准确**（典型：同一个词/短语被切断成不可读碎片）时，合并才是必须的；其余一切合并都只是可选优化，存疑一律保持分开。
1. 先完成 singles 一一对应稿（note 给五选一取舍结论），再写 translated。终稿以合并后时长/字数为准，可拒绝 singles 建议；harness 不会提供合并候选。通常只使用单源；同一句被切开时最多合并两个连续源。三源仅限 filler 三明治（两段正句碎片夹一个 ≤3 字纯语气词/口吃碎片，合计 ≤4 秒、合并后 ≤16 字）；其余三源及以上禁止。至少 2/3 的源片段通常无需合并。
2. 只有相邻片段确属同一语义单元、且合并后不触发软门槛（加权字数 >20 或跨度 >4 秒）时才合并——软门槛是默认边界，不是“尽量”。相邻、连贯或话题相关都不构成合并理由；只有拆开会把一个不可分语义单元切碎时才可越过软门槛，其中字数不得超过 36，且须在 note 说明；7 秒硬上限绝不突破。
3. **换人说话绝不合并**：依据$speaker_basis判断说话人，一旦是不同人（问答、插话、旁白与台词交替等），即使相邻、gap 极小、语义相关也必须分开；无法确认是否同一人时按不同人处理。此外有明显停顿、转折、情绪变化、话题切换，或仅仅“相关”而非同一句时，也保持分开。singles 邻接预判是草稿，不强制终稿合并。ASR 质量差或连续弱信息的区间尤其不要打包。
4. **合并行检查**：已合并行先检查末源是否更宜独立或留给后句；若是则 void 并缩窄范围。字数 >20 时，若源间存在自然断点且拆后各段均 ≥1 秒，优先拆回多条；只有不可分的极少数情况才保留，且不得超过 36。合并行 note 可短写“口播碎片成一句”等结论。
