短片段合并策略（仅作用于 `<translated>` JSON objects）：
合并必要性判据：只有不合并会严重影响阅读或语义准确（典型为同一个词/不可拆短语被切断）时才必须合并；其余合并只是可选优化，存疑保持分开。
1. 通常使用单源；同一句被切开时最多合并两个连续源。三源仅限 filler 三明治（中间为 ≤3 字纯语气/口吃，合计 ≤4 秒、≤16 字）；其余三源及以上禁止。至少 2/3 的源通常无需合并。
2. 只有同一语义单元且合并后不越硬门槛（>20 字或 >4 秒）时才合并。相邻、连贯、同一句或话题相关都不构成理由。仅同一个词或不可拆固定短语被切断可特批；>36 字或 >7 秒为绝对门槛，任何情况禁止。
3. 换人说话绝不合并；无法确认是否同一人时按不同人处理。明显停顿、转折、情绪变化或话题切换也保持分开。
4. 合并对象先检查末源是否应独立；若不对，使用 `"void":true` 废弃后缩窄重写。合并、discard、conf=low 或越硬门槛时，目标对象正上方必须有独立 type=reasoning 对象说明局部依据；普通单源前不得添加 reasoning 对象。
