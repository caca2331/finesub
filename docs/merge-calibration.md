# 精修标定的合并参考（软门槛）

从八组精修字幕 vs raw ASR 的离线标定中抽出的**仍有效**参考——数值是保守先验，
不是脱离语义的硬分类器；生产契约以当前 `PROMPT_VERSION` 与变体 fragment 为准
（见 `llm_prompts.md`、`tools/prompt-iterate.md` §4）。

时间轴判定以 **raw ASR** 的 gap / 跨度为准（精修 SRT 常 re-time，只作译文/语义参考）。

## 总体理念

1. **默认不合并**：窗内至少约 2/3 源保持单条；合并是补救 ASR 过度切分，不是默认动作。
2. **语义单元优先于逐行对齐**：允许中文语序相对 `corrected_text` 小幅错位。
3. **错并代价高于漏并**：合并后的源序号在下游不可拆回；不确定则分开。
4. **元字幕另处理**：4+ 源、「观众：」开头、跨度 >9s 或加权字数 >45 的碑文/长 meta，不走常规模板。

精修基率（明确对应组）：约 **17.5%** 为合并组；合并组中约 **70%** 为 2 源。样例窗
`BV1ojjc6MEAs` / `0001` matched 压缩约 **31%**——可作「并量是否离谱」的粗对照，不能当质量分。

## 机械信号（soft）

| 信号 | 合并且常见 | 分开常见 | 操作含义 |
| --- | --- | --- | --- |
| 相邻 gap | p50≈0.23s；2 源约 64% &lt;0.35s | 未合并邻接 p50≈0.59s；≥0.5s 强倾向分开 | &lt;0.35s 才考虑；≥0.48s 默认否 |
| 片段时长 | 合并侧单条 raw 多 &lt;4s | 任一侧已是较长完整句 | 两侧都偏短更易并 |
| 合并跨度 | 2 源 p50≈3.3s | — | 软门槛约 4s；绝对硬顶仍宜 ≤7s |
| 加权字数 | 2 源合并 p50≈13.5 | 两个单源合计 p50≈20.5 | 合计偏短才并；硬顶见变体契约 |

仅靠 gap + 字数 + 跨度会同时漏真合并、误并「两句完整但贴得很近」——**必须有语义闸门**。

加权字数：拉丁/数字/标点/空格=0.5，其余可见字符=1（`subtitle_metrics.weighted_char_count`）。

## 语义闸门

**宜合并**：同一未完句被切碎；短反应/语气填充贴紧后续意群；专名被撕成两段。

**宜分开**：话题/情绪转折（`でも` / `いや` / `待って` 等）；问答轮替或前句已完整再起信息
（即便 gap≈0）；换人说话；观众注/碑文块。

## 模型与契约形态（历史结论，仍适用）

| 观察 | 含义 |
| --- | --- |
| `gemini-3.1-flash-lite` 在长窗 mm 纠错 prompt（常 ~50k–70k input）上常报 **thinking_tokens=0** | 不要假设 lite 会在幕后用 thinking 消化检查表；规则须落在显式中间步骤或决策点 reasoning（现行 capableC / basicB 路径） |
| 弱模型「一步写完合并+翻译」不稳定 | 曾用整窗 `<singles>` 外化草案（更贵）；现行默认多用去-singles + 局部 reasoning，见变体表 |
| 强模型可在单块终稿内自洽 | note 字数自查 + `<void>` 回收（更省 token）对 3.5 级更合适；勿把只对强模型成立的契约硬套 lite |
| reasoning 里口述 `` `<translated>` `` 标签名 | 旧「首开→首闭」提取会污染校验；生产用 nesting-aware 顶层块提取，prompt 要求用「终稿块」等指代、勿写尖括号字面量 |

离线 gold / 非对称代价评分（overmerge > undermerge 等）属迭代床专用材料，留在本地
`docs/report/`；不要把压缩率或 validation-ok 当成质量分。
