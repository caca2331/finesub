# ASR 稳定化

`python -m finesub.speech.postprocessing.stabilization` 是 VAD-ASR 对齐之后、raw SRT 和 LLM 消费之前的独立 stage：读取
`*-aligned.json`，按 profile 清理或标记 ASR segment，输出 `*-stable.json`。源码和 CLI
实现位于 `src/finesub/speech/postprocessing/stabilization.py`，安装后入口为
`python -m finesub.speech.postprocessing.stabilization`。

```text
*-aligned.json -> ASR stabilization -> *-stable.json
```

## CLI 与 pipeline

```powershell
python -m finesub.speech.postprocessing.stabilization out/input/input-aligned.json `
  -o out/input/input-stable.json --profile 0

python -m finesub.pipeline data/input.wav --stage stable --asr-stabilize-profile 0
```

独立 CLI 参数为 `--profile {-1,0,1,2,3}`；pipeline 和 batch 对应
`--asr-stabilize-profile`，默认均为 `0`。这与最终中文字幕 SRT 的
`--postprocess-profile` 是两套互不相关的 profile。

pipeline 顺序为：

```text
vocal -> aligned -> stable -> raw-srt -> translated-srt -> final-srt
```

## Profiles

### Profile -1：原样复制

输入仍会执行 JSON/schema 校验，但不会解析后重写输出；校验成功时，`stable.json` 与输入 aligned 保持字节一致。

### Profile 1：常见套话幻觉清理

在 segment 的 `words` 拼接文本中查找精确的
`ご視聴ありがとうございました`。一次匹配只有在组成它的 word 不超过 5 个时才处理：

- 删除匹配字符及其后直接相连的 Unicode 标点；
- 完全变空的 word 删除，部分命中的 word 保留剩余文本，例如
  `ありがとうございました!ではまた` 保留为 `ではまた`；
- 根据剩余 words 重建 `text`；只有首/尾 word 被删空时才把 segment `start`/`end`
  收缩到新的首/尾 word，中间删除不改变外边界；
- 部分 word 保留原时间，segment/word confidence、`no_speech_prob`、energy 等诊断值不重算；
- 没有剩余 word 时删除整个 segment；没有 word-level 数据的 segment 不处理。

同一 segment 内所有符合条件且不重叠的精确匹配都会清理。

认识论口径（2026-08-05，用户确认）：这条精确短语删除并没有"原理上正确"的判别子——
它成立靠的是**先验赔率**：该短语的真实语音出现极罕见而幻觉极高频（全语料未见确认的
真实出现；曾疑似的 H6 PV 片尾两行后查明保留自 LLM 产物、相邻 `おわり` 经用户重听为
幻觉，此两行大概率同为幻觉）。`套话幽灵` 的语速判据同理，只是把赔率换成了物理
不可能性。幻觉的工程化判断到此为止；进一步压误删要靠**低幻觉第二模型校验**
（Qwen3 ASR 对嫌疑段重认，已实施为 `--qwen-verify`，默认 auto），见 [`vad-asr.md`](vad-asr.md)「数据流」一节里「第二模型校验证据」那段与
「哪些异常交给 Qwen 裁判，哪些不交」。

### Profile 2：高噪音标记

输出 tag 放在 segment 的 `tags: string[]`；按下列固定顺序追加且不重复，无 tag 时省略字段：

1. `高度疑似幻觉`
2. `高度疑似语气填充词`
3. `套话幽灵`
4. `第二模型否决`
5. `语言切换幻觉`
6. `时间漂移`

指标定义：

```text
duration = end - start
rate = (weighted_char_count(text) - 2) / duration
high_speed = rate > 20

weighted_word_confidence =
  sum(weighted_char_count(word) * word.confidence)
  / sum(weighted_char_count(word))

low_conf = segment.confidence < 0.3
           and weighted_word_confidence < 0.3
low_energy = vad_weighted_energy_db < 0
very_low_energy = vad_weighted_energy_db < -20
```

weighted word confidence 只纳入具有有限数值 confidence 且权重大于 0 的 word。
`weighted_char_count` 的共享口径为：拉丁字母、Unicode 数字、标点和空格计 `0.5`，
其他可见字符计 `1`，组合符和不可见控制/格式字符计 `0`。“去标点后字数”先删除 Unicode
category `P*`，再使用同一加权公式。

判定按三个独立 `if` 执行，因此一个 segment 可以获得多个 tag：

```text
energy_exempt = weighted_word_confidence > 0.9
                and vad_weighted_energy_db > -80    # 不在测量地板上

if (not energy_exempt
    and ((duration > 0.1 and very_low_energy)
         or (去标点后字数 <= 2 and very_low_energy)))
   or (low_conf and low_energy):
    tag += 高度疑似幻觉

if low_conf and energy存在 and not low_energy and 去标点后字数 <= 2:
    tag += 高度疑似语气填充词

if high_speed or low_conf or low_energy:
    tag += 时间漂移
```

阈值全部是上述严格比较。缺失、非数值或非有限 confidence/energy 不命中依赖该指标的
条件；但 `low_conf` 本身仍会命中“时间漂移”。

`energy_exempt`（2026-08-05 新增）：对 H6dTZf9QFTY 全程人工字幕的删除审计发现，
very_low_energy 两条腿的实际误删形态是**时间轴坍缩/漂移的真实语音**——词被量化到 20ms
点或整段位移后，能量采样落在静音处，而 decoder 对每个词都高度自信（实测受害段词加权
置信 0.92–0.99、能量 −24～−68dB）。词置信严格高于 0.9 且能量不在 −100dB 地板附近时，
能量证据不再触发丢弃，段降级为 `时间漂移` 保留；地板条件挡住纯静音上的自信幻觉
（kaguya60 的 `音楽`×5，e=−100）。79 份产物回归：仅 H6 变化（挽回 5 段人工确认的真
内容，另保留 4 段同族歌词回声/软语气词）。高置信的复读与已知短语幻觉不受影响——
它们由词级规则与 profile 1 短语清理负责。

`套话幽灵`（2026-08-05 新增，**参与 profile 0 丢弃**）：整段就是 Whisper 惯用收尾套话
（`おわり` / `それではまた` / `ありがとうございました`，归一化后 ≤ 短语+2 字），且被压进
物理不可能的时长（>20 字/秒，即时长 < 短语字数×50ms）。全语料审计（74 份产物 +
400 窗 sweep + 参照对照）：该形态的每一次出现都是幻觉（含此前唯一漏网的
`yui:37` 残留），而确认的真实出现（H6dTZf9QFTY 直播收尾致谢，Qwen 双模型重认证实）
语速正常、距阈值 ~2 倍裕度。**confidence 不能分离真话与幻觉**（重叠区间 0.16-0.999），
故判据只用语速；更长的真句子只是包含套话时被整段长度上限排除。
出处更正（2026-08-05）：H6 的两处正常语速 `おわり` 最初被当作"人工保留的真话"反例，
后查明其保留来自 **LLM 纠错层产物**（H6 无人工字幕），用户重听确认**均为幻觉**——
即正常语速的套话幻觉真实存在，语速判据刻意不碰它们（无声学判别子）。
**第二模型证据补上这块**：带 `qwen_verify` 证据（vad-asr 尾部产出，docs/vad-asr.md）的整段套话，
**Qwen 在这一段什么都没听到**（证据去掉标点后为空）时也打 `套话幽灵` 丢弃；听到任何文字（是不是这句套话、
是什么语言都算）就留；无证据时维持只删语速幽灵。
**证据 veto** 是同一个读法：`高度疑似幻觉`/`高度疑似语气填充词` 两条噪声腿在 Qwen 听到文字时不触发——丢弃审计实测它们在正能量上删过真实喊叫
（kaguya `あ!`×2）。两处共用 `_second_model_heard_speech` 一个函数（owner 2026-10-24：同一套逻辑，以后要改也改这一处）；
`[stabilize] veto_level_floor` 打开时，安静档的段上 Qwen 听到的文字一律当作没听到：噪声腿不撤回，整段套话照删。
语速幽灵腿不看证据、不可 veto（判据是时间物理不可能，不是无声）。正常语速的 BGM 上套话（如 kaguya60
片头）由既有能量腿负责，精确短语 `ご視聴ありがとうございました` 仍由 profile 1
清理——三者分工互补。

套话证据腿原先的判法是「证据文本里没有这句套话就删」（2026-08-05 起，67 clip 标定 11/11），2026-10-24 改成上面的读法。
原判法删真话：短段上 Qwen 常把真话写成别的字或别的语种（真 "Thank you" 写成 "Tinggi"、「对」，真
「ありがとうございました」写成「ありがとうございます」）。读数（Qwen 按生产的前后 0.1 s 听）：精修字幕确认为真致谢、
整段是「ありがとうございました」形状的 30 行（hina 29、onetonton 1），原判法删 7 行（0.6B）/ 9 行（1.7B），现判法 0 / 0；本机全部带证据产物里走证据腿的
79 段套话形状段，原判法删 51、现判法删 25，多留的 26 段里 15 段 MAI2 证实有真话（9 段就是这句套话），另 11 段 Qwen 只听到语气词或笑声
（有 MAI2 的 4 段里 3 段那里没有这句话，是现判法放过的幻觉）。不在这次回放里的同类代价：下文英文套话一节壁炉那份回退产物，接进英文套话时重跑过一次裁判
（读数在 [`bench-baselines.md`](bench-baselines.md)「17.6c 修复：英文套话接进证据腿」的表里，「裁判回答『什么都没听到』」那行），送检的 80 段有 6 段被 Qwen 听成中文语气词，原判法删、现判法留。

⚠ **因 Qwen 听到别的话而留下的套话段，产物里没有标签**，优化这套读法的分支要自己筛：整段是套话形状（`_closing_phrase_of` 非空）、
语速腿没触发、`qwen_verify` 的文字非空却不含这句套话。`第二模型否决` 不覆盖它们，也不该覆盖——没有证据时套话段本来就保留，
Qwen 在这里只会加删除、不会撤回删除，「否决改变了结局」不成立。stable 里每段都留着原文与 `qwen_verify`，所以不需要反事实重放，
直接筛就能数出这根杠杆放过了什么。上面回放里多留的 26 段就是这样数出来的；其中 Qwen 只听到语气词或笑声的那 11 段是已知放过幻觉
最集中的一类，要收紧就从这里下手，改 `_second_model_heard_speech`（两处一起变），别在套话腿旁边另起一套判法。

**英文套话（2026-08-30 补）**：`CLOSING_GHOST_PHRASES` 此前**只有那三条日文**，
所以英文侧「自信的幻觉由短语清理兜住」这句注释是**空头支票**——P1 环境音语料的定长
回退跑里，壁炉那份 106 段幻觉有 61 段活到最后，其中 15 段 `Thank you.` 靠
`VERY_LOW_ENERGY_DROP_WORD_CONFIDENCE_EXEMPT` 豁免逃掉（词置信 0.952 vs 送检那批的
0.632，能量几乎一样：−63.0 vs −63.7 dB），而它们该撞的短语表根本不存在。现在拆成
两族：

| | 日文族 `CLOSING_GHOST_PHRASES_JA` | 英文族 `CLOSING_GHOST_PHRASES_EN` |
| --- | --- | --- |
| 离线语速腿 | **参与**（>20 字/秒） | **不参与** |
| 第二模型证据腿 | 参与 | 参与（**唯一入口**） |

⚠ 语速腿刻意不覆盖英文，两条理由都是实测的：**(a) 英文的失效形态是「拉长」不是
「压缩」**——漏网的 `Thank you.` 是 10 个字符摊 11.6 秒（0.86 字/秒），语速腿永远不会
响；**(b) 20 字/秒对拉丁文不是物理不可能，而是正常快语速**（≈200 wpm），把它套上去
只有单向伤害（无证据删掉真实的快嘴 "Thank you."）。所以英文族一律证据门控，
`CLOSING_GHOST_RATE_GATED_PHRASES` 就是这个边界，红验证钉着。

短语表来自那份语料的实际产出（369 行、8 种文本）而非民间清单：`Thank you.` 247、
被重分句切开的 `Thank` / `you.` 各 56、`I'm sorry.` 6。`thank` 单列是因为切分点
25/25 完全相接；**`you.` 故意不列**——三个字符会命中真实代词。它是已知缺口，
补它需要一条「相接半句合并后再判」的规则，不是加个字符串。

`第二模型否决`（2026-09-03 新增，**仅打标，不参与 profile 0 丢弃**）标记「噪声腿本来要丢它，
但第二模型在这一段听到了东西，所以撤回了丢弃」。**它不改变任何取舍**，记的是**为什么留下**。

加它是因为那个否决是一根很大的无声杠杆，而且有实测错误率：存档里它救回 49 段，**41 段救对、
8 段救错**——那 8 段的证据根本不是那一段音频的（2026-09-03 人耳听审定案：段内无语音）。⚠ **两个分母答的是两个问题，别混**：
**8/49 = 16.3%** 是「这根杠杆一旦拉动、有多大比例拉错」；**8/129 = 6.2%** 是「全部裁判判例里
有多大比例因此被错误保留」——前者衡量判据本身，后者衡量它对成品的代价。⚠ **在打标之前这 6.2% 在产物里
完全不可见**：`_profile_2_tags` 清掉两个标志之后，被救回的段和从未被怀疑的段长得一模一样，
所以那个错误率是靠反事实重放（把证据置空重跑）才反推出来的。现在它自己写在产物里。

判据是**「否决改变了结局」而不是「有证据」**：绝大多数带 `qwen_verify` 的段本来就不在危险中，
按后者打标会给几千段健康 segment 盖章、标记随之无用。存档实测这条判据在 **8752 段里命中 49 段**，
与反事实重放认定的集合**逐段一致（零漏零多）**。
这个标签只管两条噪声腿；套话证据腿为什么不打、它留下的段怎么筛，见上文「套话幽灵」一段末尾的 ⚠。

⚠ **不要顺手把它变成丢弃依据**：没有任何本地信号能把那 41 和 8 分开——加权能量、`confidence`、
`no_speech_prob`、证据与原文的音/形对应四个都试过并否掉了：加权能量门限 −22 dB 抓 3/8 伤 1/41、
−18 dB 抓 6/8 伤 6/41，伤的全是真台词；`confidence` 中位 0.233 对 0.205，完全重叠；
`no_speech_prob` 在存档里恒为 0；音/形对应两边都跨书写系统（救对 31/41、救错 7/8）。
唯一还活着的候选是**绝对 `frame_dbfs`**（注意与加权能量是两个量），但它的工作点是看完标注
才挑的、n=8，按 `README_DEV.md` 的开发原则必须先预注册再到新素材上验。
这个候选已经做成开关、**默认关**：`config.toml` 的 `[stabilize] veto_level_floor = true` 让带绝对
电平档（`vad_level_tier`）的段不再被否决救回，实测去掉 8 段救错里的 6 段、也去掉 41 段救对里的
4 段（取舍与理由在 `stabilization.py` 的注释、声明在 `finesub.settings.VETO_LEVEL_FLOOR`）。
它是 dev-only，不进 manual。

`语言切换幻觉`（2026-08-04 新增，**仅打标，不参与 profile 0 丢弃**）标记 CJK 主导素材里
突然出现的大段 Latin 低置信文本：

```text
run_gate = 全文件字母中 Latin 占比 < 0.3   # 真英文/双语素材整体关闭
segment 命中 = 字母数 >= 8
             and 段内 Latin 字母占比 >= 0.7
             and segment.confidence < 0.6
```

**为什么不丢弃**：405 窗口验证集上命中的确实全是幻觉（4/4、0 误报），但更大范围复核
（170 份产物 + 人工修正字幕对照）发现命中集合里混着两类**不能删**的东西——
(a) 真实英文内容：歌回/英配 PV 素材（H6dTZf9QFTY）里 `Yes, my lord!`、
`Making good, being you, that's alright` 等 15+ 行真实英文歌词/台词（最初依据 LLM 层
保留判定；2026-08-05 经 Qwen 双模型重认抽检 5/5 确认音频确为英文），
低置信只是因为唱歌难识别；(b) **翻译型幻觉**：BV1cqLR6hEp3 224–251s 底下是真实日语台词
（人工字幕：女皇陛下の偉大なる計画…），Whisper 输出了它的英文翻译——删除会连真实对话的
唯一痕迹一起丢掉，正确修复是强制语言重解（已实施为 `--lang-redecode`，目前只覆盖 group 语言票翻转的子集，见
[`asr-align.md`](asr-align.md)「语言票翻转重解」）。
标签保留给下游（LLM 纠错层、未来的强制语言重解触发器）作观测证据。
confidence 阈值按一遍式解码值标定；teacher-force fallback 路径存在约 −0.14 的系统偏差。

### Profile 3：确定性预合并（**已删除**，2026-07-29）

原 profile 3 调用 `src/premerge.py` 做词形强证据的词中接回。`segment_split` 迁到全局 DP
之后它失去了对象：DP 自己就在决定每一个 ASR 段接缝是否保留，词中切断的碎片在切分阶段
就不再产生。实测 9 clip 测试床（8BV + yui）——同一套 premerge 规则在**原始 ASR 分段**与
**旧逐段 split 输出**上各合并 1 处，在**新全局 split 输出**上合并 **0 处**。模块、
stabilize profile 3、`metadata.premerge`、`premerge_rejoined` /
`premerge_filler_attached` report 字段与相关测试一并删除。

历史结论仍然有效、迁移时请勿重犯：预合并当年必须排在 profile 2 之前，因为词中切断的碎片
天然低置信（`次はキッ|と` 的 `と` conf 0.089、能量为负），先跑 profile 2 会把它当幻觉丢弃、
词永久残缺。现在这条约束由「不产生这种碎片」满足，而不是由「事后修补」满足。

### Profile 0：默认稳定化

依次执行 profile `1 -> 2`，随后删除带 `高度疑似幻觉`、`高度疑似语气填充词` 或
`套话幽灵` 的 segment。只带 `时间漂移`、`语言切换幻觉` 或 `第二模型否决` 的 segment 保留
（后两个仅观测，理由见上）。

## 补救：坍缩行与空档

profile 0 的删除阶梯与[时间轴格式契约](#时间轴格式契约2026-09-06)之后，stable 这一步再补两件 ASR 漏掉的东西，
然后再过一次契约，最后才量[最终缺口](#最终缺口落盘speech_gaps2026-09-07)：

1. **坍缩行**：话是真的，段跨度却被挤到一秒不到，几十个字一闪而过，真正说这句话的人声多半就在这一行之后、没有别的行认领。
2. **空档**：至少 1 s 的 VAD 语音没有任何一行盖住：Whisper 没写出来，或者删除阶梯删掉的行让出了时间。

另有一件默认关的：**行内漏字**（`--row-fill auto | on | off`）：行的时间对，行里却少了几个字或一个短语，见下面[行内补漏](#行内补漏)。

这几件都要一个第二模型来听音频。`stabilize_payload` 本身仍不碰模型：stage 把补救做成一个回调传进去（`repair`），
判定在 `speech/postprocessing/recall_repair.py` 与 `row_fill.py`（纯函数），加载模型、切窗、解码在 `speech/verification/recall_decode.py`。
只在 profile 0 跑。先修坍缩、后补空档：修好的行先占回自己的时间，空档只看剩下没人认领的语音；行内补漏最后落定。
本集语言在回调里定：aligned 记的 `asr_align.language`（ASR 那一步被告知的语言），没记（自动检测时它记的是字符串 `"None"`）就取各行 `lang` 按实质字计的多数，平票取先出现的。
三件补救都不按语言开关（owner 2026-10-31 定放开；读数只在日语、普通话、英语上有）。Qwen 报不出名字的语言（`speech/languages.py` 的 20 种之外）也进来：
修坍缩照跑，补空档与行内补漏要 Qwen 报出本集语言，所以不补。读音只有日语（假名）与普通话（无调拼音）查字典，普通话与粤语都繁简归一，
其余语言逐字比；阶梯与行内补漏在靠空格分词的语言里改按词比（逐个字母比太松：两段英语几乎总能碰巧共享两个连续字母），越南语的词是单音节，一个词一块就是一个音节一块（普通话要两个）；
不靠空格又没有读音字典的语言（泰语）仍是逐字母比，正是英语按字母比时太松的那种情形。泰文、天城文的元音与声调符号比的时候去掉（只比辅音骨架），切片与插入时跟着它前面的字母走。
语气词表只有日语、汉语、英语，别的语言不去语气词。完整评测只做过日语与汉语，英语只有按外部转写读的放置与插行核对。

### 开关

`--squeeze-repair`、`--gap-fill` 与 `--row-fill`，各 `auto | on | off`；前两个默认 `auto`，`--row-fill` 默认 `off`（用户向说明在 `docs/manual/tuning.md`）。stage 只在 stable 这一步真要跑时构造回调
（`stages._recall_repair`）：Whisper 的设备照 ASR 那一步的问法（`resolve_asr_device`，CTranslate2 回答、受 `--gpu-tier` 管），Qwen 由它推出
（`tail_verify_device`），因为 stable 可能复用别的运行留下的 aligned，拿不到 ASR 那一步解析过的设备。

- `--qwen-verify off` 时三个 `auto` 都不跑（关了裁判的运行不想加载它）；显式 `on` 照跑。三件都不跑时不传回调，产物与不带补救时逐字节相同；行内补漏关着时记录也与没有它时相同。
- 回调里每件不是 `off` 的补救要人声轨、aligned 的 VAD 时间线、transformers 5.x、三个读音库与 Qwen 的加载；补空档与行内补漏另要 aligned 记的模型名与 Whisper 的权重（只缺这两样时只有它们跳过）。缺一样，`auto` 跳过并记进
  `recall.skipped`（缺人声轨、transformers、读音库或加载失败时往 stderr 打一行 `Warning:`；只是老产物没有 VAD 时间线或模型名不警告），
  `on` 报错退出。没有坍缩窗、没有空档、也没有行内补漏的筛子留下的行时不加载任何模型。这是两者唯一的差别：解码或判定出错时两种都报错。各行都没有语言时两种都跳过。不为缺人声轨重新分离。
  `recall.switches` 记的是生效的取值（`--qwen-verify off` 让 `auto` 变成 `off`；行内补漏不是 `off` 时多一个 `row_fill`）。
- 修坍缩的阶梯跑不了时退回只用拉长，不报错（见[坍缩行](#坍缩行)）。
- 设备只在真要加载模型时才问（复用 stable、三件都不跑时不碰 CTranslate2）；退到 CPU 时照跑，打一行 `Warning:`（Qwen 与 Whisper 都是 float32，长音频每小时约 6 分钟，GPU 上约 0.7 分钟）。

### 坍缩行

- 判据（`squeeze_repair.is_squeezed`）：每秒加权字数 > 25 且至少 5 字。挑规则的 13 个窗上命中 46 行：坍缩 36、幻觉 8、错字 2，没有好行。
- 修法：**阶梯**（`collapse_ladder.py`）：每个坍缩行收几个候选区间，按顺序第一个过关的拿下；阶梯跑不了时只用下面的拉长。
  - 提议者按顺序：`pad`：Whisper 照 ASR 那一步的路子（同一个模型类与设置、同样的音频读法、组解码，再过那一步解码之后的整条处理链，读它的 VAD 前缀）重解这一行的跨度两边各放宽 2 s 碰到的整段 VAD 区间；
    `S`：下面的拉长（越过下一行时保持叠着）；`iso`：只解这一行自己的跨度碰到的区间；`ctx`：宽窗前放 10 s、后放 5 s 碰到的区间。区间碰到的对齐段跨过边界时组往外扩。`iso`、`ctx` 只在 `pad` 没给出区间（没对上这一行，或原地不动）时才读，所以也只为这些行解码（先解全部 `pad`，同一次加载里再解它们）。
  - Whisper 的区间：窗里各行按连续块对到解码上（日语、普通话按读音，至少 2 个读音一块；英语按词，一个词就是一块：一个假名常是碰巧对上，一个词少有），
    分给这一行的词至少占它一半的读音（词），区间就是这些词的首尾（`S` 与「裁判听到起点准时」读的是拉长自己的判定，英语里仍按字母）；起点不早于前面各行的终点、终点不晚于下下一行的起点。
    起点越过下一行起点的，只在没有别的提议者给出停在下一行之前的区间时才收。
  - 每个区间过同一套关：不是仍然挤着、不是回声、裁判听到起点准时的行不往后挪、不压到已经写着同一句话的行上；再过「内容在」：裁判在这个区间整段上的文字对上这一行至少一半
    （区间太短、去掉首或尾 1/4 后不到 0.1 s 的算没听到）。Whisper 的区间另有「词钉」：首词或尾词每个读音（英语按字母）超过 0.58 s 的收到每个读音 0.12 s，再过一遍那套关。
    两个数是 Whisper 词每个读音时长的 99 分位与中位数：日语取自维护者的第二级，普通话沿用日语的；英语按同样的取法（中英证据里的英语词）是 0.56 s 与 0.08 s；
    别的语言没量，按读音的种类套：粤语、韩语一个字一个音节，用普通话的；其余按字母，用英语的。
  - 选中的区间挪动这一行：词按字数铺在区间里的 VAD 人声上，这一行单独过分句器，压到后面一行上的那一段叠着它显示（与拉长相同）。常数是评测验收的那一版，改哪个都要重新量。
  - 阶梯跑不了时退回拉长，原因记在 `recall.collapse`：aligned 没记模型名（老产物，不警告）；VAD 前缀（`-vad.json`）没有、读不了或与 aligned 的 VAD 时间线对不上，或 Whisper 的权重取不到（打一行 `Warning:`）。
    Whisper 解码本身出错时报错。
  - 与评测不同的一处：「内容在」在生产里是一批 Qwen 解码，评测按坍缩行分批，批的成员会改 Qwen 的文字。在维护者的 10 期日语上核对过：生产重解的 517 个 Whisper 窗与评测逐字节相同，
    225 个坍缩行的判决有 3 个不同（都是「内容在」的结果翻了），其中 2 行挪动不同；规则本身在评测的解码上重放，53 期与评测臂逐字节相同。
- **拉长**（阶梯的 `S`，也是阶梯不跑时的修法）：每个命中的行切几段音频给 Qwen 裁判听（`squeeze_windows`）：行前至多 3 s（前段）、照几何拉长后会到的地方（门）、
  只因下一行紧贴着才拉不长的行越过下一行能到的地方（叠拉门），以及一段宽窗。读的是 Qwen 的文字与这一行按读音逐块对上的比例（`verdict`），先成立的那条算：
  - 前段对上行前一半的至少一半：起点晚了，不拉（`late_start`）；
  - 门里对上至少三成：照几何拉长（`stretch`）；
  - 叠拉门对上三成、宽窗对上一半，而它会压住的那几行没有写着同一句话：越过下一行拉长（`overlap`）；
  - 前段与宽窗都不到三成：疑似幻觉，不动（`suspect`）；其余不动。
- 拉长的几何（`squeeze_repair.stretch_squeezed`）：起点不动，终点往后面的 VAD 语音里扩，够「加权字数 / 每秒 8 字」秒的人声就停，
  到下一行起点为止；从这一行最后一段人声量起，中间的静音超过 0.7 s 也停。词按字数铺在这段人声上。日文套话形状与「ご視聴」残片不碰
  （它们按时长被删，拉长会让那条腿失灵），±10 s 内另一行有一段连续相同的文字占这一行 80% 以上的也不碰（拉长复制碎片就是一行看得见的重复字幕）。
- 拉长的行单独交给分句器（`segmentation.split_segments`，用产物记录的 `length_scale`）：挤短时它太短、词间没有空隙，分句器切不动；拉长后常是两个人的话并在一行。
  只切这一行，不整份重跑：分句器是全局的，整份重跑会顺带改动别的行。
- 越过下一行拉长的行（阶梯里挪过去压住后面一行的那一段也一样）怎么显示，按 owner 两轮逐处复听定的规则（`recall_repair.shown`，2026-11-03）：
  被压住的那一行整段落在挪过去的行里面（比它最后一段早结束至少 0.05 s，按整行算、不按分句器切出的段算）就叠着显示——在中点切开会把挪过去那行的后半句时间整段丢掉；
  被压住的那一行越过挪过去那行的结尾就切开：被压住的行从 Whisper 的 `pad` 重解给它的起点开始（落在它自己的跨度里时；只用拉长的那条路没有重解），
  否则两行在重叠的中点相接，挪过去那行在切点结束（它本来就更早结束时不动）；切完任一行又会挤成一闪而过的（`is_squeezed`）不切、照样叠着（owner 2026-11-03；评测里新规则臂 165 段中有 8 段会这样）。
  阶梯的跨度从下一行中间开始、挪过去的行反倒落在那一行里面时也叠着：切开会丢掉那一行的头或尾，与上面「落在里面就叠着」同理（评测里 8 处这样的，那一行都比挪过去的行先结束）。复听之后对照参照查出的起因：Whisper 把被压住那行的起点放早了，占了挪过去那行说话的时间。
  叠着显示的那一段带 `overlap_lane`（值是挪过去那行原来的起止），分组键是它的叠拉道（`subtitles/line_groups.py` 的 `LANE` 加这个值），只有它能与别的行重叠；
  每条挪过去的行各一条叠拉道，两条相邻的坍缩行挪到同一段上、互相压着时，导出 SRT 也不把其中一条截回一闪而过；
  其余本机的行仍是一组，彼此照旧不重叠，没有叠拉的任务产物逐字节不变。之后照分组键的规则走（与云端任务两个人同时说话相同，见 [`joint-asr.md`](joint-asr.md)）：
  raw SRT 与 final SRT 里两条 cue 同时显示；纠错阶段有说话人标签时它压住的那一行在 `turn` 列标 `同时`；说话人裁判不拿这两行当声音样本，轨号来源仍按声学讲。
  以前在两行重叠的中点切开、各得一半（评测臂 `sq-split`），等的就是纠错阶段能表示重叠、导出 SRT 不收回重叠。
  分句器把挪过去的行切成几段时，每段还压在后面那一行上的都进叠拉道。只用拉长的那条路起点不动：坍缩行原来就压在前一行里（Whisper 的缺陷重叠）时，前一行不再在它的起点截短（阶梯的起点不早于前面各行的终点，没有这种情形）。叠拉道上的行之后被切开（声学换人拆行、说话人裁判切行）或被补空档挪走时，不再压着别的行的那一半仍带着它：不在别的行上截短，也让它所在的纠错窗多解释 `同时` / `换回`，产物没有别的变化。
- 修出来的每一行（拉长的、切出的）带 `squeeze_repair: {start, end}`，是原行的跨度。这些行沿用原行在删除阶梯上的判决：
  再对这份输出跑一次 stabilize，profile 2 跳过它们，因为它读的能量、置信度、Qwen 证据都是在挤短的跨度上量的。所以删除阶梯跑两遍结果不变。
- 没有裁判的解码时一行都不动，不退回纯几何拉长：照几何把命中的行全拉长，评测里每小时约修坏一行。

### 空档

- 在坍缩修好之后的行上找没被盖住的 VAD 语音（逐条 VAD 区间切，至少 1 s，端点取到毫秒）。所有空档一批给 Qwen 解；
  空档前后 3 s 内的行也在自己的跨度上再解一批（看那一行自己的跨度里少了什么）。
- Whisper 只解 Qwen 的文字有至少 3 个实质字、语言是本集语言的空档。两家的读音（日语假名、汉语无调拼音、其余字母；去掉首尾的语气词与附和）
  最长公共子序列至少占较短一方的一半，才算听到。英语的语气词仍在字母串上去（`look` 末尾的 `ok` 会被去掉），没按词去。
- 听到的空档若装着附近某一行缺的那一段（那一行的读音在它自己跨度的解码里整段缺失，或缺行首 / 行尾连续一段），就把那一行挪过去或拉过去，
  带 `gap_retime: {start, end}`（原跨度）；否则插一行：Qwen 的文字，时间就是那一块，没有词，带 `gap_fill: true` 与 `whisper`（Whisper 的文字），不过分句器。
  评测第二级插的 346 行时长中位 1.5 s、最长 10.8 s，字数中位 9、最多 75。

### 行内补漏

- 哪些行（`row_fill.candidates`）：坍缩修好之后、补空档之前的行里，不是坍缩行、没被坍缩修法拉长过的，再过一道筛子：
  一个逻辑回归分数，读行长（取对数）、最长的词、行里没被词盖住的 VAD 语音、首尾词的长度与 Whisper 置信度、置信度的最低值 / 均值 / 低于 0.5 的比例、
  行的置信度与 VAD 能量、行首前与行尾后 1 s 内没被任何行盖住的语音。系数与阈值是在维护者的第二级日语行上拟合一次定下的常数（`on` 的阈值 0.245 留下那里约 70% 的要解码音频），
  生产不依赖 scikit-learn。`auto` 用更严的阈值 0.5：分数低的行补得少（0.245–0.4 的行每解一分钟补 0.22 段，0.6 以上的 0.88 段），
  在维护者的留出集上它留下 `on` 约 76% 的净值（每小时 +3.37 对 +4.42），解码约是 `on` 的 53%。这是离线按逐期净值折算的（每个片段在同一期里一样值），没有重跑尺子：`auto` 补的片段是 `on` 的子集，不会多出 `on` 没有的错，准不准只关系到收益的比例（owner 2026-11-05 定不必重量）。
  按源决定开不开（先探一段再定）不比单一阈值划算：就算按每期的真实结果挑源，同样的解码也只留下约 81%。
- 筛子留下的行各在自己的跨度上给 Qwen 解一遍（一批）。两边都按连续块对齐：日语按假名、汉语按拼音，至少 2 个读音一块；英语按词，一个词就是一块（与[坍缩行](#坍缩行)的阶梯相同）。
  Qwen 的文字不是本集语言，或对不上这一行至少一半的读音（两家对这一行有分歧，是听错的问题、不是漏字）时整行不动；
  Qwen 多出、对齐留下的一段，切到整字、至少 3 个实质字（首尾的语气词不算；英语按整词去，`look` 里的 `ok` 不算语气词）、对面这一行没有别的字（长音、促音、小假名除外：那是两家写法不同），才算候选片段。
- 有候选片段的行再给 Whisper 解一遍：Whisper 多出的某一段与片段读音的最长公共子序列至少占片段一半，才算听到。
  行首的片段若与上一行末尾同样多的读音对上一半就丢掉（邻行渗进来的），行尾的对下一行开头，行中的对时间上重叠的行；
  上一行仍是坍缩行时（它的话多半落在后面，常在这一行里），不论片段在哪都再对它整行（不然说了两遍的话会写成三份）；
  这几道闸读补空档之后的行，补空档插的行也算邻行，免得贴着空档的同一段话被写成一行又被补进隔壁行。补空档挪过的行不补（跨度变了，解码不再是它的）。
- 补进去的位置：行的词拼得回行文字时，片段是一个单独的词，插在对上的左邻字所在的那个词之后（行首的片段在第一个词之前），带 `row_fill: true`，
  时间占它与下一个词之间的空隙（两词相接时时长为 0），原有词的时间不动；拼不回时只插进文字，紧跟在左邻字之后（英语里在左邻词连同它的标点之后）。英语的片段前后各留一个空格。行的跨度不变，补进的片段记在行的 `row_fill` 里，带 Whisper 的文字。
- 评测（维护者的，口径见[效果与限制](#效果与限制)）：留出集（日语电话、中文会议、日语节目约 14 h）每小时 +4.53 [+3.72, +5.38]，是不筛全解（+4.63 [+3.80, +5.52]）的 98%，
  实际解码 77% 的音频、留下 96.8% 的补字。这是在没有补空档的行上量的；生产里补空档默认开着，叠在它之上的效果还没在生产次序上量过
  （第二级上不筛的版本叠在补空档之后是 +4.89 [+2.63, +7.72]，那份解码在补空档之后的行上做）。这些都在日语与普通话上量，没有「上一行仍是坍缩行」那道闸；加上它在评测的解码上重放，283 行补过的少 6 行，逐行看都是上一行坍缩着、已写着同一句话。英语另读过一轮（下一条），别的语言没有读数。
- 英语（中英证据，自动检测语言的视频 12 份 4.9 h，按外部转写读）：补进 64 段，外部转写在行附近听到 79.7%（同一把尺在日语、普通话的留出集上是 84.1%），
  与上一行或下一行重复 6.2%（留出集 9.8%）；「上一行仍是坍缩行」那道闸拿掉了 8 段（没有它时 72 段、重复 12.5%）。都是在同一份证据上改过之后读的，算开发读数。
  已知：补在行首时原来的首词仍大写（"And You had…"），补在行中的片段若是 Qwen 起的新句，带着它的大写、丢了前面的句号；
  落在带连字符或标点相连的词中间的片段插在整词之后（与日语插在左邻字所在的词之后相同）。
- 代价（估计，顺带测时、未在生产代码上实测）：`on` 每小时音频约多 1.4 分钟（整条管线约 +35%），`auto` 按解码量折算约 0.74 分钟（约 +18%），所以默认关。
- 与评测不同的一处：评测解了全部行再筛，生产只解筛子留下的行，Qwen 一批的成员变了，约一成行的文字会有 bf16 平局级的变化。
  规则本身在评测的解码缓存上重放（补空档关着），与评测臂逐字节相同；补空档开着时的两处（邻行闸读补空档插的行、跳过它挪过的行）是生产加的。

### 模型与音频

- 读人声轨，窗紧贴着切，不补静音。Qwen 解三批：坍缩的全部窗（各种窗混在一起）、全部空档、空档附近的全部行；阶梯跑时多一批：各坍缩行每个不同的候选区间（「内容在」）；开了行内补漏再加一批：筛子留下的行。
  批的成员会改 Qwen 的文字，所以一个都不剔，只有越过音频末尾、切出来是空的不解，当作什么都没听到。
- Qwen 裁判：默认的 0.6B、默认批大小、不带 ASR 上下文、自动语言、不编译。编译与改批大小都会改文字，所以钉成评测时的样子。
- Whisper：aligned 记的那个模型（产出这些行的），faster-whisper 原版、温度 0、greedy、本集语言、不接前文、不开 VAD 过滤，只要文字。
  只在有空档或行需要它时加载（补空档与行内补漏共用这一次），在 Qwen 关掉之后，所以两个模型不同时驻留。
- 阶梯的 Whisper 是 ASR 那一步的那一个（aligned 记的模型、打补丁的 faster-whisper 子类、同样的精修与组解码），要的是时间；有坍缩行的窗时才加载，在 Qwen 加载之前解完并释放。
  与 ASR 那一步不同处：每个窗单独一组，没有召回补解、组批预取与语言投票；处理链会重复报的警告（幽灵段之类）不再打。
- 读音比对用 `pykakasi`、`pypinyin` 与 `opencc`（繁简归一），三个版本钉死：读音随版本会变，评测是在钉住的版本上做的。

### 产物

`metadata.asr_stabilize.recall`：开关的取值（`switches`）；本集语言（`language`）；每个坍缩行的判决（`squeezed`：只用拉长时是分支与各窗的覆盖比例；阶梯时是拿下它的提议者与区间，没有就是第一个提议者被哪道关挡下，另记各提议者被挡的关）与挪动了几行（`stretched`）；
修坍缩用的哪种（`collapse`：`repair` 为 `ladder` 时带重解的窗数，为 `stretch` 时带退回的原因 `fallback`）；每个空档的端点、两家的文字与语言、
算不算听到（`gaps`），插了几行、挪了几行（`inserted`、`moved`）；行内补漏的计数（`row_fill`：筛子的阈值 `gate`、留下几行、它们的音频秒数、Whisper 解了几行、被补空档挪走而跳过几行、补了几行，以及各道闸挡下的片段数）；各模型与它们跑在哪个设备上（`referee`、`whisper`、阶梯的 `ladder_whisper`）；跳过的那件与原因（`skipped`）；第二次过契约新出的修复记录（`segment_time_repairs`，
下标指补救之后的行，所以与第一次的分开放；不记重叠：既有的重叠第一次已经记过，补救造成的重叠都牵涉带 `squeeze_repair` 的行（叠拉道上的行，或拉长的行压住不止一行时））。`speech_gaps` 量的是补救之后的缺口。

## 繁简

stabilize 最后一步（补救之后、写出之前）把 `lang == "zh"` 的段写成简体：段文本与每个词各转一次，不设阈值，`metadata` 不记，
运行摘要里多一项「繁转简」（转了几段，为 0 时不显示）。没有 `lang` 的段（补空档、召回修补插进来的行）跟本集的语言走：转写时告诉 ASR 的语言，
没有就按段的 `lang` 以字数加权（`recall_repair.episode_language`）。粤语（`yue`）、日语不动；profile -1（原样复制）不经过，
一体转写用的就是它，那几家本来就出简体。owner 2026-11-05 定：统一转简体，不给繁体输出开关。

- **为什么要转**：Whisper 的 `zh` 不分繁简，每段用哪种字由模型定，`--language zh` 与自动检测输出相同。2026-11-05 在 6 份中文
  30 分钟片段上：大陆源 4 份有 2.0% / 7.8% / 9.2% / 11.5% 的行是繁体，成段出现（连续十几到三十多行，再切回简体），几乎都是整行繁体；
  台湾源 2 份 63.7% / 75.9%。同样的素材上 MAI2、35t、MOSS Pro 与本地 MOSS 一个繁体字都没有。
- **为什么不设阈值**：最终字幕后处理的 t2s 步骤按整份文件算，改动超过 15% 的字才整篇转；混杂的文件只有 0.4–3.6%，永远过不了。
  对已是简体的文字无条件转几乎不动：38 份人工简体字幕 45 万汉字只被改 6 个，且那 6 个本来就是繁体。
- **为什么按段的语言门控**：日语文本会被改约 20% 的汉字（見→见）。1811 份日语为主的产物里标成 zh 的段只有 6 段、都不含假名。
- **为什么放在最后**：行内补漏会把裁判听到的字写进行里，放在补救之后能一起转掉。补救里跨模型比对文字的地方本来就先繁简归一
  （`recall_sounds`），放前放后不改变它们的判断。
- **段与词**：opencc 按词组转，一个词被切在词组中间时，词拼起来与段文本可能差一个字（4577 段里 1 段）。
- **旧产物**：按存在性跳过，已写好的 `-stable.json` 续跑不补转；要转就删它及其下游。

## 时间轴格式契约（2026-09-06）

**每一份被重写的 stable，其 segment 都跨住自己的词、时长为正，
且（在拿得到音频时长时）终点不晚于音频末尾。**
`normalize_segment_timeline` 在 profile 判定之后、写出之前跑一次。

为什么在这里也跑一次——识别阶段已经在源头修过同样的东西，但**stable 可以从一份早于那次修复
的 aligned 重建**（或者干脆是手写的），而下游分不出差别：`subtitles/rendering.py` 与
`llm/chunking.py` 都会静默丢掉 `end <= start` 的条目，丢了不留任何痕迹。实测：全床 59 份
**产于修复之前**的 aligned 重跑 stabilize，词越界 **40 → 0**。

⚠ **既有重叠不在这里修。** 扩段时的上界卡在后一段起点、下界卡在**前一段已修好的终点**
（读修复前的值会让相邻两段同时占用同一段间隙——`[1,2]` 的词伸到 2.8、`[3,4]` 的词从 2.2 起，
两边各自看输入都合法），卡不住的词被拉回段内（与 `clamp_segment_overlaps` 上游用的是同一套
取舍）——所以这一步**不会新造重叠**：全床 120 份产物重叠数 11 → 11，另有 4000 组随机时间轴
（含倒置词与乱序段）零反例。但产物里本来
就有的重叠（全床 4 处，最大 12.6 s，典型是一段长幻觉吞掉了里面的真实台词）**原样保留**：
它归 `resolve_overlaps` 在渲染时管，那条规则是有意不删任何一条 cue 的，在这里"顺手消掉"
会把文本挪进邻段、再把空掉的段删掉，那是另一件事。

⚠ **只记录，不告警**（owner 2026-09-06）。修复与仍然存在的违规逐条写入
`metadata.asr_stabilize.segment_time_repairs`，`kind` 为 `contain`（段被扩到盖住自己的词）/
`zero-span`（零跨度，随后被延长 0.01 s）/ `overlap`（既有重叠，未修，只记）/
`overrun`（终点越过音频末尾，已钳回）。
连续越界尾段从后向前预留正时长，必要时连同前邻段终点一起收短并记录，
避免零跨度被下游丢弃；具体规则见 `vad-asr.md` 的出口契约。
计数同时进 `AsrStabilizeReport.segment_time_repairs`。依据是发生率——61 份产物 / 23648 段里
这类失配从未改变过观众看到的东西，逐次告警的注意力成本高于缺陷本身。

⚠ **越界那一维要看 aligned 有没有记时长（2026-09-07）。** 界读的是
`metadata.asr_align.audio_duration`；**早于该字段的产物拿不到它**——实测六份交付包，
一份只有 `segments`、另外五份有 `asr_align` 但都没有这个键。那种情况下这一维**不检查**，
并写 `metadata.asr_stabilize.audio_end_unchecked = true`：
「没越界」与「没人量过」在产物里必须长得不一样。要修那种产物得回到音频重算，这条路径没有音频。

### 最终缺口落盘（`speech_gaps`，2026-09-07）

写出之前再量一件事：**最终的 segment 集合（补救之后）把多少 VAD 语音留在了无人认领的状态**，
写进 `metadata.asr_stabilize.speech_gaps`——
`speech_sec` / `uncovered_sec` / `uncovered_ratio` / `pieces` / `longest_piece_sec` /
`spans`（**最长的 50 块、按时间排列**——按大小挑是因为那些才值得打开音频听，按时间排是因为
人是那么读的；⚠ 所以 `spans[0]` 是最长那几块里最早的一块，**不是最长的一块**，
最长的时长看 `longest_piece_sec`。上限存在是为了不让病态产物把自己的审计记录变成文件里最大的一块）。

⚠ **它和另外两个覆盖率量的不是一件事，三个都要有：**

| 量 | 在哪一刻 | 回答 |
| --- | --- | --- |
| `asr_align.audio_coverage` | VAD 之后 | 有多少源音被交给了模型 |
| `asr_align.asr_coverage` | 每个解码组，救援前后 | 交给模型的，有多少被认领了 |
| `asr_stabilize.speech_gaps` | **stabilize 之后** | 哪些 VAD 区间没有被最终 stable 段时间覆盖 |

前两个都在 stabilize 之前测，所以一个组可以覆盖率健康、而它的句子在后面被删掉——
第三个描述最终 stable 的时间覆盖，不能证明缺失的是真语音、文本是否正确，
也不反映后续 LLM discard、翻译或 SRT 后处理造成的变化。判断内容漏识仍需听审。

⚠ **只记录，不告警**（owner 2026-09-07，与上节同一条口径），也**不带阈值**：
理由与 `audio_coverage` 的 docstring 相同——这里没有任何一处是决定，
管线也没有旋钮让人对着它做点什么。

⚠ **需要 `vad_timeline.intervals` 当尺子**；payload 里没有（手写的、或更老的 schema）就
**什么都不写**，而不是写一个零——「没有缺口」与「没有尺子」是两个答案。

⚠ 判据是**逐条 VAD 区间**切的，所以两条区间之间的静音永远不算缺口。同一套切法也供
`--qwen-verify` 的 `collect_gaps` 用（`recognition/segments.uncovered_speech_pieces`），
两者只差保留什么：那边问「这块值不值得再听一遍」，这边问「观众是不是丢了这段」。

⚠ **profile -1 不经过这一步**：它按定义是字节复制（见上），所以它的输出与它的输入一样干净，
不多也不少。管线自己产出的 aligned 已在识别阶段满足同一条契约。

## Schema 与复用

- aligned 的 schema 与此前未稳定化的 stable schema 相同，包含 `segments` 和原
  `metadata.vad` / `metadata.asr_align`；aligned 侧 split 的产物见
  `docs/segmentation-split.md`：word 可带 `whisper_segment_start: true`（ASR 原生分段首词），
  段可带 `tags: ["mid_segment_start"]`（起点是 DP 在 ASR 段内部切出的）。
- 稳定化保留未知顶层字段、metadata 和未修改的 segment 字段；写的 metadata 只有 `metadata.asr_stabilize` 下的
  时间轴契约审计记录（`segment_time_repairs`，只在非空时写）、`audio_end_unchecked`、`speech_gaps` 与补救的记录（`recall`，见
  [补救：坍缩行与空档](#补救坍缩行与空档)）。补救改写或新增的行多五个字段：`squeeze_repair`、`gap_retime`、`gap_fill`、`whisper`、`row_fill`（行内补漏补进的片段与 Whisper 的文字；补进的词也带 `row_fill: true`）。
- pipeline 只按输出是否存在复用：stable 已存在时不回补 aligned；aligned 已存在且 stable
  缺失时只跑稳定化；显式 `--stage aligned` 必须生成或复用 aligned。
- profile 改变不会自动使现有 stable 失效。要重跑需删除 stable 及全部下游 artifact。
