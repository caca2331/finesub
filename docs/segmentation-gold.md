# 分割点金标准（segmentation gold set）：标注规范与打分口径

## 1. 为什么要有它

本仓库此前所有关于「断句好不好」的数字都是**机械判定**：条内埋了多长静音、几条紧邻、首词
在不在某张表里。两轮人工语义裁决给它量了体温（原始记录见 git 历史）：

| 机械判定 | 精确率 |
| --- | --- |
| 欠切 | 67%（误报多是 VAD 把连续语音标成静音的伪影） |
| 词中切 | 58%（nagisa 臂）/ 25%（whisper 臂） |
| 不可救过切 | 0/1 —— 全语料唯一一条是误报 |
| **自由刀（判为"该切"）** | **~8% 漏报，池子有 2310 条** |

最后一行是关键：**最大的错误类是指标根本看不见的那一类**。`やっぱ元の` \| `お人形さんって
感じの…` 切在领属 `の` 之后、gap 0.91 s，下游 merge 不会救，指标却记 0 分——尺子上没有那一
刻度，调参修不了。而且指标每改一次都同时改变「被测对象」和「测量工具」（词中切指标与分句器
的 `fragment_penalty` 共用同一张词表），自我验证没有出口。

**金标准的作用**：一把与被测系统完全无关的尺子——由人按语义标出「哪里必须切/绝不能切」，
任何分割器都能拿同一批标签打分；同时**反过来校准机械指标**（后者在 gold 上的精确率，
就是它作为廉价代理的可信度）。

## 2. 三个设计决定（改之前先读这节）

### 2.1 标在**时间轴**上，同时留下词序号；两种口径都能打分

不同系统的词流不同（whisper 是子词、Qwen 是 nagisa 词素、文本本身也可能不一样），标在
任何一方的词序号上，这批标签就只能给那一方打分。所以标签落在**时刻**上：
`t = (左词 end + 右词 start) / 2`。`validate` 会把底本词序号 `k` 回填到每一条，
于是 `score --by-index` 可以按序号精确匹配、完全不看时间。

> **两种口径量的不是同一件事，要按问题选。**
>
> | | 时间锚定（默认，扫 τ） | `--by-index` |
> | --- | --- | --- |
> | 量什么 | 分割决策 **+ 对齐精度 + 显示时刻** | 只量**分割决策** |
> | 容差 | τ = 0.15/0.30/0.50 | 无 |
> | 适用 | 任何有 cue 时间的产物，含成品 `.srt` | 需要能映回底本词流 |
> | 干净吗 | 有**底本优势**（见下） | 同文本的臂干净；换了 ASR 文本的臂只有 75–92% 字符能映上 |
>
> **结论：whisper 系一律用 `--by-index`；qwen 臂的绝对读数按不可判定处理**（它把时间混淆
> 换成了文本对齐混淆，跨文本比位置没有无偏解）。三臂实测见 `tools/qwen3_explore/FINDINGS.md` §0。

打分时用容差 τ 匹配：某个必切点 t 若落在某刀的 `[gap_start-τ, gap_end+τ]` 内（或与刀口中点
相距 ≤τ），算作切到了。**τ 不是常数，要扫**（默认 0.15 / 0.30 / 0.50）——结论若只在某个 τ
上成立，那结论是 τ 选出来的，不是数据给的。

> **时间口径的两个坑（都实测过，都只影响时间锚定，`--by-index` 免疫）**：
>
> ① **底本优势**：标签的 `t` 由底本词级时间戳算出，**提供底本的那一臂零误差命中**——
> 生产臂的「必切位最近刀 \|Δt\| 中位」是 0.002–0.003 s，Qwen 臂是 0.070–0.249 s，
> 与 τ=0.15 同量级。于是 Qwen 在 τ=0.15 只召回 54–60%、τ=1.0 却有 87–94%，
> **「没切」与「切了但时间戳偏」分不开**。用时间口径时必须连 `score` 打印的对齐偏移诊断
> 一起引用，跨臂读数以 τ=0.50 为准。
> ② **cue 重定时**：`snap_cues_to_speech` 把刀口从静音中点挪到边缘，**逐词完全相同的一套
> 分段**因此从 95.8% 掉到 75.0%。该改的是打分口径，不是关掉生产的 snap。

### 2.2 以**完整标注窗口**为单位，不做零散抽样

可以只标一部分素材，但被标的窗口要给出**完整判断**。全窗口有 400+ 个词间位置，逐个标不现实，
所以契约反过来写：

> **`never` 是默认。标注者的义务是声明全部 `must` 与 `ok`（以及无法裁决的 `unknown`），
> 其余位置按定义即禁切。**

这不是"能容忍的近似"，而是一个**良定义的契约**：若某个未声明的位置其实该是 `must` 或 `ok`，
那是**漏标**，不是指标缺陷——责任明确落在标注者身上，而不是变成一个谁也说不清的灰区。
它同时让任务变轻：读完窗口，标出"必须切"和"可以切"的地方即可，不必逐位过一遍。

候选位表（§2.3）的角色随之变成**清单**：它列出所有带边界信号的位置，走完它保证你没漏掉
一个有信号的地方。显式写 `never` 仍然允许且有用（有 `why`，是**证据**），但不再是必须的。

打分时人标 `never` 与推定 `never` **永远分列**：前者是证据，后者是推断。推定项占比高，
说明该回头补标或补候选规则——因为推断的可信度低于人标。

> **一个必须同时处理的后果**：`unknown` 得能标成**区间**。否则整段不可解的文本
> （yingtao 那种 `Iknow.救世。`）会默认成"处处禁切"，分割器在乱码里下刀全算违规。
> 落在 `unknown` 区间里的刀整条排除，不计入任何分子分母。

### 2.3 候选位规则必须**与被测系统无关**

候选位 = 窗口内满足下列任一条件的词间位置：

- 词间停顿 ≥ 0.10 s；
- 该处有 VAD 静音；
- **左词以句读标点结尾**（`。！？…、，` 等）；
- 参考字幕在此换条（吸附到最近的一个词间位，`±0.30 s` 内）。

刻意**不**包含「某个臂在这里切了」——否则金标准只能评判今天这几个臂，换个分割器就失效。
代价是候选位里会混进一些明显在词中间的位置（参考字幕是重新计时的，不落在词边界上）。
这些位置标成禁切很快，而且它们确实是真金标准。

#### 「没有停顿但语义可分」的位置——这条规则曾经完全漏掉它

第 3 条（标点）与下面的补标机制是后加的，补的是一个真漏洞：原规则只有声学信号 + 参考字幕，
于是 §3.1 举的 `…って言ってた` \| `でも今日はさ…`（两个话轮之间没喘气）**按规则根本进不了
候选表**——规范和实现自相矛盾。更糟的是，靠参考字幕兜底等于让 `must` 的召回上界等于那份
机器字幕的断句质量，而这正是本文件要避开的锚定。偏倚方向也最坏：漏的恰好是**快速连续语流
里的话轮切换**。

标点规则是部分补救，但**第 1 批证明它是承重的**：三个窗口里"只靠标点进来"（无停顿、无 VAD）
的位置共 14 个（9 / 5 / 0），其中 **6 个被判 `must`**——占全部 61 个 `must` 的 10%，
且它们**只能**从这条规则进来。标注者反馈"标点规则几乎只产生 ok/never"，与实测不符：
它确实只是入口信号（14 个里 8 个不是 `must`），但删掉它会直接丢掉 10% 的必切位。

不过底本自带标点的密度很低（窗内带句读的词：BV1nxje63ERi 22/428、`yui` 9/390、
BV1UBjq6fEgb 更少），所以这条规则的产出量取决于 ASR 加没加标点，**不能指望它兜住
无停顿话轮边界的大头**。**真正的兜底是：
候选位是下限不是上限，标注者可以补位。** 工作表的连续词流每行标了首词序号 `[k=N]`，
标注者数出目标位置左侧那个词的 k，用 `{"k": N, "label": "...", "why": "..."}` 写进 `items`，
`validate` 会解析出时刻并回显上下文供复核。

补位**不限标签**，而且**最该补的是 `never`**。候选位规则靠的是「有边界信号」（停顿 / VAD /
标点），而 `never` 位置按定义就是**没有边界信号**的地方——词内、紧密短语内。`ア|ラン`、
`死|ねば` 这类真实的词中切，停顿 0、无 VAD、无标点，**结构性地进不了候选表**。这是候选规则
唯一一处系统性偏倚，偏的又正是最该测的那一类，补位是修它的唯一低成本手段。

补位只会让指标更严：`must` 的分母是自然总体，多标只是更完整；`never` 报绝对数；
「未覆盖」只会下降。所以补位没有副作用，**拿不准该不该补时就补**。
注意补位是**机会性**的（标注者碰巧看到才补），所以 `never` 绝对数只在同一批 gold 上跨臂可比，
不能跨窗口或跨批次比——这一点与 §2.3 开头「不报百分比」的理由是同一个。

> 因此**禁切违反不报成百分比**：它的分母是候选位规则碰巧捞出来多少个禁切位，不是一个自然
> 总体，报成率会让所有系统都好看。报**绝对条数** + **每百条窗内 cue**，同一批窗口上跨臂
> 可比。必切召回则是真正的率（分母是「所有必须切的地方」这一自然总体）。

## 3. 标签词表

每个候选位给且只给一个标签。

**每个标签就是一对断言**——「在这里切算不算错」和「不在这里切算不算错」。先看这张表，
判据表是它的展开：

| 标签 | 切了算错吗 | 不切算错吗 | 一句话 |
| --- | --- | --- | --- |
| `must` 必切 | 否 | **是** | 这里非切不可 |
| `ok` 可切 | 否 | 否 | 两可 |
| `never` 禁切 | **是** | 否 | 这里绝不能切 |
| `unknown` 存疑 | 不知道 | 不知道 | 我给不出裁决 |

**`never` 是默认，不需要写**（§2.2）：声明全部 `must` / `ok` / `unknown`，其余即禁切。
写出来的 `never` 是证据，打分时与推定的分列。

前三个是一根轴上的三个值，`unknown` 是轴外的弃权。**曾经有过第五个 `should`（宜切：
不切不算错但切了更好），已删** —— 它从不进错误率、只算质量项，却是主观性最高的一档，
拖慢标注速度换来的东西我们暂时用不上。它原本的用途（替换掉用同一张词表判定、因而循环论证
的 `turn_missed`）留给以后单开一趟标注，不绑在这批里。现在犹豫"该不该切"一律落到 `ok`。

| 标签 | 判据 |
| --- | --- |
| `must` | ①换人 / 换话轮 / **换发话身份**（朗读弹幕或评论、系统事件插入、引用他人话语——念别人的话时，说话的是别人）；②两侧是内容独立的两段，任何一段被切断都会受损。**同一人、同一发话身份、只是换了话题不算**，那是 `ok`，见 §3.4(a) |
| `never` | 切断一个词；切断紧密短语——修饰语+被修饰语、领属 `の` 及其体言、复合谓语、助词与其所属成分 |
| `ok` | 上面两条都不成立，且你确信「切了不算错」——这不是兜底项，见 §3.3 |
| `unknown` | 给不出裁决。两种情形：①ASR 文本不可解、听不出、明显错乱；②文本读得懂但你无法判断切了算不算错。整段不可解时用**区间**形式 `{"span": [a, b]}`，区间内的刀整条排除 |

`must` / `never` / `unknown` **必须写 `why`**（一句话，说清是哪条判据）。这是后续复核和
争议裁决的唯一依据，也是发现判据本身有问题的唯一途径。

### 3.1 语义优先——这是全部规范里最重要的一条

**停顿长短不是判据。** 分割器已经在用停顿了；金标准的价值恰恰在于提供停顿之外的信息。

- 停顿很长但不能切：`やっぱ元の` ⟨0.9s⟩ `お人形さんって感じの` —— `元の` 修饰
  `お人形さん`，中间那 0.9 s 是说话人的犹豫。**标 `never`。**
  这正是机械指标漏掉的那一类，多标出几个这样的位置，这批 gold 就值回票价了。
- 完全没有停顿但必须切：`…って言ってた` `でも今日はさ…` —— 两个话轮之间说话人没喘气。
  **标 `must`。**
- 唱歌段落：停顿由节奏决定，与语义无关。歌词行末未必是语义边界，句中换气未必不是。
  按歌词的语义单位判断。

### 3.2 常见误判

| 情形 | 正确做法 |
| --- | --- |
| 被参考字幕的断句带跑 | 参考文本在工作表里已抹掉分条边界，只用来确认「说了什么」。**不要照抄它的断句** |
| 首词是助词就标 `never` | 助词合法起句的情况很多：`ないわ`（应答）、`ってことは`（连接词）、`ね、`（句首）、`てか`。要看它是不是真的属于左边 |
| 叹词/应答独立成条 | `あ` `うん` `かわいい` 独立成条通常是 `ok`；只有当它明确是下一句的引导语时才与右侧绑定。**这说的是整个附和序列相对于前后文，不是序列内部**，见 §3.4(b) |
| ASR 文本明显错但能猜出原话 | 按猜出的原话判断，`why` 里注明；完全猜不出才用 `unknown` |
| 同一个语义单位跨多个候选位 | 逐个位置标 `never`，不要只标一个。禁切是**逐位**的，不是区间 |
| 拿不准 | **分方向，见 §3.3**。不要一律标 `ok` |

### 3.3 拿不准时标什么：`ok` 是一个断言，不是弃权票

`ok` 断言了「**在这里切不算错**」。打分时它因此提供**覆盖**——分割器在这里下刀，会被记成
一把已被裁决过的、正确的刀。把弃权写成 `ok`，等于替一把你没看懂的刀背书，
「未覆盖」计数也会虚低，让 gold 显得比实际够用。

所以拿不准要分方向，由上面那张两断言表直接推出来：

| 你在犹豫 | 标什么 | 为什么 |
| --- | --- | --- |
| `must` 还是 `ok` | **`ok`** | 两个候选都同意「切了不算错」，覆盖成立。只是别声称必须切 |
| `never` 还是 `ok` | **`unknown`** | 两者在「切了算不算错」上正好相反，你没有立场给覆盖 |
| 文本读不懂 | **`unknown`** | 同上 |

第三行是这份规范里最容易做错、后果也最严重的一条：那正是
`やっぱ元の` \| `お人形さんって感じの`（第 1 节里机械指标漏掉的那类）所在的位置。
把它标成 `ok`，等于亲手把这批 gold 建立的初衷抹掉。

`must` / `never` 仍然是强断言，仍然宁可少标——但「少标」的去处是 `unknown` 或 `ok`
中正确的那一个，不是无脑选 `ok`。

### 3.4 三条补充判据（标注反馈提出，逐条裁定）

**(a) 同一话轮内的话题转换 → `ok`；但「换发话身份」不算话题转换，仍是 `must`。**
`話を戻しましょう` \| `こんなんあたり言ってたら` 这类「同一人连续说、前句已完整、另起新话题」，
按两断言表就是 `ok`，不需要新档位（`BV1UBjq6fEgb` 的 24 个 `ok` 里约一半是这类——主播口语里
这类位置本来就多）。

> **界线要划清**：判据是**发话身份 / 内容来源**，不是嘴的归属。本条初版只写「同一人连续
> 说话」，导致 `BV1kYLR6AEXv` 标出 **0 个 `must`**（标注者把「评论↔朗读弹幕」「会员提醒
> 插入」也降成了 `ok`）。
> 同一人、同一发话身份、只换话题 → `ok`；**朗读他人文字、系统事件插入、引用他人话语** →
> 属「换人/换话轮」，标 `must`——**主播念别人的话时，说话的是别人**。
> 后果不只是少标几个 `must`，见 §5「零 `must` 窗口」。

**不为它单开「字幕友好」一档**：那本质是行长约束，机械的、可由 SRT 行宽/显示时长策略事后调整；
把长度偏好混进来，gold 就会随断行策略而变，失去独立标尺的身份。

**(b) 复合附和/感叹序列 → 序列内部一律 `never`，序列与前后按话轮判。**
`うんうんうん`、`ねーうん`、`なんかあのー` 视作**一个语义单位**，内部任何位置都是 `never`
（`うん` \| `うんうん` 与切在词中同罪）。§3.2 那条「叹词独立成条通常 `ok`」说的是**整个序列**
相对于前后文，不是序列内部。gold **不区分**「词中切 vs 两个叹词之间」——那是分词器概念、
逐臂不同，不该进金标准；gold 只断言「这里不该切」，理由写 `why`。

> **已知缺口**：本条依赖「同一语调轮廓」，而**纯词流给不出语调**。`kaguya60` 上确认了两侧：
> 序列内部判 `never` 有效，但**不能扩成「相邻叹词一律 never」**——能各自独立成立的连续反应
> 仍是 `ok`，二者的区别在听觉里不在文本里。
> 暂行：只在**文本本身**支持「这是一个单位」时判 `never`（重复同词、明显连缀如 `なんかあのー`）；
> 两个叹词各自完整时判 `ok`；拿不准按 §3.3 走 `unknown`，**不要靠猜语调**。

**(c) 素材类型的适用性差异 —— 是素材属性，不是判据缺陷，但要影响批次设计。**
剧情台词判据最清晰（话轮交替即 `must`）；主播连续口语 `must` 最难界定；混合轮替判据清晰且
密度最高。这解释了各窗口 `must` 密度的差异，属预期内。含义：**批次要配主播口语窗口**——
`ok` 边界的案例库只能从这类素材里长出来，而它恰恰判例最少。

## 4. 数据格式

一个窗口一个文件，放在 `tools/segmentation_gold/labels/<clip>-<start>-<end>.json`：


## 5. 打分口径

| 指标 | 定义 | 性质 |
| --- | --- | --- |
| 必切召回 | 命中的 `must` / 全部 `must` | **错误率**，漏 = 欠切，下游不可救 |
| 禁切违反（人标） | 切在显式 `never` 上的条数 | **错误率**，有 `why` 支撑，是证据 |
| 禁切违反（推定） | 切在既非 `must`/`ok` 也非 `unknown` 的位置上 | **错误率**，由默认得出，是推断；占比高同时是「该补标」的元指标 |
| 存疑内 | 落在 `unknown` 区间/位置里的刀 | 整条排除，不计入任何分子分母 |
| 对齐偏移诊断 | 必切位到最近一刀的 \|Δt\| 中位（±1.0 s 内） | **不是错误率，是读数说明**：它与 τ 同量级时，必切召回测的是对齐精度而非分割决策（§2.1） |

### 零 `must` 窗口：不能并进汇总数

一个窗口若一个 `must` 都没有，它**只能惩罚下刀**：「一刀不切」在那里拿 0 违反、0 漏切，
是满分。把这种窗口并进一个汇总的禁切违反率，等于给欠切的系统无条件加分。

第 2 批实测到了这个坑：`BV1kYLR6AEXv`（0 `must` / 27 `ok` / 85+5 `never`）一个窗口就
主导了整个留出集的违反列，把一个逐窗口 3 好 2 平 1 差的结果汇总成了「两个轴都变差」。

**规则**：零 `must` 窗口单独报，不进汇总；跨臂比较只在有 `must` 的窗口上做。
这与 §6「已知缺陷区必须单独报」是同一条纪律——分母性质不同的窗口不能相加。
若某个窗口的零 `must` 是判据造成的（如 §3.4(a) 那次），那是要修判据，不是接受这个窗口。

### 校准机械指标

金标准的第二个用途：把 `acceptability.py` 的每个机械判定与 gold 对齐，算出它的精确率/召回率。
之后 FINDINGS 里引用机械指标时，可以直接标注「该指标在 gold 上精确率 X%」，而不是像现在
这样每次都要重新人工抽查。

## 6. 批次管理与选样偏倚

**窗口必须按规则选，不能挑。** 若按「机械指标出错的地方」选窗口，这批 gold 只会证明机械
指标有问题（已知），却无法给出无偏的系统对比。

现行规则：每个 clip 取**起点 = 25% 时长处、长度 120 s** 的连续窗口。分层维度是**素材类型**

可以要，但**必须单独报，不能与其它窗口合并计算**。

## 7. 标注者协议（每批都一样，prompt 里不再重复）

### 7.1 不许看的东西

标注者**不得查看任何分割器的输出**：`out/qwen-explore/*-QS.json` / `*-WS.json`、
任何 `*-stable.json`、任何成品 `.srt`，以及 `tools/qwen3_explore/FINDINGS.md`。
看到被测系统的答案，这批 gold 就废了。工作表里已备齐所需的一切。

参考文本只用来确认「说了什么」，**不要照抄它的断句**——它是重新计时过的机器产物。

### 7.2 流程

1. 先通读工作表末尾的「全窗口连续词流」，弄懂这一段在说什么（对不上就查参考文本）；
2. 走完候选位表这份**清单**，逐个给标签（`i` 和 `t` 照抄，不要自己算）；
3. 回到连续词流，**补声明**清单外遗漏的位置：数出目标位置左侧那个词的 `k`
   （行首 `[k=N]` 是该行首词序号），写 `{"k": N, "label": ..., "why": ...}`，不要自己填 `t`；
4. 整段不可解的地方用 `{"span": [起, 止], "label": "unknown", "why": ...}` 圈掉。

第 3 步**不是可选的，且必须显式作答**。候选位表只覆盖「有边界信号」的位置，
`must` 里最要紧的那一类——**两个话轮之间没喘气**（§3.1 第二例）——按规则根本进不来，
除非底本恰好在那里加了标点。第 1 批 268 个候选位补出 0 个位置，无法区分"确实没有"
和"没找"。所以总结里必须逐窗口写明：**通读连续词流后，是否存在候选表外的无停顿话轮边界；
若为 0，说明你是找过之后判定为 0 的。**

判据见 §3；拿不准怎么标见 §3.3；`never` 是默认、不用逐位写见 §2.2。

**交卷前的自检：这个窗口标出了几个 `must`？** 如果是 0，先别交——回到 §3 判据表
逐条对一遍，特别是「换发话身份」（朗读弹幕/评论、系统提醒、引用他人话语）那一支，
它在主播独白素材上最容易被整片降成 `ok`。零 `must` 的窗口在打分时会退化成
「只惩罚下刀」（§5），一刀不切就是满分，等于把这个窗口作废。
若逐条对完确实是 0，在总结里说明你对了哪几条、为什么都不成立。

### 7.3 交付

- 每窗口一个 `tools/segmentation_gold/labels/<clip>-<start>-<end>.json`（schema §4）；
- 跑 `python -m tools.segmentation_gold.gold validate`，必须全部 OK；
- **不要 commit**，交给发起人复核。

### 7.4 总结里必须报的五项

计数只是记账，第 3–5 项才是这批标注的主要产出——规范是活的，暴露它的缺口比标得漂亮重要。

1. 每窗口 `must` / `ok` / `never` / `unknown` 计数；**任何窗口的 `must` 为 0 都要按
   §7.2 末尾那条自检说明理由**；同样地，**把 `ok` 占比与既往批次对比**（历史值约 20%），
   若某个窗口 `ok` 塌缩到 0 也要说明理由——第 3 批在这里翻过车，见 §8.2；
2. **补声明了多少个位置、都是什么情形**（补得多说明候选位规则还得改）；
   报 0 也要按 §7.2 第 3 步写清「找过、结论是 0」；
3. `unknown` 里「文本不可解」与「文本可解但无法裁决」各占多少
   （后者比例高说明判据本身不够用）；
4. **判据的缺口**：哪些情形规范没覆盖、哪几条判得勉强、不同素材类型上适用性有无差别；
5. **做了什么质量复核，以及它是哪一种**。自己回头重看叫**自复核**，只能发现笔误和
   不一致，不能证明判据用得对；只有另一个标注者独立标同一批才叫**二标**，才产出一致率。
   报数字时必须写明是哪一种——第 2 批报的 96.6% 是自复核，不是一致率。

不要在总结里评价任何分割器的表现——你没看过它们的输出，也不该看。

## 8. 质量控制

- **单人标注是当前最大的弱点**：全部裁决都是单人、无独立二标。批 2 做过 29/273（10.6%）
  固定间隔自查（初次一致 96.6%），但**自复核不产出一致率**，独立二标仍然欠着。
- 标注者**不应看**任何被测系统的分割结果（§7.1）。
- 一批标完先 `validate`，再用它给**生产原样输出**打一次分。**若必切召回接近 100% 或禁切
  违反为 0，多半是标松了，不是生产完美**（第 1 批触发过，见文末）。

### 8.1 交付物可能是**编造的**：五步检查，每批必跑

`validate` 只检查 schema，**通过它完全不代表标注者读过文本**。批 3 曾委派给一个编码 agent，
它把任务当成「满足约束」：条数对上、每文件至少 1 个 `must`、`validate` 通过——但标签是填的。
五步在几分钟内就能定性（括号内是那次的实测值）：

1. **计数分布**——与既往批次比 `must` 占比与 `unknown` 数量（`must` 5.1% vs 批 1 的 22.8%，
   且 643 位 `unknown` 与补位**全为 0**；真人标注不会这么干净）。
2. **`why` 去重**——不同 `why` 的数量应与条数同量级（477 条 `never` 只用 8 种说法、262 条
   同一句；`must` 的 `why` 多是照抄工作表头部的 `regime` 字符串）。
3. **`must` 的位置序号规律性**（出现 `[5,25,45,65,85]` 等差 20、`[18,42,66,90]` 等差 24，
   两个不同 clip 的前三个序号完全相同；回查工作表还有切在 `チ|ェーモフモフ` 中间的）。
4. **`k` / `t` 与冻结工作表逐行对齐**——缺项、多项、对不上都是没读表（重标那批 643 位全对）。
5. **`why` 的引文能否在工作表上下文里找到**——取 `「」` 内字串与该行左右上文做最长公共子串
   （重标那批 606 条里 90.4% 达 ≥40%；低分项全是引文比那 10 字上下文更长，逐条看都对得上。
   编造的那批此项直接归零）。

**这不是「质量不够好」，是「没有做」，发现即整批作废**，不能靠追加指令补救。
经验：这类判断任务不要交给以「完成约束」为目标的编码 agent。

### 8.2 `ok` 塌缩：五步全过，却把中间档并进了 `never`

批 3 重标（通用 LLM）通过全部五步检查，但 `ok` 占比 20.3% → 5.8%、`never` 57.3% → 72.3%，
且**按任务顺序单调塌缩**（19 → 10 → 7 → 1 → 0 → 0 → 0 → 0）。根因是把 `never` 当成了
「非 `must` 的默认」——**§2.2 说的是「未声明的位置」按 never 处理，候选表上的位置仍要逐个
过 §3 的两断言**。（`must` 那一列的差异是素材差异不是标注差异：同标注者同 clip 的相邻窗口
给出 20%→18%、29%→24%，稳定。）

定向修复改了 27 处 `never→ok`（`must`/`i`/`k`/`t` 未动），`ok` 回到 10.0%——**仍低于历史**，
同 clip 对照缺口犹存（`BV1nxje63ERi` 26.5% vs 3.9%）。用法：**`must` 一侧可用；`never` 的
绝对数不要单独引用**。

> **但这类偏差对「比较」是中性的**：修复前后重跑全部结论，各臂违反数等量下降、**臂间差值
> 一个没变**。可被差分消掉的系统偏差，与不可消的噪声，危害完全不同。

防它的办法在 §7.4 第 1 项：报计数时把 `ok` 占比与既往批次对比，塌缩到 0 要说明理由。

### 8.3 第 1 批那次「标松了」告警的结论

生产臂必切召回 100% / 95.8% / 94.1% 且**不随 τ 变化**，排查出三个原因，都不是"生产完美"：
① **底本优势**（§2.1）；② **`must` 几乎全落在有停顿的候选位上**（声学信号进来的 `must`
11/11、13/13、16/17 全被切中），而生产本就在停顿处下刀，这类 `must` 没有区分度；
③ **0 补位**（§6）——真正能区分的「无停顿话轮边界」没被补进来。

**结论：那批 gold 能有力地测过切，几乎测不动欠切。** 补位与 `--by-index` 落地后已修正。
