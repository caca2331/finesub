# 让 AI agent 替你做的几件事

仓库中备有多份**任务说明**（位于 `agent-tasks/`），供执行工作的 AI agent 阅读。这些说明不绑定任何
特定工具：将仓库交给 Claude Code、Codex 或其他能读取文件、执行命令的 agent，告知需要完成的工作，
它便会自行在 `agent-tasks/` 中查找对应说明并执行。

无需记忆具体命令：直接用自然语言描述需求即可，各节下方的「你可以这么说」即为示例。

## 能让它做什么

### 审查一次运行的结果

> 「审一下这次 run」「这次跑得怎么样」「诊断一下 out/reference/xxx」「validation 为什么失败」

对**已完成的**产物进行只读检查，输出带证据的报告，覆盖：字幕是否存在成类问题、知识库提案是否合规、
harness 是否存在异常重试或重复提交。该流程**不修改任何内容**，仅指出问题所在及可能的原因。

⚠ 若你的目标是调整提示词并观察效果变化，请勿使用本任务——该工作有独立的方法论
（`docs/prompt-iterate.md`）。

### 把资料收进知识库

> 「把这份笔记加进知识库」「这个主播的资料整理一下」「帮我把这页收进去」

你提供一份材料——例如自行编写的主播习惯笔记、保存的网页、他人整理的术语表——agent 会从中提取
**对听写和翻译有用**的内容整理为词条修改，其余内容丢弃。可通过一句补充要求（如「重点收自称和观众
叫法」）指定收录偏好。

⚠ 流程分三步执行，默认停在最保守的一步：先仅展示准备向模型提出的问题，经你确认后才真正执行；
写入知识库同样需要确认，中间一步会把拟写内容列出供你审阅。

⚠ 每次只处理一个**已有**词条。若材料涉及新的主播或作品，请先创建条目，再收录资料。

⚠ **该流程不记录「误听」判断**。误听需要通过真实转写与人工精修对照才能确认，属于完整流程结束后的
工作；仅凭一份材料断言某个词会被误听，缺乏依据。

### 把出问题的那次打包好，方便你发给开发者

> 「这次结果不对，怎么发给开发者」「打个包我发过去」「帮我把出问题的那几个任务收集一下」
> 「我想帮你们改进」「我的字幕可以拿去用」

agent 会把相关任务的字幕、参数、LLM 问答记录与运行日志打包为**一个 zip**，保存到桌面并返回文件路径。
该功能有两种用途：报告问题时**包含人声轨**（音频通常是定位问题的关键）；仅贡献素材时**完全不含音频**，
且只收集经你精修的任务——未经人工校对的产物对改进没有价值。

⚠ agent **不会代为发送**：不上传、不创建 issue、不发送邮件，仅生成文件。是否发送、发送给谁，
由你决定。

⚠ 包内的具体内容以 zip 中的 `MANIFEST.txt` 为准：字幕全文、LLM 每次问答的完整记录
（含引用的知识库条目原文）、包含你用户名的绝对路径，以及报告问题时的人声轨。
包内**不含** API key 或 `.env`。

⚠ 已打包过的任务会被记录，后续不会重复收集；若精修字幕有所改进，可再次打包，该次计为新的贡献。

## 它是怎么找到这些的

`agent-tasks/` 下一个子目录一件事，每份说明开头写着「用户说什么话时该读它」。agent 读仓库根的
`CLAUDE.md`（或 `agent-tasks/README.md`）就能看到清单，再按你的话去匹配。

因此该方式**无需安装或配置**，也不依赖特定工具的「技能」功能。你也可以直接要求 agent「读一下
`agent-tasks/run-audit/SKILL.md`，然后按其执行」，效果相同。

如需新增任务：按 [`agent-tasks/README.md`](../../agent-tasks/README.md) 中的约定编写一份即可。

（`agent-tasks/` 下另有**维护者专用**的两份说明——本机桌面包构建与版本发布——不随仓库公开，
此处不再展开。）
