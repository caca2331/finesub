# 说话人分离（`--diarize`）

给每条字幕标上「是谁说的」。**跑到 LLM 阶段、`--llm-difficulty quality` 时默认开**，其余默认关，默认档位 `intermediate` 也关，见[怎么开](#怎么开)。
开了以后，标签写进中间产物，另可按需导出分轨字幕；`-raw.srt` 只有一处会变：日语素材上，两个人先后说的话被识别进同一行、
声学上又听得清在哪换人时，这一行会被[拆成两行](#拆开两个人的行)。`--no-diarize-split` 关掉这一处，`-raw.srt` 就与不开时逐字节相同。
`quality` 与 `intermediate` 档开了 LLM 说话人裁判时，LLM 纠错另改走[三个 pass](#三个-pass)。

## 怎么开

```powershell
finesub input.mp4 --diarize acoustics
```

`--diarize` 有四档：`off`、`acoustics`（声学标签与[逐行置信标](#逐行置信标)）、`judge-text` / `judge-audio`（再加
[LLM 说话人裁判](#llm-说话人裁判)，读字幕判、或边读边听）。下面说的「开了」指后三档。

- **默认**：不写 `--diarize` 时，跑到 LLM 阶段（`--stage translated-srt` 以上）、`--llm-difficulty quality` 的运行用 `judge-audio`（`--llm-media text` 时用 `judge-text`），其余运行是 `off`。默认只出 `-raw.srt` 的运行因此不下载模型、字幕不变。写 `--diarize off` 不跑说话人分离和裁判；但目录里留着以前写的 `-diar-rows.json`、`-speaker-judge.json` 时，LLM 阶段照样读它们（纠错照样标出换人）。要回到完全不带说话人的纠错，连这两份一起删掉。
- 一个任务用哪一档，和走不走三个 pass 一起记在 `.llm-artifacts/correction-mode.json`；续跑不写 `--diarize` 时照它走，写了就照写的（见[三个 pass](#三个-pass)的「一个任务只定一次」）。默认开之前 LLM 阶段就已开始的任务续跑时不开：不补跑裁判，已经纠好的窗口也不重做。

- 第一次用时会**自动下载模型**（约 450 MB，只下一次），之后直接复用。下载走和其他模型相同的镜像线路，
  下完按固定的 sha256 校验。
- 跑不起来（比如下载失败）时打一行 `Warning:`，字幕照常产出，只是没有说话人标签。

## 用的是什么模型，能不能商用

默认模型是 NVIDIA 的 **Nemotron-3-Diarization**（判断每一刻谁在说话），再用 **WeSpeaker 声纹**把各段按声音归到同一个人。
**全部可以商用**；声纹与 PLDA 两个组件的许可要求署名，署名就是下表。

| 组成部分 | 来源 | 许可 |
| --- | --- | --- |
| 说话人活动模型 Nemotron-3-Diarization | [nvidia/Nemotron-3-Diarization](https://huggingface.co/nvidia/Nemotron-3-Diarization)，直接从 NVIDIA 的仓库下载 | OpenMDW-1.1 |
| 声纹模型 WeSpeaker ResNet34 | [pyannote/wespeaker-voxceleb-resnet34-LM](https://huggingface.co/pyannote/wespeaker-voxceleb-resnet34-LM)（Wang 等，ICASSP 2023） | CC BY 4.0 |
| PLDA 参数 | [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) | CC BY 4.0 |
| 后两者的转换版 | [spurtcarl/finesub-speaker-embedding](https://huggingface.co/spurtcarl/finesub-speaker-embedding)（格式转换，未重新训练） | CC BY 4.0 |

## GPU 与 CPU

| | 1 小时音频大约要 | 说明 |
| --- | ---: | --- |
| GPU | 30 秒 | 显存约 1 GB，不随音频时长增长 |
| CPU | 12 分钟 | 约为音频时长的五分之一；跑到这一步时会打一行提示 |

用不用 GPU 跟随整条任务：`--device cpu`、`--gpu-tier cpu`，或者这台机器的显卡用不了时，说话人分离也在 CPU 上跑。

## 产出了什么

| 产物 | 内容 |
| --- | --- |
| `<名字>-diar.json` | 说话人时间线。⚠ **别当中间文件删**：它是留着复用的，重跑不保证得到同一个答案 |
| `<名字>-diar-rows.json` | 时间线对 `-stable.json` 每一行说了什么：`rows` 与 stable 的行一一对应，每项的 `speaker` 是这一行挂的轨，含[逐行置信标](#逐行置信标)；被[拆开](#拆开两个人的行)的行另有 `split`；顶层 `speaker` 是这次的模型与提示，`split.chosen` 是这个任务用不用拆过的版本。`-stable.json` 本身一个字都不改。⚠ **别当中间文件删**：删了会按当时的证据与开关重新写，已经纠错过的行可能对不上。手改坏了、读不了时，运行会提示、不覆盖它，修好或删掉即可 |
| `<名字>-diar-evidence.npz` | 聚类算出来的声学证据，可删：置信标与切点已经记在 `-diar-rows.json` 里，只有那份要重写时才再读它（这时没有它就没有置信标、也不拆）；要连 `-diar.json` 一起删才会重算 |
| `<名字>-speakers/` | 仅 `--speaker-tracks`：按说话人拆开的 ASR 原文，见[转成分轨](#转成分轨) |
| `<名字>-annotated.csv` 的 `spk` 列 | 仅跑了 LLM 阶段（`--stage translated-srt` 以上）：每行是哪条轨，读法见[读 `spk` 列](#读-spk-列) |
| `<名字>-speaker-judge.json` | 仅 `judge-text` / `judge-audio`：[LLM 说话人裁判](#llm-说话人裁判)的结果。⚠ **别删**：同样的输入再问一次，答案可能不同 |

每个文件的细节见[运行产物](outputs.md)。

## 读 `spk` 列

`-annotated.csv` 去掉开头 `#` 注释行之后只剩字幕行（`type` 都是 `sub`），第 N 行就是最终 SRT 的第 N 条；`spk` 列写这一行是哪条轨。一条字幕可能由几句识别原句并成（`position` 列列出是哪几句），这时它的轨由这几句的轨合起来；列与表头见[`-annotated.csv`](outputs.md#-annotatedcsv核对低置信度的行)。一格由这些记号拼成：

| 记号 | 例子 | 意思 |
| --- | --- | --- |
| `s` + 数字 | `s2` | 轨编号，只在这一次运行里有效。**编号不是人**：一个人可能被拆成两条轨，几个声音相近的人也可能被并进一条轨，长录音里一条轨还可能中途换人 |
| `+` | `s2+s3` | 这一行时间里几条轨都有声音，按占的时间从多到少排，**最前面的是主轨**：通常就是说这句话的人。一条轨要覆盖这一行至少五分之一的时间才列出（几句并成一行时按每一句算）；列出只说明它在响，不保证那个人在这一行里有字。几句并成一行时可能列出三条以上 |
| `?` | `s2?+s3` | 只跟在主轨后面：[逐行置信标](#逐行置信标)判为没把握，校对时先看这一行；和 `conf` 列（LLM 对译文的自评）无关 |
| `~` | `s1~+s0` | 只跟在主轨后面：两条轨占这一行几乎一样多，谁是主轨说不准，校对时先看。只出现在没算置信标的任务里（研究用的两个后端，或证据文件被删过） |
| `(sN)` | `s3?(s2)` | 跟在 `?` 后面：声学层的第二候选是 s2，它不一定在这一行里响。只是提示，这类行多数时候原来的轨号仍是对的。`?` 后面没有它很常见：没有像样的第二候选、几句并成一行而各句的候选不一致、没把握的那句的主轨不是这一行的主轨（第二候选是和那句自己的主轨比出来的）、或第二候选已经列在 `+` 后面时都不写 |
| `*` | `s2*` | 这一行原本没挂上任何轨，按声学线索补上了 s2，把握低。几句都是补的时写作 `s4*+s2*`，按时长排 |
| `<` | `s3<s2?+s3` | [LLM 说话人裁判](#llm-说话人裁判)挪过这一行：`<` 左边是套上裁判结论之后的格，读法和不带 `<` 的格一样——一句话的行上就是裁判定的那一条轨、不带记号，几句并成一行而只挪了其中几句时，左边可能是 `s3?+s2` 这样的整格；右边原样保留声学层当初的格，声学层没挂上、也没补上的行右边为空（`s3<`）。左边的 `?`：这一行没被挪的那几句里仍有没把握的；左边的 `~`：套上裁判结论之后，两条轨仍占这一行几乎一样多；两侧主轨也可能相同（被挪的不是主轨那几句）。左边的编号比 `-stable.json` 各段 `speaker` 里提到过的所有轨号都大时，是裁判新建的轨。没有 `<` 不等于裁判同意原轨：它也可能判断不了，或那一窗没判成，见[`-speaker-judge.json` 里多出来的](#llm-说话人裁判) |
| 名字 | `Aki+s2` | 有人在 `-diar-rows.json` 的标签里写了名字时，那一句显示名字代替轨号，不带 `?`、`~`、`(sN)`；名字里的保留字符（`+ ? ~ ( ) * < \|`）显示成全角（`＋`），空白与控制字符（含全角空格、换行）都显示成一个半角空格。裁判挪过带名字的行，两侧都显示名字（`Aki<Aki`），挪到哪条轨要看 `-speaker-judge.json` |
| 空 | | 这一行没挂上轨，也没补上（声学线索不够，或这次没算置信标）；没开 `--diarize` 时整列为空 |

**取主轨**：有 `<` 时只看左边那一格，没有时看整格；在这一格里取第一个成员（轨号或名字），去掉它后面的 `?`、`~`、`(…)`、`*`。`+` 后面的是同时在响的轨。
用程序读这一列时，直接拷 [`examples/spk_cell.py`](../../examples/spk_cell.py)：开头是正式语法，`parse` 把一格拆成主轨、裁判之后与之前两侧各自的轨、标记和第二候选，遇到语法外的写法就报错；测试保证它读得懂 finesub 写出的每一种格。
在 Excel 里查找或筛选 `?`、`*`、`~` 时要写成 `~?`、`~*`、`~~`：前两个是 Excel 的通配符，`~` 是它的转义符。

| 格 | 主轨 | 读法 |
| --- | --- | --- |
| `s2?+s3` | s2 | s2 为主、s3 也在响；声学层没把握，先核对 |
| `s3?(s2)` | s3 | 声学层没把握，第二候选是 s2 |
| `s1~+s0` | s1 | s1、s0 占这一行几乎一样多，主轨说不准 |
| `s3<s2?+s3` | s3 | 裁判挪到了 s3；声学层原来是「s2 为主、s3 也在响、没把握」 |
| `s3<s1+s2` | s3 | 裁判挪到了 s3；声学层原来是「s1 为主、s2 也在响」 |

### 推荐怎么用

按下面的顺序做。改轨号时改在自己的副本或一张「轨 → 人」对照表里：再跑一次裁判会重写 `-annotated.csv` 的 `spk` 列，分轨导出也不读你的改动。

1. **先认人。** `-diar.json` 的 `metadata.hints.samples` 给每条轨一段「单独说话、最像这条轨」的时间区间（秒），照着听十秒最快；
   某条轨没有样本时（哪些轨没有，见[一次运行留下什么](outputs.md#一次运行留下什么)的 `-diar.json` 一行），就挑以它为主轨的几行去听。开了裁判时，`-speaker-judge.json` 的 `names` 是裁判猜的名字（`不明` = 认不出），只作参考：它可能和裁判自己挪的轨对不上，例如把 s2 叫作主播，却把主播说的几行挪到了 s3。
2. **合并被拆开的人。** 只在少数几行里当主轨的小轨，可能是某个人换了语气被单独切出来的，也可能是嘉宾、角色配音或背景人声；
   听过它的样本或这几行，确认是同一个人再把编号换成那个人的轨。
3. **逐类核对**，先后是：带 `<` 的行（裁判与声学层意见不同；右边的 `?` 是声学层当初的把握，这类行都归这一类）；
   主轨带 `?` 或 `~` 的行；带 `*` 的行；空的行；最后是带 `+` 的行里像是两个人各说了半句的——
   一行只有一个主轨，这样的行标哪条都错一半，要手工拆成两行才能对；要[转成分轨](#转成分轨)的话，先分好轨，再到各人那份里拆。
4. **没有记号的行也会错。** 几个声音相近的人被并进同一条轨时，这些行在声学上照样显得有把握，任何记号都看不出。
   素材里有声音相近的人时，挑一段对话顺着内容读：同一条轨上出现一问一答，多半是并轨了，这一段要逐行听。

### 转成分轨

先看要拆的是哪份文字：

- **ASR 原文**（拿去打轴）：加 `--speaker-tracks srt`、`ass` 或 `both`。已经跑完的任务带上它原样再跑一次就会导出，别的不重算。
  产物在 `<名字>-speakers/`：`srt` 是每条轨一份（`s2` 的那份叫 `<名字>-speakers-speaker2.srt`），没挂上轨的行进 `<名字>-speakers-other.srt`；
  `ass` 是一份含全部行、每条轨一个样式的 `<名字>-speakers.ass`，同一时间的两条就是重叠；`both` 两样都要。
  正文与时间来自 `-stable.json`，**是识别原文，不是纠错、翻译后的字幕**，也不带记号。
  一行列了几条轨就进几份（重叠的行在两份里各出现一次：删重复比补遗漏便宜）；补上轨的行进补的那条；裁判挪过的行进裁判定的轨，裁判新建的轨各成一份。
  有人在 `-diar-rows.json` 的标签里写了名字时，那几行进以名字命名的一份（`<名字>-speakers-Aki.srt`），ASS 里的样式也叫这个名字；名字和 `spk` 格里显示的一样，另把文件名与 ASS 里放不下的 `\ / : " > ,` 也换成全角，最长 64 个字。两个名字只差大小写时，后来的那个加 `-2`、`-3`，不会互相覆盖；写成 `speaker2`、`other` 这种样子的名字也加，免得被当成轨或没挂上轨的那份。
  每次导出先清掉这个目录里的 `<名字>-speakers-*.srt` 与 `<名字>-speakers.ass`，自己的校对副本别用这个前缀放在这里。
- **成品字幕**（译文或纠错后的原文）：没有现成的选项，用 `-annotated.csv` 自己拆。时间与文字取最终 SRT 的第 N 条，
  按 CSV 第 N 行的[主轨](#读-spk-列)放进那一份；想让重叠的行两份都有，就把 `+` 两侧的编号都算上（有 `<` 时只看左边）。
  `spk` 为空的行单独放一份，别丢掉。合并过轨的，按你的对照表把轨号换成人再分。每份的序号重新从 1 编。

## 逐行置信标

默认后端（`nemotron3`）给每行的标签附一个把握，在 `spk` 列里写成 `?`、`(sN)`、`*`（读法见[读 `spk` 列](#读-spk-列)），告诉校对的人先看哪些行。

- **写在哪**：`-diar-rows.json` 每行 `speaker` 里的 `mark`（`{"tier": "low", "p_wrong": 0.13, "alternative": 5}` 或
  `{"tier": "filled", "track": 4, "by": "slot"}`；补上的行**没有** `track`，补的轨只在 `mark.track` 里）；`-annotated.csv` 的 `spk` 列。
  分轨 SRT / ASS 的正文不打标。文件顶层 `speaker.marks` 为 `null` 时这次没算标，此时没有 `mark` 不代表有把握。
- **只在日语上拟合过。** 在日语的多人直播上，不算附和，约四分之一的行被标为低，圈住约八成半的挂错，没有标的行约 1% 是错的。
  ⚠ **其他语言没有拟合过**：分数里分量最重的一项是一行的字数，换语言后标出的多少与准不准都没验证过，效果难以保证。
- **附和不打「低」标**：识别原文去掉标点后不超过 4 个字的行（「はい」「うん」），挂错了代价小，改个轨号即可。漏检的附和照样补。⚠ 这条规则也只按日语定过：中文 4 个字已经能是一整句话，这样的行拿不到「低」标。
- **补上的行**：有台词的漏检行里一半多补对；另有约三成漏检行在人工校对后的字幕里没有台词（多是音乐、音效被认成了字，也可能是没记下的口头禅），补了也会进某条人轨。
- **要证据文件**：写 `-diar-rows.json` 时没有 `-diar-evidence.npz`，这次就没有标（运行时会提示）。旧任务想要标：删掉 `-diar.json`
  重跑（证据文件与 `-diar-rows.json` 跟着重写）——重跑的分轨可能和原来不同；`-annotated.csv` 要重跑 LLM 阶段才会更新。
- 研究用的两个后端不出标。

## 拆开两个人的行

识别常把两个人先后说的话写进同一行。说话人分离在这一行里听得清「前半是一个人、后半是另一个人」时，就在换人处把它切成两行，
各挂各的轨。不用 LLM，跟着 `--diarize` 默认开。

- **切在哪**：在声学允许的范围里找最像句界的地方（标点、停顿），不切在一个词中间；切点前一个词若是后一句的开头（前面有停顿、后面紧接着），归给后一行。
  声学层听不清、或者两半像是同一条轨时不切。
- **效果**（日语，两份逐行真值共 11.3 小时）：两个人挤在一行的 121 行里，37 行拆得更好了，其中 34 行刚好切在换人处；
  其余大多没拆、维持原样。切错的代价分两种：把一个人的一句话切成两行，多半读得通，后面的纠错有时会并回去（多数留成两行）；
  切错到字放错了边、读起来不通的，约每小时 0.8 处。
- **用哪一版**：`-raw.srt` 默认是拆过的，`--no-diarize-split` 时是原来的；LLM 阶段（纠错、说话人裁判、`spk` 列、分轨导出）读的是同一版的行。
  两版都能从 `-stable.json` 加 `-diar-rows.json` 得到，`-raw.srt` 随时可以重新生成。
- **写在哪**：`-stable.json` 的行一个字都不改；`-diar-rows.json` 里被切那一行的条目多一个
  `"split": {"at": 3, "speakers": [前半的 speaker, 后半的 speaker]}`——`at` 是后半第一个词的序号，两个 speaker 的写法同行自己的 `speaker`。
  文件顶层 `split.chosen` 为 `true` 时这样的行读作两行（自己写脚本读这两个文件、要对上 `-annotated.csv` 的行号时，照这条规则展开；
  三个 pass 里带音频的裁判再切开、补上的行号带 `b`、`i`，见[三个 pass](#三个-pass)）。
- **只拆日语。** 其他语言没有读数，开着也不拆。
- 要声学证据文件（`-diar-evidence.npz`，默认后端才有）；决定拆行时没有它就不拆。
- ⚠ **拆在哪里、用哪一版，在 `-diar-rows.json` 写成时定下**：之后续跑一直用它，不看这次的开关，删了证据文件也不重拆——
  这样后加的说话人裁判、`spk` 列总对得上已经纠错过的行。只有它被删掉、时间线重算（删了 `-diar.json`，要一个新答案），
  或 `-stable.json` 重新识别过时，才重新写、重新决定。这时照「重跑一个阶段要删它的下游」，`-raw.srt` 和 LLM 产物也要删
  （含 `<名字>.llm-artifacts/` 目录，见[重跑某一阶段](outputs.md#重跑某一阶段需删除的产物)）。
  决定时已经有 `-raw.srt` 或纠错产物的任务，按没拆处理。只想换版本、不重算时间线：删掉 `-diar-rows.json`、`-raw.srt` 和 LLM 产物（同样含 `<名字>.llm-artifacts/`）再跑；
  留着任何一样产物，都会按「已有产物」记成不拆。证据文件已经删了的，这样重写出来就没有置信标、也不拆。

## 纠错不把两个人并成一行

LLM 纠错会把同一句话被切开的两行并成一行。开了 `--diarize` 时，相邻两行挂的主轨不同，纠错就不许把它们并起来：
模型拿到的输入里这一行标着「换人」（不给轨号），并在合并规则里被要求不许把它与上一行并起来。

- **按什么算换人**：两行的主轨（`spk` 列第一个轨号）不同就算，带 `?` 的也算；没挂上轨的行不算。跑了[LLM 说话人裁判](#llm-说话人裁判)时，用裁判改过之后的轨。
  被[拆开](#拆开两个人的行)的两半主轨本来就不同，自然不会被并回去。
- **代价**：声学层把同一个人误判成两条轨时，这两行也不会被并，成品里多一行短字幕。在日语直播与游戏实况（hina / manosaba）已有的纠错产物上离线估算，每这样多拆一处，能挡住约 6 处把两个人并成一行的合并；别的素材与语言没量过。
- **效果**：日语游戏直播 3 个窗口、Gemini 3.8 Flash 上，标了换人处的跨人合并从 42 处降到 4 处；没标处（声学层没听出换人）管不到。
- **模型仍然并了**：照收这次回答，运行提示一行（`correction-turn-merge`）、写明是哪几行，不为它退回重写，也不让纠错失败；这一窗若因别的格式错误反正要重写，会顺带要求把这几行拆开。
- 任务没有说话人标签时（没跑过说话人分离，或 `-diar-rows.json` 已删），纠错和以前一样。

## 三个 pass

开了 LLM 说话人裁判（`--diarize judge-text` / `judge-audio`；跑到 LLM 阶段的 `quality` 档默认就开着），且 `--llm-difficulty` 是 `quality` 或 `intermediate` 时，LLM 纠错改走三步
（`intermediate` 默认不开 `--diarize`，要自己写）：

1. **定形状**：先判哪几行是同一个人接着说、该合成一条字幕，哪几行可以合也可以不合（「可并」），哪几行是语气填充或识别的幻听、可以丢掉。
   由[LLM 说话人裁判](#llm-说话人裁判)顺带回答。
   边读边听的裁判（`judge-audio`）还能在换人处把一行切成两行、补上识别漏掉的半句或一句话，切出、补出的都进成品。
2. **纠错翻译**：读合好的行，只在标了「可并」的地方再合，其余照[纠错不把两个人并成一行](#纠错不把两个人并成一行)。
3. **校对**：成品出来之后另开一次，读观众实际看到的字幕（每行在屏幕上停几秒、每秒要读几个字），只改文字：读不完的、漏译、译重、前后不一致的；不改分行，也不动时间。

- **成品**：文件和以前一样；开着校对时另多四件 `-pass2-*`，是校对之前的版本，留作对照，可以删。
- **校对的开关**：`--llm-proofread`，默认 `auto` 看档位：`quality` 校对，`intermediate` 与 `efficiency` 不校对，不论走没走三步；`off` 不校对，`on` 哪一档都校对。
- **丢掉的行**：第 1 步丢掉的行不出现在成品里；丢了哪些、为什么，`.llm-artifacts/task-report.md` 的「Speaker Judge」一节逐行列出。
- **切出、补出的行**（`judge-audio`）：`-annotated.csv` 的行号里，切开的一行前半保留原号、后半记原号加 `b`（如 `12b`），补出的一句记它前一行的行号加 `i`（如 `12i`），其余行号不变；
  补了半句的行时间往旁边的静音里延一点，补出的一句放进前后两行之间的空当。空当不到半秒的那句先不进字幕（补出的行还不能与原有的行重叠），个数记在 task report 里。
  这些只记在 `<名字>-speaker-judge.json` 里，`-stable.json` 与 `-diar-rows.json` 都不改；`spk` 列与分轨导出也按切开、补上之后的行写。
- **出错时**：第 1 步某个窗口没答好，那一窗照一步纠错的做法纠；校对有窗口没答好，那几窗留第 2 步的版本、运行时提示一行。再跑一次只补没答好的部分。
- **一个任务只定一次**：开工时定下走不走三步、校不校对、用不用裁判，记在 `.llm-artifacts/correction-mode.json`，之后续跑照它走，开关后来改了也不变。例外是裁判：续跑时写了 `--diarize` 就照写的，比如给跑完的任务补跑裁判（[重跑某一阶段](outputs.md#重跑某一阶段需删除的产物)一表里的「只重做说话人裁判」）；纠错跑到一半时改了档、多出或少了说话人标签，已经纠好的窗口会全部重做。想换走法，删掉整个 `.llm-artifacts/` 和成品再跑，或者用 `--no-resume`（两种都要把窗口全部重做）；只删 `correction-mode.json` 不行，那样会被当作以前开始的任务、按一步纠错走。
- **花费**：日语直播的两份验收素材（约 38 分钟）上，三步合计（含校对）按价格加权（输出按未缓存输入的 6 倍、缓存输入按 0.1 倍算）约为裁判加一步纠错的 1.5 倍。
- **开了裁判就走三步**：`judge-text` / `judge-audio` 时裁判就是第 1 步。说话人分离没跑成、没有标签时任务仍记三步，裁判跳过（提示一行），每个窗口照一步纠错的做法纠，校对照档位。
- **`efficiency` 档开裁判会报错**：这一档一律一步纠错，没有第 1 步可走。`--diarize judge-text` / `judge-audio` 加 `--llm-difficulty efficiency`、又跑到 LLM 阶段时报错：单独跑一个源时开跑之前就报，不白跑说话人分离；`--manifest` 批处理里，一项先跑到 `raw-srt` 的那一半不查，说话人分离照跑，到 LLM 那一半才报。改用 `--diarize acoustics` 或 `off`，或换到 `quality` / `intermediate`。纠错格子配了别的、没有三步版本的 prompt 时同样报错。
  例外是续跑：额度用完后照原命令加 `--llm-difficulty efficiency` 续跑一个开着裁判的任务，照它记下的裁判接着走，不报错；只有这次写的裁判与记下的不同才报错。走法要等准备任务做完、窗口开跑之前才记下：额度在准备任务里就用完的任务还没有记录，原命令里写了 `--diarize judge-*` 会报错，去掉它再续跑（这一档不写 `--diarize` 就是 `off`）。
- **不开裁判就一步纠错**：`--diarize acoustics` / `off` 的任务一律一步纠错，有没有声学标签都一样；有标签时，一步纠错的输入照样标着「换人」（见[纠错不把两个人并成一行](#纠错不把两个人并成一行)），先认人、再合并在同一次调用里做。
  以前只有声学标签（`acoustics`）的任务也走三步（第 1 步单独问一次，只读字幕），这种第 1 步已经没有了：这样开始的任务续跑时，还没纠完的窗按一步纠错，提示一行。

## LLM 说话人裁判

跑到 LLM 阶段的 `quality` 档默认开（`judge-audio`，见[怎么开](#怎么开)）；别的运行用 `--diarize judge-text` 或 `judge-audio` 打开，要跑到 LLM 阶段，即 `--stage translated-srt` 以上，否则标签不经裁判，并提示一行。
在 LLM 纠错阶段里、纠错窗口之前，让模型按纠错窗口（一个纠错窗口就是一个裁判窗）读原始识别结果与声学层的轨号，
逐行判断：轨号对不对、该挪到哪条轨、是不是一个声学层没分出来的人（新建一条轨）、还是判断不了。它主要修声学层最常见的错：几个声音相近的人被并进同一条轨。

- **看到什么**：`-annotated.csv` 的 `spk` 列里，被挪过的行写成 `s7<s3`（读法见[读 `spk` 列](#读-spk-列)），没被挪的行照旧；
  [分轨导出](#转成分轨)也跟着裁判走。裁判挪的轨不进单轨 SRT（它在三个 pass 里顺带答的形状会，见[三个 pass](#三个-pass)）。
  裁判新建的轨接着声学层的轨号往下编（声学层最大是 s5，新建的就是 s6、s7…），只出现在 `<` 左边。
  窗口按顺序判时（`--llm-continuity serial`），上一个窗口新建或用到的轨会连同名字与例句交给下一个窗口，同一个人可以接着用同一条轨；窗口并行判时，每个窗口新建的轨各占一个号，同一个人在两个窗里会是两条轨。
  重判过某个窗以后，后面窗口新建轨的号可能整体挪动。
- **`-speaker-judge.json` 里多出来的**：按窗口记（对半拆开的窗口记在它的 `parts` 里），`status` 不是 `success` 的那一份保留原有的标签（声学的，云端任务是转写模型的）。
  - `results` 只列挪过的行与判断不了的行（`abstain`），带理由（`why`）；没列出的行就是裁判认可原轨。`row` 是源句编号，对应 CSV 的 `position` 列，不是 CSV 的行号。
    挪到已有的轨写 `track`；挪到裁判新建的轨写它起的标签 `label`，前面窗口新建、这一窗接着用的写 `carried`。
  - `gated` 列出 `judge-audio` 被挡下的改动（行、它要挪去的轨、理由），见下面的「短行」。
  - `names` 是裁判给轨猜的名字（`不明` = 认不出），已有的轨以 `s2` 为键，新建的轨以 `@` 加它的 `label` 为键。想知道 CSV 里的 `s6` 是谁：找一行 `s6<…`，按它的 `position` 在 `results` 里找到这一行，再查同一个窗口的 `names` 里 `@` 加它的 `label`；这一行写的是 `carried` 时，按 `carried.window` 找到新建这条轨的窗口，查那个窗口的 `names` 里 `@` 加 `carried.label`。裁判猜的名字不进 `spk` 列与分轨文件名。
- **人物名单**：开了裁判时，背景调查顺带列出素材里开口说话的人（只凭标题、简介和台词里直接看得出的，不另外检索）；这份名单、[知识库](knowledge.md)里的主播和调查提到的人物（最多 30 个）直接交给裁判，名单外认得出的人它也可以自己加。fast 模式没有背景调查，名单只来自知识库。
- **花多少**：每个窗口正常一次调用（调用出错或回复解析不了时重试，每个窗口最多 4 次，对半拆开后每半各自最多 4 次；回复只是个别行写坏或漏了时，重试只要那几行），走纠错同一个思考档；模型组按这一档的模态取（`judge-audio` 用能听音频的那组，与纠错是不是纯文本无关；那一组没有能用的模型时提示一行、改按纯文本判）。
  一小时的日语直播（纯文本、经 Codex、high 思考）分 3 个窗：GPT-6.1 Sol 当裁判约用 11 万未缓存输入、3.1 万输出（同一份素材的纠错约 35 万、4.7 万）；GPT-6 Luna 约 8 万、1.3 万。
  `judge-audio` 时它还听这一窗的录音与每条轨两段声音样本（从人声分离轨切）。
- **短行**（`judge-audio`）：不到 1.5 秒的行，裁判要把它挪到这一行 `spk` 格子里没有的已有轨时不收，这一行保留原有的标签。这么短的声音靠听认不出是谁，台词也很少说明是谁，这类挪动多半是错的（日语对谈素材上量过；英语会议的短行看起来是同一类）。挪到格子里有的轨、新建一条轨、切行、补字与插行照收（只有一种切行不收：被挡的那一行切开、后半段又写那条被挡的轨，那是同一次听错）；纯文本的裁判（`judge-text`）不挡。
- **一窗放不下时**：纠错窗口的大小已经按模型的输出上限定过，裁判的回答一般放得下。万一放不下（回答撞上输出上限，或这一窗的录音太长、输入超限），裁判把这一窗对半拆开重判，和纠错的拆窗一样只拆一次；半窗还放不下，那半窗的行保留原有的标签。
- **效果**：值得开的是**声学层把几个相近的声音并进一条轨**的素材（游戏剧情、多角色配音）：这类窗上挂对的行，GPT-6.1 Sol 多出了二三十个百分点，GPT-6 Luna 多出 4.6–8.2 个百分点（量过的只有 3 个窗，其中 2 个调 prompt 时用过）。
  普通的对谈节目上，裁判有改对的也有改错的，整体与不开持平（推测是因为这类素材的错多是行挂错了现有的轨）。在 11 个窗口上（纯文本，人物名单由准备任务列出）挂对的行从 82.5% 到 86.4%（GPT-6.1 Sol）；换成 GPT-6 Luna 是 83.3%。
  **带音频这条在生产代码上还没验证过**。
- **续跑**：结果按窗口写进 `-speaker-judge.json`，中断后续跑只判还没判完的窗（`--no-resume` 也一样：它管的是纠错的续跑，不管这份记录）。已经跑完的任务再开裁判，只补裁判、改写 `-annotated.csv` 的 `spk` 列，纠错不会重跑。
  删 `-diar.json` 重跑说话人分离以后轨号会重编，对不上的旧判决不再生效（那些行回到声学标签），带着 `judge-text` / `judge-audio` 再跑一次就按原来的窗口重判。
  想整份重判（例如换了模型，或从 `judge-text` 换成 `judge-audio`：已判的窗会照旧沿用），删掉 `-speaker-judge.json` 再跑。
- 需要说话人标签；说话人分离没跑成时裁判也不跑（提示一行）。只看日语素材试过。

## 相关选项

| 选项 | 默认 | 作用 |
| --- | --- | --- |
| `--diarize off\|acoustics\|judge-text\|judge-audio` | 跑到 LLM 阶段的 `quality` 档 `judge-audio`，其余 `off` | 开关与档位，见[怎么开](#怎么开) |
| `--diarize-backend nemotron3\|diarizen\|sortformer` | `nemotron3` | 用哪个模型。`diarizen` 与 `sortformer` 留作研究用，一般不要选（见下一节） |
| `--diarize-split` / `--no-diarize-split` | 开 | `-raw.srt` 与 LLM 阶段用不用[拆开两个人的行](#拆开两个人的行)之后的版本；两版都能从 `-stable.json` 加 `-diar-rows.json` 得到，`-raw.srt` 只写选中的那一版 |
| `--speaker-tracks off\|srt\|ass\|both` | `off` | 按说话人导出 ASR 原文，见[转成分轨](#转成分轨) |
| `--diarize-max-speakers N` | 不限 | ⚠ 建议别开，理由见[调参](tuning.md) |

## 云端转写的任务

转写交给一体转写模型（`--asr`，云端三家或本地 MOSS，见[一体转写](joint-asr.md)）的任务，说话人来自转写模型自己的识别结果，上面说的声学模型不跑：

- 不管 `--diarize` 是哪一档，每行都标上转写模型给的说话人（写进 `-diar-rows.json`，记的来源是 `joint:<后端>`），
  `turn` 列、三个 pass、`spk` 列与分轨导出读的都是它。所以在这样的任务上 `off` 与 `acoustics` 一样：纠错的输入照样标着「换人」（还有「同时」「换回」，见[一体转写](joint-asr.md)），不开裁判时一步纠错，开了裁判走三个 pass。
- `judge-text` / `judge-audio` 在云端标签上加 LLM 说话人裁判；裁判听的是原始混音（云端任务没有人声轨）。
- 没有[逐行置信标](#逐行置信标)，也不[拆开两个人的行](#拆开两个人的行)。
- `--diarize-backend` 不起作用，写了只打一行说明。目录里以前留下的声学 `-diar.json` 不读也不删，任务回到本机转写时照用。

## 研究用的两个后端

`diarizen`（DiariZen，⚠ **CC BY-NC 4.0，仅限非商业使用**，首次用时自动下载约 300 MB）与
`sortformer`（NVIDIA Sortformer，要先用 `tools/sortformer_export/` 自行导出，再把 `FINESUB_DIARIZATION_ARTIFACTS`
指到导出目录）只为对比研究保留，**一般情况下不要选**。

## 其他限制

- **远场会议录音**（一支麦克风放在桌上录多人开会）上，默认模型比 `diarizen` 漏检多：有人说话却没标上的时段更多。
- **换后端不会重算已有的时间线。** 已经有 `-diar.json` 的任务照常复用；想要另一个后端的结果，删掉它重跑。

逐项读数与限制见[说话人分离的实测结论](../diarization-findings.md)。
