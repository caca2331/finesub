# 说话人分离（`--diarize`）

判出每条字幕「是谁说的」。`--llm-difficulty quality` 档默认开，其余默认关，见[怎么开](#怎么开)。
⚠ 成品字幕 `<名字>.srt`（译文）里**不带**说话人，也没有按说话人拆开成品的选项：标签写进中间产物与 `-annotated.csv` 的 `spk` 列，
能直接按说话人分轨导出的只有识别原文（成品要分轨得自己按 CSV 拆，见[转成分轨](#转成分轨)）；`-raw.srt` 只有一处会变：日语素材上，两个人先后说的话被识别进同一行、
声学上又听得清在哪换人时，这一行会被[拆成两行](#拆开两个人的行)。`--no-diarize-split` 关掉这一处，`-raw.srt` 就与不开时逐字节相同。
开了 LLM 说话人裁判时，LLM 纠错另改成三个 pass（定形状、纠错翻译、校对三步）；`intermediate` 档例外，裁判并进一步纠错里，见[三个 pass](#三个-pass)。

## 怎么开

```powershell
finesub input.mp4 --diarize acoustics
```

`--diarize` 有四档：`off`、`acoustics`（声学标签与[逐行置信标](#逐行置信标)）、`judge-text` / `judge-audio`（再加
[LLM 说话人裁判](#llm-说话人裁判)，读字幕判、或边读边听）。下面说的「开了」指后三档。

- **默认**：不写 `--diarize` 时，跑到 LLM 阶段（`--stage translated-srt` 以上）、`--llm-difficulty quality` 的运行用 `judge-text`，其余运行是 `off`。带音频的裁判（`judge-audio`）不一定比纯文本好，有时更差，所以不是默认；手动开时提示一行。默认只出 `-raw.srt` 的运行因此不下载模型、字幕不变。写 `--diarize off` 不跑说话人分离和裁判。
- 续跑时用哪一档、拆不拆行、用哪份裁判结果，见下面[续跑时以什么为准](#续跑时以什么为准)。

- 第一次用时会**自动下载模型**（约 450 MB，只下一次），之后直接复用。下载走和其他模型相同的镜像线路，
  下完按固定的 sha256 校验。
- 跑不起来（比如下载失败）时打一行 `Warning:`，字幕照常产出，只是没有说话人标签：也就不按换人[拆行](#拆开两个人的行)，纠错时也不再[挡住跨人合并](#纠错不把两个人并成一行)。

## 续跑时以什么为准

说话人分离的结果当产物留着，续跑一般沿用任务已经定下的，不看这次的开关：

| 你做了什么 | 续跑时用什么 | 想换怎么做 |
| --- | --- | --- |
| 续跑时没写 `--diarize` | 任务记下的那一档（和走不走三个 pass、校不校对一起记在 `<名字>.llm-artifacts/correction-mode.json`）；默认开之前 LLM 阶段就已开始的任务不开 | 写上想要的档 |
| 续跑时写了另一档 `--diarize` | 照这次写的。已经判完的裁判窗照旧沿用，只判没判完的；纠错跑到一半时改档、多出或少了说话人标签，已经纠好的窗口全部重做 | 想整份重判（例如换了模型，或从 `judge-text` 换成 `judge-audio`），删 `-speaker-judge.json` 再跑 |
| 写 `--diarize off`，目录里留着以前的 `-diar-rows.json`、`-speaker-judge.json` | LLM 阶段照样读它们，纠错照样标出换人 | 连这两份一起删 |
| 改了 `--diarize-split`，或删了证据文件 | 写 `-diar-rows.json` 时定下的那一版（拆不拆、拆在哪）；那时已经有 `-raw.srt` 或纠错产物的任务按不拆记 | 删 `-diar-rows.json`、`-raw.srt` 和 LLM 产物（含 `<名字>.llm-artifacts/`）再跑；留着其中任何一样都会记成不拆，证据文件已删的重写出来也不拆、没有置信标 |
| 换了 `--diarize-backend` 或 `--diarize-max-speakers` | 已有的 `-diar.json`（换后端时提示一行） | 删 `-diar.json` 重跑，下游一起删，见[重跑某一阶段](outputs.md#重跑某一阶段需删除的产物)。重算会换一个答案、轨号重编，对不上的旧裁判判决不再生效，带着裁判档再跑会按原来的窗口重判 |
| 删了 `-diar-rows.json` | 按当时的证据与开关重写；已经纠错过的行可能对不上 | 连 `-raw.srt` 与 LLM 产物一起删 |
| 想换走不走三个 pass、校不校对 | 开工时记下的走法 | 删整个 `<名字>.llm-artifacts/` 和成品再跑，或加 `--no-resume`（两种都要把窗口全部重做）；只删 `correction-mode.json` 不行，那样会被当成以前开始的任务、按一步纠错走 |
| 一体转写的任务（`--asr` 不是 `local`） | 转写模型给的说话人；目录里以前留下的声学 `-diar.json` 不读也不删，任务回到本机转写时照用 | — |

## 用的是什么模型，能不能商用

默认模型是 NVIDIA 的 **Nemotron-3-Diarization**（判断每一刻谁在说话），再用 **WeSpeaker 声纹**把各段按声音归到同一个人。
**全部可以商用**；声纹与 PLDA（把声纹归成几个人的打分参数）两个组件的许可要求署名，署名就是下表。

| 组成部分 | 来源 | 许可 |
| --- | --- | --- |
| 说话人活动模型 Nemotron-3-Diarization | [nvidia/Nemotron-3-Diarization](https://huggingface.co/nvidia/Nemotron-3-Diarization)，直接从 NVIDIA 的仓库下载 | OpenMDW-1.1 |
| 声纹模型 WeSpeaker ResNet34 | [pyannote/wespeaker-voxceleb-resnet34-LM](https://huggingface.co/pyannote/wespeaker-voxceleb-resnet34-LM)（Wang 等，ICASSP 2023） | CC BY 4.0 |
| PLDA 参数 | [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) | CC BY 4.0 |
| 后两者的转换版 | [spurtcarl/finesub-speaker-embedding](https://huggingface.co/spurtcarl/finesub-speaker-embedding)（格式转换，未重新训练） | CC BY 4.0 |

## GPU 与 CPU

| | 1 小时音频大约要 | 说明 |
| --- | ---: | --- |
| GPU | 30 秒 | 显存约 1 GB，不随音频时长增长 |
| CPU | 12 分钟 | 约为音频时长的五分之一；跑到这一步时会打一行提示 |

用不用 GPU 跟随整条任务：`--device cpu`、`--gpu-tier cpu`，或者这台机器的显卡用不了时，说话人分离也在 CPU 上跑。

## 产出了什么

| 产物 | 内容 |
| --- | --- |
| `<名字>-diar.json` | 说话人时间线。⚠ **别当中间文件删**：它是留着复用的，重跑不保证得到同一个答案 |
| `<名字>-diar-rows.json` | 时间线对 `-stable.json` 每一行的结论：`rows` 与 stable 的行一一对应，每项的 `speaker` 是这一行挂的轨与[逐行置信标](#逐行置信标)，被[拆开](#拆开两个人的行)的行另有 `split`。`-stable.json` 本身一个字都不改。⚠ **别当中间文件删**：删了会按当时的证据与开关重新写，已经纠错过的行可能对不上。手改坏了、读不了时，运行会提示、不覆盖它，修好或删掉即可 |
| `<名字>-diar-evidence.npz` | 聚类算出来的声学证据，可删：置信标与切点已经记在 `-diar-rows.json` 里，只有那份要重写时才再读它（这时没有它就没有置信标、也不拆）；要连 `-diar.json` 一起删才会重算 |
| `<名字>-speakers/` | 仅 `--speaker-tracks`：按说话人拆开的 ASR 原文，见[转成分轨](#转成分轨) |
| `<名字>-annotated.csv` 的 `spk` 列 | 仅跑了 LLM 阶段（`--stage translated-srt` 以上）：每行是哪条轨，读法见[读 `spk` 列](#读-spk-列) |
| `<名字>-speaker-judge.json` | 仅 `judge-text` / `judge-audio`：[LLM 说话人裁判](#llm-说话人裁判)的结果。⚠ **别删**：同样的输入再问一次，答案可能不同 |

每个文件的细节见[运行产物](outputs.md)。

## 逐行置信标

默认后端（`nemotron3`）给每行的标签附一个把握，在 `spk` 列里写成 `?`、`(sN)`、`*`（读法见[读 `spk` 列](#读-spk-列)），告诉校对的人先看哪些行。

- **写在哪**：`-annotated.csv` 的 `spk` 列；`-diar-rows.json` 每行 `speaker` 里的 `mark`：`tier` 是把握（`low` 时另有 `p_wrong`，挂错的估计概率，
  与 `alternative`，第二候选的轨号；补上的行 `tier` 是 `filled`，补的轨写在 `mark.track`，这一行自己**没有** `track`）。
  分轨 SRT / ASS 的正文不打标。文件顶层 `speaker.marks` 为 `null` 时这次没算标，此时没有 `mark` 不代表有把握。
- **只在日语上拟合过。** 日语多人直播上标出约四分之一的行，圈住大部分挂错（口径见[实测结论](../diarization-findings.md)「4.6 逐行置信标」，开发者参考）。
  ⚠ **其他语言没有拟合过**：换语言后标出的多少与准不准都没验证过。
- **附和不打「低」标**：识别原文去掉标点后不超过 4 个字的行（「はい」「うん」），挂错了代价小，改个轨号即可。漏检的附和照样补。⚠ 这条规则也只按日语定过：中文 4 个字已经能是一整句话，这样的行拿不到「低」标。
- **补上的行**把握低：补对的略多于一半，有些补的是音乐、音效被认成的字。
- **要证据文件**：写 `-diar-rows.json` 时没有 `-diar-evidence.npz`，这次就没有标（运行时会提示）。旧任务想要标：删掉 `-diar.json`
  重跑（证据文件与 `-diar-rows.json` 跟着重写）——重跑的分轨可能和原来不同；`-annotated.csv` 要重跑 LLM 阶段才会更新。
- 研究用的两个后端不出标。

## 拆开两个人的行

识别常把两个人先后说的话写进同一行。说话人分离在这一行里听得清「前半是一个人、后半是另一个人」时，就在换人处把它切成两行，
各挂各的轨。不用 LLM，跟着 `--diarize` 默认开。

- **切在哪**：只在声学上听得清换人处时才切，找最像句界的地方（标点、停顿），不切在一个词中间；两半像是同一条轨时不切。
- **效果**：日语上拆对的多，两个人挤在一行的大多仍维持原样；切错到读不通的约每小时不到一处（口径见[实测结论](../diarization-findings.md)「6.5 声学换人拆行」，开发者参考）。
- **用哪一版**：`-raw.srt` 默认是拆过的，`--no-diarize-split` 时是原来的；LLM 阶段（纠错、说话人裁判、`spk` 列、分轨导出）读的是同一版的行。
  两版都能从 `-stable.json` 加 `-diar-rows.json` 得到，`-raw.srt` 随时可以重新生成。
- **写在哪**：`-stable.json` 的行一个字都不改；`-diar-rows.json` 里被切那一行多一个 `split`：`at` 是后半第一个词的序号，
  `speakers` 是前后两半各自的标签。文件顶层 `split.chosen` 为 `true` 时这样的行读作两行（自己写脚本对 `-annotated.csv` 的行号时照这条展开；
  带音频的裁判再切开、补上的行另见[三个 pass](#三个-pass)）。
- **只拆日语。** 其他语言没有读数，开着也不拆。
- 要声学证据文件（`-diar-evidence.npz`，默认后端才有）；决定拆行时没有它就不拆。
- ⚠ **拆在哪里、用哪一版，在 `-diar-rows.json` 写成时定下**，之后续跑一直用它，这样后加的说话人裁判、`spk` 列总对得上已经纠错过的行；想换见[续跑时以什么为准](#续跑时以什么为准)。

## 纠错不把两个人并成一行

LLM 纠错会把同一句话被切开的两行并成一行。开了 `--diarize` 时，相邻两行挂的主轨不同，纠错就不许把它们并起来：
FineSub 告诉模型这一行换了人（不给轨号），要求它别把这一行与上一行并起来。

- **按什么算换人**：两行的主轨（`spk` 列第一个轨号）不同就算，带 `?` 的也算；没挂上轨的行不算。跑了[LLM 说话人裁判](#llm-说话人裁判)时，用裁判改过之后的轨。
  被[拆开](#拆开两个人的行)的两半主轨本来就不同，自然不会被并回去。
- **代价与效果**：声学层把同一个人误判成两条轨时，这两行也不会被并，成品里多一行短字幕；换来的是标了换人的地方跨人合并大幅减少（日语上量过）。没标处（声学层没听出换人）管不到。
- **模型仍然并了**：照收这次回答，运行提示一行、写明是哪几行，不为它退回重写，也不让纠错失败。
- 任务没有说话人标签时（没跑过说话人分离，或 `-diar-rows.json` 已删），纠错和以前一样。

## 三个 pass

开了 LLM 说话人裁判（`--diarize judge-text` / `judge-audio`，哪些运行默认开见[怎么开](#怎么开)），且 `--llm-difficulty` 是 `quality` 或 `intermediate` 时，LLM 纠错改走三个 pass（`intermediate` 多半例外，见下面的[一步纠错兼认人](#一步纠错兼认人)），分三步：

1. **定形状**：先判哪几行是同一个人接着说、该合成一条字幕，哪几行可以合也可以不合（「可并」），哪几行是语气填充或识别的幻听、可以丢掉。
   由[LLM 说话人裁判](#llm-说话人裁判)顺带回答。
   边读边听的裁判（`judge-audio`）还能在换人处把一行切成两行、补上识别漏掉的半句或一句话，切出、补出的都进成品。
2. **纠错翻译**：读合好的行，只在标了「可并」的地方再合，其余照[纠错不把两个人并成一行](#纠错不把两个人并成一行)。
3. **校对**：成品出来之后另开一次，读观众实际看到的字幕（每行在屏幕上停几秒、每秒要读几个字），只改文字：读不完的、漏译、译重、前后不一致的；不改分行，也不动时间。

- **成品**：文件和以前一样；开着校对时另多四件 `-pass2-*`，是校对之前的版本，留作对照，可以删。
- **校对的开关**：`--llm-proofread`，默认 `auto` 看档位：`quality` 校对，`intermediate` 与 `efficiency` 不校对，不论走没走三个 pass；`off` 不校对，`on` 哪一档都校对。
- **丢掉的行**：第 1 步丢掉的行不出现在成品里；丢了哪些、为什么，`<名字>.llm-artifacts/task-report.md` 的「Speaker Judge」一节逐行列出。
- **切出、补出的行**（`judge-audio`）：`-annotated.csv` 的行号里，切开的一行前半保留原号、后半记原号加 `b`（如 `12b`），补出的一句记它前一行的行号加 `i`（如 `12i`），其余行号不变；
  补了半句的行时间往旁边的静音里延一点，补出的一句放进前后两行之间的空当。空当不到半秒的那句先不进字幕（补出的行还不能与原有的行重叠），个数记在 task report 里。
  这些只记在 `<名字>-speaker-judge.json` 里，`-stable.json` 与 `-diar-rows.json` 都不改；`spk` 列与分轨导出也按切开、补上之后的行写。
- **出错时**：第 1 步某个窗口没答好，那一窗照一步纠错的做法纠；校对有窗口没答好，那几窗留第 2 步的版本、运行时提示一行。再跑一次只补没答好的部分。
- **一个任务只定一次**：开工时定下走不走三个 pass、校不校对、用不用裁判，之后续跑照它走；例外与想换时怎么做见[续跑时以什么为准](#续跑时以什么为准)。
- **花费**：`quality` 档（裁判、三个 pass 与校对都开着）约是 `intermediate` 的 1.4–2.9 倍（`intermediate` 还没有窗内校对时量的，现在的差距会小一些），见[模型路由「difficulty 是定位」](model-routing.md#difficulty-是定位)。
- **开了裁判就走三个 pass**：`judge-text` / `judge-audio` 时裁判就是第 1 步（`intermediate` 多半例外，见下一节）。说话人分离没跑成、没有标签时任务仍记三个 pass，裁判跳过（提示一行），每个窗口照一步纠错的做法纠，校对照档位。
- **`efficiency` 档不能开裁判**（显式开会报错，额度用完换到这一档续跑的例外见[模型路由「difficulty 是定位」](model-routing.md#difficulty-是定位)）：改用 `--diarize acoustics` 或 `off`，或换到 `quality` / `intermediate`。纠错那一格配了没有三个 pass 版本的 prompt 时同样报错。
- **不开裁判就一步纠错**：`--diarize acoustics` / `off` 的任务一律一步纠错，有没有声学标签都一样；有标签时，一步纠错的输入照样标着「换人」（见[纠错不把两个人并成一行](#纠错不把两个人并成一行)），先认人、再合并在同一次调用里做。
- **窗内校对**：另一个开关 `--llm-proofread-inline`，只用于一步纠错，三个 pass 不做，见[调参](tuning.md#llm-这一侧)。

### 一步纠错兼认人

`--llm-difficulty intermediate` 加 `--diarize judge-text` 或 `judge-audio` 时不走三个 pass，也不另跑裁判：每个纠错窗口照一步纠错的做法纠错翻译（中文素材是纠错润色），同一次调用里顺带把每行判给哪条轨（声学层的轨，或它新认出的人）。

- **看到什么**：和单独的裁判一样，结果写进 `-speaker-judge.json`（写的是纠错窗口，不是单独的裁判），`spk` 列与分轨导出照它写；没有切开、补上的行（那是 `quality` 档 `judge-audio` 的）。
- **听不听音频**：跟 `--llm-media` 走，和纠错一样（默认 `audio` 就边听边判），提示一行：带音频认人不一定比纯文本好。要纠错带音频、认人用纯文本，改用 `--llm-difficulty quality --diarize judge-text`（三个 pass，裁判单独一步）。`judge-audio` 配 `--llm-media text` 时按纯文本认人，也提示一行。
- **不走这条的**：`quality` 档、[一体转写的任务](#一体转写的任务)，以及纠错那一格配了别的 prompt 的，照旧三个 pass。中文素材（[只纠错](chinese.md)）也走这条，同一次调用里纠错、润色兼认人。
- **效果与花费**：量过的样本（日语对谈与一段多角色的游戏剧情，Claude Opus 与 Gemini 3.8 Flash，纯文本输入；带音频的还没量）上，挂对的行比声学层多、与三个 pass 持平，连同默认开着的窗内校对，花费比 `quality`（含成品后的校对）低约两成（在 Claude Opus 上量的，窗内校对读到前缀缓存时）；跨人合并比不认人时多一些。较弱的模型（GPT-6 Luna）挂对的行没有比声学层多。中文素材上（会议与综艺各一段，Claude Sonnet 与 DeepSeek）挂对的行不如三个 pass，DeepSeek 在会议上比不开裁判还差，花费也与三个 pass 相当；所以中文素材走这条时提示一行，要更稳用 `quality`。
- **某个窗口的说话人没答对**：先让模型重答；重答用完还不对，这一窗的字幕照收，没答对的行保留原有的标签，提示一行。任务跑完后不再单独补判。
- **目录里已有一份 `-speaker-judge.json`**（以前用三个 pass 或单独的裁判跑过）：开跑前报错，不覆盖它。删掉它，或改用 `--llm-difficulty quality`（三个 pass 接着用它）。
- **想重判**：只删 `-speaker-judge.json` 不行，要连纠错一起重做（加 `--no-resume`）。

## LLM 说话人裁判

哪些运行默认开见[怎么开](#怎么开)；手动开用 `--diarize judge-text` 或 `judge-audio`，要跑到 LLM 阶段，即 `--stage translated-srt` 以上，否则标签不经裁判，并提示一行。
在 LLM 纠错阶段里、纠错窗口之前，让模型按纠错窗口（一个纠错窗口就是一个裁判窗）读原始识别结果与声学层的轨号，
逐行判断：轨号对不对、该挪到哪条轨、是不是一个声学层没分出来的人（新建一条轨）、还是判断不了。它主要修声学层最常见的错：几个声音相近的人被并进同一条轨。
走[一步纠错兼认人](#一步纠错兼认人)的 `intermediate` 任务没有单独的这一步，由纠错窗口顺带判，见[一步纠错兼认人](#一步纠错兼认人)；`spk` 列与 `-speaker-judge.json` 的 `results` 照下面读，`why` 是那一行字幕的 note，`names` 是窗口回答时先列的「哪条轨是谁」。

- **看到什么**：`-annotated.csv` 的 `spk` 列里，被挪过的行写成 `s7<s3`（读法见[读 `spk` 列](#读-spk-列)），没被挪的行照旧；
  [分轨导出](#转成分轨)也跟着裁判走。裁判挪的轨不进单轨 SRT（它在三个 pass 里顺带答的形状会，见[三个 pass](#三个-pass)）。
  裁判新建的轨接着声学层的轨号往下编（声学层最大是 s5，新建的就是 s6、s7…），只出现在 `<` 左边。
  窗口按顺序判时（`--llm-continuity serial`），上一个窗口新建或用到的轨会连同名字与例句交给下一个窗口，同一个人可以接着用同一条轨；窗口并行判时，每个窗口新建的轨各占一个号，同一个人在两个窗里会是两条轨。
  重判过某个窗以后，后面窗口新建轨的号可能整体挪动。
- **`-speaker-judge.json` 里多出来的**：按窗口记（对半拆开的窗口记在它的 `parts` 里），`status` 不是 `success` 的那一份保留原有的标签（声学的，云端任务是转写模型的）。
  - `results` 只列挪过的行与判断不了的行（`abstain`），带理由（`why`）；没列出的行就是裁判认可原轨。`row` 是源句编号，对应 CSV 的 `position` 列，不是 CSV 的行号。
    挪到已有的轨写 `track`；挪到裁判新建的轨写它起的标签 `label`，前面窗口新建、这一窗接着用的写 `carried`。
  - `gated` 列出 `judge-audio` 被挡下的改动（行、它要挪去的轨、理由），见下面的「短行」。
  - `names` 是裁判给轨猜的名字（`不明` = 认不出），已有的轨以 `s2` 为键，新建的轨以 `@` 加它的 `label` 为键。查 CSV 里新建的 `s6` 裁判叫它什么：按 `s6<…` 那一行的 `position` 在 `results` 里找到它的 `label`（写的是 `carried` 时，`carried` 里给出新建它的窗口与标签），再到那个窗口的 `names` 里查 `@` 加这个标签。裁判猜的名字不进 `spk` 列与分轨文件名。
- **花多少**：每个窗口正常一次调用，走纠错同一个思考档；模型组按这一档的模态取（`judge-audio` 用能听音频的那组；那一组没有能用的模型时提示一行、改按纯文本判）。
  一小时的日语直播（纯文本、GPT-6.1 Sol 经 Codex、high 思考）上，裁判的未缓存输入约为纠错的三分之一。
  `judge-audio` 时它还听这一窗的录音与每条轨两段声音样本（从人声分离轨切）。
- **短行**（`judge-audio`）：不到 1.5 秒的行，裁判要把它挪到这一行 `spk` 列里没有的已有轨时不收，这一行保留原有的标签：这么短的声音靠听认不出是谁。被挡下的记在 `-speaker-judge.json` 的 `gated` 里。纯文本的裁判（`judge-text`）不挡。
- **效果**：值得开的是**声学层把几个相近的声音并进一条轨**的素材（游戏剧情、多角色配音），这类素材上挂对的行明显变多（量过的样本还少）；
  普通的对谈节目上，裁判有改对的也有改错的，整体与不开持平（读数见[实测结论](../diarization-findings.md)，开发者参考）。
  上面的读数都来自纯文本的裁判。带音频的裁判（`judge-audio`）在量过的素材上不比纯文本好，有时更差，所以默认用纯文本。
- **续跑**：结果按窗口写进 `-speaker-judge.json`，中断后续跑只判还没判完的窗（`--no-resume` 也一样：它管的是纠错的续跑，不管这份记录）。已经跑完的任务再开裁判，只补裁判、改写 `-annotated.csv` 的 `spk` 列，纠错不会重跑。
  想重判见[续跑时以什么为准](#续跑时以什么为准)。
- 需要说话人标签；说话人分离没跑成时裁判也不跑（提示一行）。只看日语素材试过。

## 读 `spk` 列

`-annotated.csv` 去掉开头 `#` 注释行之后只剩字幕行（`type` 都是 `sub`），第 N 行就是最终 SRT 的第 N 条；`spk` 列写这一行是哪条轨。一条字幕可能由几句识别原句并成（`position` 列列出是哪几句），这时它的轨由这几句的轨合起来；列与表头见[`-annotated.csv`](outputs.md#-annotatedcsv核对低置信度的行)。一格由这些记号拼成：

| 记号 | 例子 | 意思 |
| --- | --- | --- |
| `s` + 数字 | `s2` | 轨编号，只在这一次运行里有效。**编号不是人**：一个人可能被拆成两条轨，几个声音相近的人也可能被并进一条轨，长录音里一条轨还可能中途换人 |
| `+` | `s2+s3` | 这一行时间里几条轨都有声音，按占的时间从多到少排，**最前面的是主轨**：通常就是说这句话的人。一条轨要覆盖这一行至少五分之一的时间才列出（几句并成一行时按每一句算）；列出只说明它在响，不保证那个人在这一行里有字。几句并成一行时可能列出三条以上 |
| `?` | `s2?+s3` | 只跟在主轨后面：[逐行置信标](#逐行置信标)判为没把握，校对时先看这一行；和 `conf` 列（LLM 对译文的自评）无关 |
| `~` | `s1~+s0` | 只跟在主轨后面：两条轨占这一行几乎一样多，谁是主轨说不准，校对时先看。只出现在没算置信标的任务里（研究用的两个后端，或证据文件被删过） |
| `(sN)` | `s3?(s2)` | 跟在 `?` 后面：声学层的第二候选是 s2，它不一定在这一行里响。只是提示，这类行多数时候原来的轨号仍是对的。`?` 后面没有它很常见：没有像样的第二候选、几句并成一行而各句的候选不一致、没把握的那句的主轨不是这一行的主轨（第二候选是和那句自己的主轨比出来的）、或第二候选已经列在 `+` 后面时都不写 |
| `*` | `s2*` | 这一行原本没挂上任何轨，按声学线索补上了 s2，把握低。几句都是补的时写作 `s4*+s2*`，按时长排 |
| `<` | `s3<s2?+s3` | [LLM 说话人裁判](#llm-说话人裁判)挪过这一行：`<` 左边是套上裁判结论之后的格，读法和不带 `<` 的格一样——一句话的行上就是裁判定的那一条轨、不带记号，几句并成一行而只挪了其中几句时，左边可能是 `s3?+s2` 这样的整格；右边原样保留声学层当初的格，声学层没挂上、也没补上的行右边为空（`s3<`）。左边的 `?`：这一行没被挪的那几句里仍有没把握的；左边的 `~`：套上裁判结论之后，两条轨仍占这一行几乎一样多；两侧主轨也可能相同（被挪的不是主轨那几句）。左边的编号比 `-stable.json` 各段 `speaker` 里提到过的所有轨号都大时，是裁判新建的轨。没有 `<` 不等于裁判同意原轨：它也可能判断不了，或那一窗没判成，见[`-speaker-judge.json` 里多出来的](#llm-说话人裁判) |
| 名字 | `Aki+s2` | 有人在 `-diar-rows.json` 的标签里写了名字时，那一句显示名字代替轨号，不带 `?`、`~`、`(sN)`；名字里和上面这些记号撞车的字符显示成全角（`+` 显示成 `＋`），空白显示成一个半角空格。裁判挪过带名字的行，两侧都显示名字（`Aki<Aki`），挪到哪条轨要看 `-speaker-judge.json` |
| 空 | | 这一行没挂上轨，也没补上（声学线索不够，或这次没算置信标）。本机 Whisper 转写（`--asr local`）的任务没开 `--diarize` 时整列为空；[一体转写的任务](#一体转写的任务)不开也有轨号 |

**取主轨**：有 `<` 时只看左边那一格，没有时看整格；在这一格里取第一个成员（轨号或名字），去掉它后面的 `?`、`~`、`(…)`、`*`。`+` 后面的是同时在响的轨。
用程序读这一列时，直接拷 [`examples/spk_cell.py`](https://github.com/caca2331/finesub/blob/main/examples/spk_cell.py)：（安装版没有这个文件，从 GitHub 上取）开头是正式语法，`parse` 把一格拆成主轨、裁判之后与之前两侧各自的轨、标记和第二候选，遇到语法外的写法就报错；测试保证它读得懂 finesub 写出的每一种格。
在 Excel 里查找或筛选 `?`、`*`、`~` 时要写成 `~?`、`~*`、`~~`：前两个是 Excel 的通配符，`~` 是它的转义符。

| 格 | 主轨 | 读法 |
| --- | --- | --- |
| `s2?+s3` | s2 | s2 为主、s3 也在响；声学层没把握，先核对 |
| `s3?(s2)` | s3 | 声学层没把握，第二候选是 s2 |
| `s1~+s0` | s1 | s1、s0 占这一行几乎一样多，主轨说不准 |
| `s3<s2?+s3` | s3 | 裁判挪到了 s3；声学层原来是「s2 为主、s3 也在响、没把握」 |
| `s3<s1+s2` | s3 | 裁判挪到了 s3；声学层原来是「s1 为主、s2 也在响」 |

### 推荐怎么用

按下面的顺序做。改轨号时改在自己的副本或一张「轨 → 人」对照表里：再跑一次裁判会重写 `-annotated.csv` 的 `spk` 列，分轨导出也不读你的改动。

1. **先认人。** `-diar.json` 的 `metadata.hints.samples` 给每条轨一段「单独说话、最像这条轨」的时间区间（秒），照着听十秒最快；
   某条轨没有样本时（哪些轨没有，见[一次运行留下什么](outputs.md#一次运行留下什么)的 `-diar.json` 一行），就挑以它为主轨的几行去听。开了裁判时，`-speaker-judge.json` 的 `names` 是裁判猜的名字（`不明` = 认不出），只作参考：它可能和裁判自己挪的轨对不上，例如把 s2 叫作主播，却把主播说的几行挪到了 s3。
   认出来之后想让 `spk` 列与分轨文件显示名字，目前没有给整条轨起名的命令，两条路：只要分轨文件名对，就导出之后自己把
   `<名字>-speakers-speaker4.srt` 这样的文件改名；要 `spk` 列也显示名字，就在 `-diar-rows.json` 里**逐行**写上（行多时用编辑器的批量替换或一个小脚本）。
   改法是在这一行 `speaker` 的 `labels` 里加一项，
   `role` 是 `streamer` / `guest` / `other` / `unknown` 之一，`conf` 是 `high` / `median` / `low` 之一，`src` 写 `human`：

   ```json
   {"speaker": {"labels": [{"role": "streamer", "conf": "high", "src": "human", "name": "Aki"}], "block": 0, "track": 4, "tracks": [4], "coverage": {"4": 1.0}}}
   ```

   改完带上 `--speaker-tracks` 原样再跑一次，分轨导出就按名字分份。已经写好的 `-annotated.csv` 不会因此改写：`spk` 列只在纠错写出 CSV、或裁判跑完时重写。
   所以要它显示名字，最省的是在 LLM 阶段之前改好（先跑到 `--stage raw-srt`，认人、写名字，再跑 `final-srt`）。已经纠错过的任务：
   开着裁判档的，删 `-speaker-judge.json` 带着裁判档再跑，只重判、只改写 `spk` 列，但裁判结果会换一份；
   否则按[重跑某一阶段](outputs.md#重跑某一阶段需删除的产物)的「只重做 LLM 纠错翻译」一行删掉产物重跑，会再花一次额度、译文也会变。改坏了、读不了时，运行会提示、不覆盖它。
2. **合并被拆开的人。** 只在少数几行里当主轨的小轨，可能是某个人换了语气被单独切出来的，也可能是嘉宾、角色配音或背景人声；
   听过它的样本或这几行，确认是同一个人再把编号换成那个人的轨。
3. **逐类核对**，先后是：带 `<` 的行（裁判与声学层意见不同；右边的 `?` 是声学层当初的把握，这类行都归这一类）；
   主轨带 `?` 或 `~` 的行；带 `*` 的行；空的行；最后是带 `+` 的行里像是两个人各说了半句的——
   一行只有一个主轨，这样的行标哪条都错一半，要手工拆成两行才能对；要[转成分轨](#转成分轨)的话，先分好轨，再到各人那份里拆。
4. **没有记号的行也会错。** 几个声音相近的人被并进同一条轨时，这些行在声学上照样显得有把握，任何记号都看不出。
   素材里有声音相近的人时，挑一段对话顺着内容读：同一条轨上出现一问一答，多半是并轨了，这一段要逐行听。

### `-diar.json` 里的几条提示

`-diar.json` 元数据的 `hints`（`-diar-rows.json` 顶层的 `speaker` 里有同一份）帮你判断有没有并轨、拆过头，**都只是提示，不改任何标签**：

| 字段 | 意思 | 别据此下的结论 |
| --- | --- | --- |
| `samples` | 每条轨一段「这个人单独说话、最像他自己」的时间区间（秒），照着听十秒就能认人 | 没有连续单独说满 2 秒的轨、裁判新建的轨没有样本 |
| `co_activity` | 每对轨同时发声的比例，按较短那条轨的说话时长算 | 同时响得多常常是两个人，但主播回放自己的录音、回声、同一个人被切成两条轨时也会一起响，**别据此认定是两个人** |
| `fourth_track_share` | 第四忙的那条轨占全部说话时间的比例；高说明四条轨都有人在用 | 素材里超过 4 个人时，多出来的人记在别人的编号下；这个数分不开「正好 4 人」与「5 人以上」 |
| `single_speaker_log_bayes` | 默认的 `nemotron3` 与 `diarizen` 才有：模型「不止一个人」的把握，大 = 更信不止一人，接近 0 = 「只有一个人」没被排除 | 它是总量、随音频变长而变大，**两个文件之间别直接比**，横向比看旁边按声纹段数除过的 `single_speaker_log_bayes_per_embedding`；它多大才算「不止一个人」还没定过界线，用来怀疑「单人素材被拆成几个人」只能当方向 |

### 转成分轨

先看要拆的是哪份文字：

- **ASR 原文**（拿去打轴）：加 `--speaker-tracks srt`、`ass` 或 `both`。已经跑完的任务带上它原样再跑一次就会导出，别的不重算。
  产物在 `<名字>-speakers/`：`srt` 是每条轨一份（`s2` 的那份叫 `<名字>-speakers-speaker2.srt`），没挂上轨的行进 `<名字>-speakers-other.srt`；
  `ass` 是一份含全部行、每条轨一个样式的 `<名字>-speakers.ass`，同一时间的两条就是重叠；`both` 两样都要。
  正文与时间来自 `-stable.json`，**是识别原文，不是纠错、翻译后的字幕**，也不带记号。
  一行列了几条轨就进几份（重叠的行在两份里各出现一次：删重复比补遗漏便宜）；补上轨的行进补的那条；裁判挪过的行进裁判定的轨，裁判新建的轨各成一份。
  有人在 `-diar-rows.json` 的标签里写了名字时，那几行进以名字命名的一份（`<名字>-speakers-Aki.srt`），ASS 里的样式也叫这个名字；文件名里放不下的字符换成全角，最长 64 个字；两个名字只差大小写、或写成 `speaker2`、`other` 这种样子时，后来的加 `-2`、`-3`，不会互相覆盖。
  每次导出先清掉这个目录里的 `<名字>-speakers-*.srt` 与 `<名字>-speakers.ass`，自己的校对副本别用这个前缀放在这里。
- **成品字幕**（译文或纠错后的原文）：没有现成的选项，用 `-annotated.csv` 自己拆。时间与文字取最终 SRT 的第 N 条，
  按 CSV 第 N 行的[主轨](#读-spk-列)放进那一份；想让重叠的行两份都有，就把 `+` 两侧的编号都算上（有 `<` 时只看左边）。
  `spk` 为空的行单独放一份，别丢掉。合并过轨的，按你的对照表把轨号换成人再分。每份的序号重新从 1 编。

逐项读数与限制见[说话人分离的实测结论](../diarization-findings.md)（开发者参考，用户可跳过）。
