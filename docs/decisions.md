## 评测与尺子

### 成品对精修的 SubER / AS-chrF 配对读数不采纳（2026-11-08）

- **背景**：LLM 层的 A/B 靠读者模型（派出去逐处判两臂断法不同之处的 LLM）。想加一把程序尺：拿字幕组的精修字幕当参考，用 `subtitle-edit-rate` 包算两臂成品的 SubER（带断行与时间的字幕编辑率）、AS-chrF（按时间对齐后的字符 F 值）与 TER-br（只数断行符的 TER）之差，配块 bootstrap 区间。
- **选项**：把它接进开发工具当 A/B 的主尺或副尺；或者不接。
- **定了什么**：不合并（owner 2026-11-08）；代码留在归档 tag `archive/suber-readout`。
- **理由**：在四组有读者模型判决的 A/B（hina 各集）上回测，它只在两种情形与读者一致：一臂严重失败（整窗错位、漏行，例如 3.5 Flash Lite 错位的两窗 SubER +21.5 / +67.9），以及读者也分不出两臂。两臂接近时它与读者不一致；两组「多并 / 少并」的 A/B 上方向相反：精修稿并得多，多并的一臂就显得更近，哪怕读者判它把两个人并进了一行。它的区间也不含同配置复跑的采样噪声：时间轴相同的两次 Luna 运行差 2.5 SubER。
  它抓得到的严重失败，纠错校验器在线上更早就拦下、送回这一窗重做：整窗错位检查（`serial_shift`）、每个源都要覆盖或显式丢弃、保留数下限；拼接之后的覆盖检查再对一遍，只告警不拦。五行以内的短局部错位两边都漏（[`llm_followups.md`](llm_followups.md)「整窗错位校验漏掉短的局部错位」）。逐组读数在维护者本地的实验报告里。
- **范围与重开条件**：结论针对以意译、并得多的精修字幕当参考。有了逐字、按句对齐的人工参考，或出现一类校验器漏掉、而参考指标抓得到的失败时再看。

### 不凭机器参考的 CER 给 ASR 底座定级（2026-09-07）

2026-09-07 复核一份反馈包时定的：那份包只做了结构检查，没有人工逐字稿，两份输出互比的距离当不了噪声底，VAD 与分离的影响又混在里面。
真要做底座选型，前置条件是人工逐字稿、同设备同精度、统一输入（都分离或都不分离）、配对差值的置信区间，并控制分句粒度（按时长把文本分进窗口时，每四段合并一次 CER 就涨约 0.17）。只在真有选型决策时立项。

### 不拿外部发表的 DER 数字当说话人分离的目标（2026-08）

外部数字所在素材的难度分布与我们的不同。DER 在这里只是几把尺子之一：它按时间计，看不到字幕行粒度与人工改正的代价，各尺子看什么见 [`diarization-findings.md`](diarization-findings.md)「11.1 四把尺子各看什么」。

### wt 对齐坍缩：检测与救援梯的决策记录（2026-07-19）

wt 是当时的对齐后端 whisper-timestamped（2026-08-02 移除，现在走 faster-whisper / CT2 那条路），坍缩是它把一串词挤进近零跨度。下表里的 regroup 重试已删；现行为以 [`asr-align.md`](asr-align.md)「当前对齐逻辑」为准。

（实验与接入过程草稿在维护者的本地归档；逐例产物在 `out/collapse-exp/`、
对照评估在 `out/collapse-eval*/`；现行为在 [`asr-align.md`](asr-align.md)「当前对齐逻辑」第 5 步，代码在 `src/finesub/speech/recognition/transcribe.py` +
`finesub/text.py`。）

| # | 决策 | 理由 |
| --- | --- | --- |
| C.1 | 坍缩签名用**词级形态**：≥3 个连续 ≤25ms 词（`COLLAPSE_STACK_*`，进 `detect_abnormal_asr_words`），不用段级 CPS（每秒字数）阈值 | wt efficient 路径把词挤进近零跨度时词时长帧量化在 ~20ms；确证真台词坍缩（8/8）全部含 ≥3 连零时长词，而真实快语速只有**孤立**零时长词——CPS≥12 单独用会误报快语速（实测 2 例全变体时间轴一致），变体间共识即非坍缩证据 |
| C.2 | 修复不新增机制，走现有的 abnormal 救援，现在就是 C.4 的异常 interval 隔离剥离。当初接上的梯是 regroup ×2（scale 2/3、1/2）→ 组级 beam → 隔离剥离，前两级之后都删了 | 当时的实验（V0 逐词复现坍缩）里 regroup∪beam 修复了全部确证真台词坍缩且互补（单变体只 5-6/8）；之后在一条 2h12m 直播素材上量出 regroup 重试解决率仅 23%、近半与失败的 greedy 逐字节相同，无条件整组 beam 在 greedy 正常的组上单向坍缩 10%，两级都删了，见 [`asr-align.md`「救援策略的取舍」](asr-align.md#救援策略的取舍)。refine 0.5 也有效但属全局参数不动（且更小 refine 可能损时间轴精度） |
| C.3 | regroup 第 3 轮（scale 2/5）比 C.2 那两级更早删掉；现在整个 regroup 重试都不在了 | 11 源评测解决率 1/32，成本是一整轮全子组重解码 |
| C.4 | 异常救援从「全组逐 interval 碎片化」改为**异常位置导向的剥离**（照 coverage rescue 末级建模）：异常前干净 run 一窗重解、异常 interval 单独成窗、剩余重解再检；上轮干净 subgroup 直接保留结果 | 健康邻居不再被碎片化/重复解码（短段 9/11 源下降、耗时反降）；各窗音频不相交防重复转写 |
| C.5 | 干净前窗重解码若返回异常，回退候选干净切片（裁越界溢出词）——但切片须先过 `_coverage_shortfall` **覆盖率闸门**，不足则降级为逐 interval 重解 | 两轮 held-out 各抓到一半：前窗单独解码可退化成复读循环（へ×134）吞真实台词→需要切片回退；但「interval-clean」也可能是 interval-**empty**（词按 whisper 段整段归属主导 interval，候选可把前窗语音全部吸附到异常 interval），空切片=丢内容→需要覆盖率闸门+逐 interval 兜底 |
| C.6 | 纯已知短语堆叠（`COMMON_HALLUCINATION_TEXT`，常量在 `src/finesub/text.py`，与 stabilization 共用）**早退**跳过整个救援梯；判定从严（混任何真实文本/其他异常不早退） | 假 ご視聴 下面没有可恢复语音，重试纯耗 GPU 且只把挤压转成拉伸；stabilize profile 1 按词跨度（≤5 词）整段清除，真说的短语是十几个词不受影响——形态判别不依赖能量，天然覆盖非低能量区 |
| C.7 | 幻觉/坍缩不用 confidence 区分 | 实测方向与直觉相反：真台词坍缩 conf 中位 0.85（最高 1.0），ご視聴 幻觉 0.77（0.46-0.90），重叠严重；仅 <0.5 / >0.95 两端有弱判别力。段能量才是强区分器（幻觉中位 −43dB vs 真台词 +9.7dB，profile 2 已在用） |
| C.8 | 顽固幻觉（音乐/静音区 ご視聴、笑声）不指望重试消除，维持 stabilize 链（短语清理+能量 tag+drop）兜底 | 实测重试只消一半；stable 级残留=0（基线与新版同），说明下游链已完备。真正缺口是**笑声拉伸长段**（くっふっふ×35s 类，能量不低、字数>2 全规则穿透）→ 挪词 pass / 笑声模式 tag 的输入（呼应 M.9/M.10 线） |
| C.9 | 阈值沿用单语料标定标注（同 M.7）；8 BV held-out 零调参验证通过（词级 stack 37→10） | held-out 只验证不调参；C.5 两次修正均由 held-out 对照跑抓出（collapse-eval2/3），最终生产产物 stable 级 ご視聴 残留 0、词级 stack 0 |

### 不向 Whisper 主解码器注入术语（2026-08-31）

`initial_prompt` / `hotwords` 那个 prompt 面装不下有意义的术语量，而且会改变解码行为（owner 判定；前文怎样把一个窗口带崩见 [`asr-align.md`](asr-align.md)「根因：前文污染下的窗内崩塌，不是语言检测漂移」）。术语只经 `--asr-context` 进第二模型 Qwen 裁判（[`vad-asr.md`](vad-asr.md) 选项表）。

### 不靠改 Whisper 权重修幻觉、复读、提前收尾与时间戳（2026-11-07）

2026-11-07 的探索，owner 决定不进生产：

- 停止闸门：在 turbo 解码器最后一层 FFN 后加一个神经元，判出「块里已经没话」就写 EOT。
  开着生产工程时质量看不出变化（它删掉的凭空行稳定化本来也会删），只省算力：日语上生成调用约少 7–9%，整条管线约 3.5%（估计）；
  中英文只省约 4%，还净丢一点真话。不值得为它多一份模型、换底模时重拟合。
- 复读闸门开着工程时什么也没省；在复读中途写 EOT 会让 faster-whisper 丢掉后面的话。
- 改对齐头或词时间后处理的温度，对时间戳没有无偏的收益；坍缩行不随试过的后处理变少。
- 长段无输出在生产里很少；提前收尾的「保持」闸门分不开真假，无效。

重开条件：闸门省下的大半是少做的异常隔离重解，所以先试纯代码规则能否拿到同样的省量；它拿不到、而权重改动的省量又值得多维护一份模型、换底模时重拟合，再提给 owner。探索代码在 `explore/`。

### 不让 Qwen3-ASR-1.7B 接管产出文字的调用（2026-11-08）

2026-11-05 的外部调研把它排在第一：stable 补救里产出文字的那几次调用（补空档插入的行、行内补漏的片段）从第二模型 Qwen3-ASR-0.6B 换成 1.7B，理由是外部日语 CER 上 1.7B 明显更好。owner 早先在本项目的素材上量过，确认不做（2026-11-08）；那次读数不在仓库里。第二模型仍是 0.6B（[`manual/models.md`](manual/models.md) 模型表）。

重开条件：owner 另有新读数，或 0.6B 产出的文字在实际运行里成了补救质量的主要瓶颈。

### 不把 Silero 提升为基础检测器（2026-08）

Silero 只作能量 VAD 之后的辅助（energy AND silero 的后置组合，`--vad-silero-assist`，见 [`vad-asr.md`](vad-asr.md) 选项表）。不提升，因为支持这一步的外部横向证据只有一个 60 s 片段。辅助切掉安静真话的那条还开着，在 [`speech-followups.md`](speech-followups.md)「散在别处的未做项」。

### 分离器分块权重不改三角权重（2026-08，撤回）

撤回的是「改成三角权重」这条提议，现行的权重不变。`separator/demix.py` 本来就是 Hamming 窗加 counter 归一的重叠相加，模块说明写明两样都照原样复现：简化任何一个都会移动音频而没有可测收益（600 s 的重叠相加与除法一共 0.24 s）。分离器其余被否的优化（FP8、手写 GEMM、真 batch、换 checkpoint、TensorRT、16 kHz 分离）在 [`separator-optimization.md`](separator-optimization.md) 的 E12、E14、E16。

### 不往 CT2 加 CUDA graph capture（2026-08）

CT2（CTranslate2，faster-whisper 的推理库）的 KV cache 每步增长，要先做 shape-stable 重写（上千行 C++）；而它要解决的那个瓶颈，组批（`--asr-decode-batch`）已经在解决。

## 说话人分离

### vbx 聚类的声纹不换模型、也不改喂法（2026-11-08）

- **背景**：默认的 Nemotron-3 + vbx（[`diarization-findings.md`](diarization-findings.md)「2.6 默认：Nemotron-3 + vbx」）给每个 16 s 窗里的每个 Nemotron 槽（Nemotron-3 每个窗输出的说话人通道，最多 8 个）算一个 WeSpeaker ResNet34 声纹：整窗音频进网络，本槽独响的帧只作池化权重。串轨（同一场景的不同人被并进一轨）是它最贵的错。
- **选项**：换更新的声纹（ResNet293-LM，或 ReDimNet2-B6 的 VoxCeleb2 版，两者都可商用）；或者保留 ResNet34 与现有 PLDA，只把喂法改成把本槽独响的音频拼起来进网络。
- **定了什么**：都不采纳，生产不变（2026-11-08，owner 授权「有希望提升生产就继续，不然就打住」，按预注册的读数打住）。实验代码在归档 tag `archive/vbx-voiceprint`。
- **理由**：
  - 只看声纹本身分不分得开人：新声纹在生产的喂法下反而更差；换成拼接喂法后各模型都好得多，同一个 ResNet34 在串轨素材上的人对错误降六成，新模型在它之上的增量正负参半。
  - 拼接喂法接上生产的 PLDA + VBx 聚类：护栏全过（姐姐咚咚 15 集不变，hina 19 份小幅变好、多来自原神那 10 份，约 −0.7%），挑方法用过的串轨素材大幅变好（魔裁剧情录像一对一错误 −13.4 个百分点）。
  - 但在没用过的串轨素材上没有复现：魔裁直播 4 小时，一对一错误 +2.2 个百分点 [−0.3, +4.8]，四小时里三小时变差。真正要的收益只出现在选方法用过的素材上。
  - 效率上拼接喂法每小时素材多约 7 s，不算收益。逐行置信标的系数在它上面可以沿用，不是障碍。
- **范围与重开条件**：有更多带真值、没用过的串轨素材时再看；最便宜的下一步是查直播上变差是否出在不在真值里的主播轨。换一个新的声纹模型重开时，同样先在留出的串轨素材上确认。
