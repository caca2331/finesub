# 反馈打包：把现场交到用户手里

产出一个 zip，路径打给用户。**到此为止。**

## 两种模式

| | `debug` | `corpus` |
| --- | --- | --- |
| 什么时候 | 用户碰到问题，要给开发者排查 | 用户愿意贡献素材，帮开发者改提示词与结构 |
| 收哪些任务 | 用户指名的（或最近出问题的那几次） | 尽量多，但**只收有精修字幕的**，且台账里没记过的 |
| 音频 | 分离出来的人声轨（16 kHz 单声道，一小时几 MB） | **完全不收** |
| 其余 | 字幕各档、`-annotated.csv`、`-stable.json`、`run-metadata.json`、`exchanges/`、运行日志 | 同左，去掉 `-vad*` 那两个大而可重建的 |

## 怎么跑

```powershell
# 用户碰到问题：一个或多个任务，带音频
python agent-tasks/feedback-pack/scripts/pack.py debug out/input/input.srt

# 分离本身可疑时才额外带上源媒体（几百 MB，先问用户）
python agent-tasks/feedback-pack/scripts/pack.py debug out/input/input.srt --with-source

# 贡献素材：每个任务都要指出哪份是精修字幕
python agent-tasks/feedback-pack/scripts/pack.py corpus `
  out/a/a.srt --refined out/a/a.srt=D:\subs\a-final.srt `
  out/b/b.srt --refined out/b/b.srt=D:\subs\b-final.srt

# 先看会打包什么（不写文件），念给用户听
python agent-tasks/feedback-pack/scripts/pack.py corpus out/a/a.srt --refined ... --dry-run
```

任务用**它交付的那个 SRT** 指认（`out/<stem>/<stem>.srt`）；其余产物全部由它派生，
和管线自己的做法一致（`README_DEV.md` 的产物树）。

## 你要做的判断

脚本只做搬运。三件事它不猜，得由你来定：

1. **哪些任务。** `debug` 里通常就是用户刚才说「这个不对」的那次。用户说不清时，
   按运行日志的时间倒序找最近几次，把候选念给他们确认——**别自己扩大范围**。
2. **哪份是精修字幕。** ⚠ 这是本任务唯一的硬缺口：`--refined-srt` 只是个调用参数，
   任务目录里**没有**固定名字的精修产物，所以脚本认不出来。问用户，或者从他们给的
   目录里找出对得上的那份，用 `--refined <任务SRT>=<精修SRT>` 显式交给脚本。
   `corpus` 模式没有它会直接报错——这是有意的，宁可报错也不要打包一堆没有对照的任务。
3. **要不要源媒体。** 默认不要。只有当问题看起来出在**人声分离**那一步（人声轨里
   有明显残留伴奏、或整段没声音）才值得，而且要先问用户——那通常是几百 MB。

## 台账：别让用户重复发同一份

脚本在数据根下记 `feedback/packed.json`，键是**模式 + 任务路径 + 内容指纹**。

⚠ 指纹里同时含交付字幕与精修字幕的大小/时间，所以**用户改进了精修版之后可以再发一次**
——只按路径去重会把那次贡献永远挡在外面。同一个任务先作为 bug 现场发过、后来又作为
语料发一次，也是两条独立记录，互不影响。

要无视台账重发（用户明确要求时）：`--ignore-ledger`。

## 隐私：这一段不能省

包里**确实**有这些东西，用户有权在发出去之前知道：

- 字幕全文（原始识别、纠错后、以及他们自己精修的那份）
- 每次 LLM 问答的完整记录，其中**包含知识库里被用到的条目原文**
- 运行日志与产物里的绝对路径，**通常含用户名**
- `debug` 模式下的人声轨——那是能听清内容的音频

包里**不会**有 API key、`.env`、以及 `config.toml` 里任何名字像密钥的项（白名单过滤，
不是黑名单：配置文件长出新键时它会漏在外面而不是被发出去）。

**做法**：跑完之后把 zip 里的 `MANIFEST.txt` 念给用户——它列的是实际打进去的每一个文件，
不是一段承诺。然后把路径给他们。

## 不要做什么

- ⚠ **不要替用户把包发出去。** 不上传、不贴 issue、不发邮件、不放进任何共享位置。
  只产出文件、给路径。用户问「能不能直接帮我发」时，告诉他们这一步得他们自己来。
- **不要用它诊断问题。** 用户问「为什么会这样」时那是 `run-audit`（只读审查）。
  两件事可以先后做，但别把审查结论当成打包的前提——现场先收好，分析随时可以再来。
- **不要为了凑数把没有精修字幕的任务塞进 `corpus`。** 没有对照的产物对改提示词没有用，
  只是让用户白发一堆数据。
- **不要默认带源媒体。** 见上面第 3 条。
- **不要改任何产物。** 这是只读的收集，不是清理、不是重跑、不是修复。
- **不要打包别的任务目录**，哪怕它就在旁边、哪怕看起来相关。用户指名的才收。
