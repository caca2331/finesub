素材概要（背景调查写的，只作背景，不据此认定谁开口）：雑談
素材里可能插播宣传片、游戏剧情等角色配音片段（也可能是别的语言）：这些行的说话人记片中的角色，不记节目里的人。节目成员介绍、模仿或拿角色开玩笑的行，说话人仍记那位成员。
声学层已经把录音分成了若干条**轨迹**（相对编号 s0、s1…），大多数行挂上了一个轨号。你拿到的是**连续的一段字幕**，要逐个 ▶ 行判断：这一行的轨号该不该改、改成什么，并定下字幕的形状：它和上一行并不并成一条、要不要丢掉（写法见后面「定字幕的形状」一节）。

⚠ 声学层常把**声音相近的几个人并进同一条轨**：一条轨的例句可能来自不同的人，轨号相同的连续几行也可能是两个人在对话。
反过来，一个人也可能被拆到几条轨。

你拿到：素材标题与候选人物；每条轨的画像（占多少语音、几句声学层最有把握是这条轨的话）；这一段字幕，每行 `开始秒|时长|gap|轨号|文字`，
标了 ▶ 和 id 的是要复核的行，其余是上下文。`??` 表示这一行声学层没挂上轨（也要复核：给它一条轨，或保持不挂）；`s5+s4` 表示这一行时间里两条轨都有声音、排在前面的是主轨。
一行里有时混着两个人的话（插话、附和、抢话）：判这一行**大部分是谁说的**。

**判断以台词内容为主**，按可靠性从高到低：
1. **对话结构**：这句在回答谁、谁在回答它。一问一答通常是两个人；一个人的话顺着往下说、中间没人插话，通常还是同一个人。
2. **称呼、自称与口癖**：句子里叫了谁的名字（被叫的人通常不是说话的人）、用了什么自称或口癖；和哪条轨的例句像同一个人。
3. **内容与语气的连续**：它是不是上一句或下一句、同一个人的话的延续。

声学层的轨号默认可信，没有明确的理由不改。

每个 ▶ 行的答案只能是下面几种之一：
- `keep`：现在的轨号是对的（`??` 行：保持不挂轨；`s5+s4` 行：主轨 s5 是对的）；
- 一条轨号：画像里列出的任意一条轨——如果画像里有一条轨就是这一行的说话人，用它；
- `@新轨`：**新建一条轨**。只在你判断这一行的说话人**不是**画像里任何一条轨的主人时用（混进一条轨里的人不是任何一条轨的主人时，也算新人）。写法是 `@` 加一个标签：认得出是谁就写名字（「候选人物」里有的，照抄括号前的写法；名单里没有的，写台词里对他的叫法），
  认不出就写 `@甲`、`@乙` 这样的代号。同一个标签就是同一条新轨，这一段里这个人的其他行也用同一个标签；
- `abstain`：证据不足。这是正当答案，改错比不改代价大。

输出格式：除 `<judge>` 与 `<tracks>` 两个块外不要输出任何其他文字，不要 Markdown 代码块。
- `<judge>`：每个 ▶ 行一行 JSON，覆盖每个 id、不多不少；每行三个字段：`id`、`track`（你的答案）、`why`（一句理由）；后面「定字幕的形状」一节还有三个可选字段。
- `<tracks>`：按你的答案改完之后，▶ 行最后挂着的每条轨和每个新标签各写一行 `轨号或标签 = 人名`，说它是谁；人名的写法同 `@新轨` 的标签，认不出写 `不明`。

## 定字幕的形状

除了轨号，每个 ▶ 行还可以带下面几个字段，只在为 true 时写进这一行的 JSON，用不上就不写。

`"join":true`：把这一行接到上一条保留下来的行后面，成为同一条字幕（上一行 drop 了，就接再上一条保留的行，说话人也跟那一行比）。这一段里第一个 ▶ 行不 join。
- 先要是同一个人：按你判完的说话人，不同的人绝不 join；这一行或它要接的那一行答了 `abstain`，不 join（所以 `abstain` 只留给内容显出可能换了人、只是定不了是谁的行；内容与声学层对不上、又说不清谁对时答 `keep`）。轨号相同本身不算同一个人（一条轨里可能混着几个声音相近的人），要从对话结构、称呼与口吻看出是同一个人接着说。反过来，同一个人被拆在两条轨上时，要 `join` 或 `may_join` 就把这一行的 `track` 答成和它要接的那一行同一条轨：脚本按你答的轨号认人，轨号不同的不并。一问一答、插话、附和、称呼对方，多半是两个人。重复或复述上一行的话，可能是同一个人重复，也可能是另一个人接话，看前后文判断；判不出是同一个人就不 join。
- 是同一个人时，看两件事：
  1. 停顿：长的自然停顿（gap 约 1 秒以上）不 join。中短的停顿，只在上一行单独读不成一句话时 join：词或短语被切成两行，或上一行停在「因为」「但是」「然后」「如果」「的话」这类连接处、后面明显还没说完（「……就是了」「对吧」这种已经说完的句尾不算）。上一行已是完整的一句、这一行只是补充或往下说：不 join，标 `may_join`（见下）；转折另起、情绪变了、换了话题的都不标。隔着 drop 的行接时，停顿按上一条保留的行结束到这一行开始算。
  2. 长度：join 只把短碎片接起来，并完（连同前面已经接上的行）是一条短字幕，大约 4 秒以内，一般只并两行；会更长的不 join，上一行没说完也一样，改标 `may_join`。有个大概就行，不用细算，超长的接法会被自动挡下。
- join 从严：下一步只并不拆，这里并错了改不回来；确定是同一个人接着说同一件事、只是拿不准上一行算不算说完或并完会不会太长的，标 `may_join`。判不出是不是同一个人的，join 和 `may_join` 都不标。
- 写了 join 的行，`why` 写出为什么是同一个人接着说。

`"may_join":true`：这一行是同一个人接着上一行往下说，只是不在这一步并（上一行已经是完整的一句，或并起来会比短字幕长）。下一步纠错会看纠错后的字幕长短决定并不并，但只在你标了 `may_join` 的地方并，所以认人这件事在这里做完。
- 条件和 join 一样先要是同一个人（判法同 join，判不出就不标），中间没有长的自然停顿，说的是同一件事、接着往下说；转折另起、换了话题、只是相关的不标（同一个人说完装备又说起晚饭，就不标）。
- `may_join` 只放宽断句与长度，认人的标准和 join 一样严，不是拿不准是不是同一个人时的折中。
- 写了 `may_join` 的行，`why` 写出为什么是同一个人接着说。一行只写 `join` 与 `may_join` 中的一个。

`"drop":true`：这一行整行不进字幕。只用于下面一种，`why` 写明理由：
- 确信的 ASR 幻觉：凭空出现的套话（感谢观看、订阅点赞一类），与前后对话脱节，前后有停顿或与前后台词明显断开，三点同时满足。
其余的行一律不 drop，包括：带实义词的行（识别得再乱也留着，下一步会纠错）；应答与附和（嗯、嗯嗯、对）；感叹、语气词、寒暄；主持人的转场、串场与报幕（「好，接下来」「那么」一类）；与上一行重复的行；时长或时间看着异常的行；整行只有垫词或口吃的行。单独一行的「嗯……」「啊」「哇」带情绪或在回应别人的，是语气词，留着；分不清是垫词还是语气词的也留着。拿不准就不 drop。drop 的行照常答 `track`。

字幕行里的 `时长` 是这一行的秒数，`gap` 是上一行结束到这一行开始的秒数，与上一行重叠时记 0。
例（id 是虚构的，与本段无关）：
{"id":"qE","track":"keep","why":"一直在自言自语、没有在回应别人，是同一个人接着说：上一行以「然后」收尾，gap 0.2 秒，并完约 2 秒","join":true}
{"id":"qF","track":"keep","why":"同一个人接着补充自己的上一句（中间没有人回答）：上一行已说完，gap 0.3 秒","may_join":true}
