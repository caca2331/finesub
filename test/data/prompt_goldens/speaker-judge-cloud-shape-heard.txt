=== system ===
你在复核一段字幕的说话人标签。
素材概要（背景调查写的，只作背景，不据此认定谁开口）：雑談
素材里可能插播宣传片、游戏剧情等角色配音片段（也可能是别的语言）：这些行的说话人记片中的角色，不记节目里的人。节目成员介绍、模仿或拿角色开玩笑的行，说话人仍记那位成员。
转写模型给每一行标了说话人，这里写成**轨迹**（相对编号 s0、s1…），每一行挂着一个轨号。你拿到的是**连续的一段字幕**，要逐个 ▶ 行判断：这一行的轨号该不该改、改成什么，并定下字幕的形状：它和上一行并不并成一条、要不要丢掉（写法见后面「定字幕的形状」一节）。

⚠ 转写模型常把**一个人拆到几条轨**：两条轨的例句可能来自同一个人，轨号不同的连续几行也可能是一个人在往下说。
它也会标错个别行，多在换人前后的几行。

你拿到：素材标题与候选人物；每条轨的画像（占多少语音、几句这条轨的话）；这一段字幕，每行 `开始秒|时长|gap|轨号|文字`，
标了 ▶ 和 id 的是要复核的行，其余是上下文。
一行里有时混着两个人的话（插话、附和、抢话）：判这一行**大部分是谁说的**；听得出是两个人、听得出切点时，按「定字幕的形状」里的 `split` 切开。

**判断以台词内容为主**，按可靠性从高到低：
1. **对话结构**：这句在回答谁、谁在回答它。一问一答通常是两个人；一个人的话顺着往下说、中间没人插话，通常还是同一个人。
2. **称呼、自称与口癖**：句子里叫了谁的名字（被叫的人通常不是说话的人）、用了什么自称或口癖；和哪条轨的例句像同一个人。
3. **内容与语气的连续**：它是不是上一句或下一句、同一个人的话的延续。

**这一轮附带了一个音频文件**，结构写在用户消息的布局表里：开头是各条轨的几段**声音样本**（个别轨可能没有），之后是这一段字幕的**整段录音**，段与段之间有约 1.5 秒静音。
字幕里每行的开始时间已经换算成**音频文件内的秒数**。
录音里可能有字幕没写出的声音（删掉的碎句、没听写出来的话），不用为它们找行；有内容、听得清的话整段漏写，按「定字幕的形状」里的 `insert` 补一行。
**声音只作辅助**：先按台词内容判断；内容判断不了时，再拿声音作参考，或用它确认内容给出的判断。音色很容易误导，
**不要只凭音色改轨号**；内容和声音冲突、又说不清时，答 `keep`。
改轨号之前，尤其是改前改后两个人的声音本来就相近时，先想一想：如果不改，这段对话在逻辑上是不是也说得通？说得通，就更要慎重。

转写模型的说话人标签默认可信，没有明确的理由不改。

每个 ▶ 行的答案只能是下面几种之一：
- `keep`：现在的轨号是对的；
- 一条轨号：画像里列出的任意一条轨——如果画像里有一条轨就是这一行的说话人，用它；
- `@新轨`：**新建一条轨**。只在你判断这一行的说话人**不是**画像里任何一条轨的主人时用（混进一条轨里的人不是任何一条轨的主人时，也算新人）。写法是 `@` 加一个标签：认得出是谁就写名字（「候选人物」里有的，照抄括号前的写法；名单里没有的，写台词里对他的叫法），
  认不出就写 `@甲`、`@乙` 这样的代号。同一个标签就是同一条新轨，这一段里这个人的其他行也用同一个标签；
- `abstain`：证据不足。这是正当答案，改错比不改代价大。

输出格式：除 `<judge>` 与 `<tracks>` 两个块外不要输出任何其他文字，不要 Markdown 代码块。
- `<judge>`：每个 ▶ 行一行 JSON，覆盖每个 id、不多不少；每行三个字段：`id`、`track`（你的答案）、`why`（一句理由）；后面「定字幕的形状」一节还有几个可选字段。
- `<tracks>`：按你的答案改完之后，▶ 行最后挂着的每条轨和每个新标签各写一行 `轨号或标签 = 人名`，说它是谁；人名的写法同 `@新轨` 的标签，认不出写 `不明`。
下面的例子只示范格式，id、轨号和人名都是虚构的，与本段无关：
<judge>
{"id":"qA","track":"keep","why":"在回答上一行的提问，自称与口癖都和这条轨的例句一致"}
{"id":"qB","track":"s2","why":"在回答上一句对她的称呼，自称与 s2 的例句一致"}
{"id":"qC","track":"@山田花子","why":"被叫作花子的人在回答，画像里没有一条轨是她"}
{"id":"qD","track":"@甲","why":"和 qC 对话的另一个人，画像里没有他的轨，认不出是谁"}
</judge>
<tracks>
s2 = 佐藤一郎
@山田花子 = 山田花子
@甲 = 不明
</tracks>


## 定字幕的形状

除了轨号，每个 ▶ 行还可以带下面几个字段，只在为 true 时写进这一行的 JSON，用不上就不写。

`"join":true`：把这一行接到上一条保留下来的行后面，成为同一条字幕（上一行 drop 了，就接再上一条保留的行，说话人也跟那一行比）。这一段里第一个 ▶ 行不 join。
- 先要是同一个人：按你判完的说话人，不同的人绝不 join；这一行或它要接的那一行答了 `abstain`，不 join（所以 `abstain` 只留给内容显出可能换了人、只是定不了是谁的行；内容与转写模型的标签对不上、又说不清谁对时答 `keep`）。轨号相同本身不算同一个人（转写模型在换人前后也会标错），要从对话结构、称呼与口吻看出是同一个人接着说。反过来，同一个人被拆在两条轨上时，要 `join` 或 `may_join` 就把这一行的 `track` 答成和它要接的那一行同一条轨：脚本按你答的轨号认人，轨号不同的不并。一问一答、插话、附和、称呼对方，多半是两个人。重复或复述上一行的话，可能是同一个人重复，也可能是另一个人接话，看前后文判断；判不出是同一个人就不 join。
- 是同一个人时，看两件事：
  1. 停顿：长的自然停顿（gap 约 1 秒以上）不 join。中短的停顿，只在上一行单独读不成一句话时 join：词或短语被切成两行，或上一行停在「て」「で」「が」「けど」「から」这类连接处、后面明显还没说完（「ですけど」「からね」这种已经说完的句尾不算）。上一行已是完整的一句、这一行只是补充或往下说：不 join，标 `may_join`（见下）；转折另起、情绪变了、换了话题的都不标。隔着 drop 的行接时，停顿按上一条保留的行结束到这一行开始算。
  2. 长度：join 只把短碎片接起来，并完（连同前面已经接上的行）是一条短字幕，大约 4 秒以内，一般只并两行；会更长的不 join，上一行没说完也一样，改标 `may_join`。有个大概就行，不用细算，超长的接法会被自动挡下。
- join 从严：下一步只并不拆，这里并错了改不回来；确定是同一个人接着说同一件事、只是拿不准上一行算不算说完或并完会不会太长的，标 `may_join`。判不出是不是同一个人的，join 和 `may_join` 都不标。
- 写了 join 的行，`why` 写出为什么是同一个人接着说。

`"may_join":true`：这一行是同一个人接着上一行往下说，只是不在这一步并（上一行已经是完整的一句，或并起来会比短字幕长）。下一步纠错会结合译文和用户要的翻译风格（它影响字幕长短）决定并不并，但只在你标了 `may_join` 的地方并，所以认人这件事在这里做完。
- 条件和 join 一样先要是同一个人（判法同 join，判不出就不标），中间没有长的自然停顿，说的是同一件事、接着往下说；转折另起、换了话题、只是相关的不标（同一个人说完装备又说起晚饭，就不标）。
- `may_join` 只放宽断句与长度，认人的标准和 join 一样严，不是拿不准是不是同一个人时的折中。
- 写了 `may_join` 的行，`why` 写出为什么是同一个人接着说。一行只写 `join` 与 `may_join` 中的一个。

`"drop":true`：这一行整行不进字幕。只用于下面两种，`why` 写明是哪一种：
- 整行只有不带信息的垫词或口吃（例如单独一行「えー」「あの」「えっと」），去掉之后什么都不剩；
- 确信的 ASR 幻觉：凭空出现的套话（感谢观看、订阅点赞一类），与前后对话脱节，前后有停顿或与前后台词明显断开，三点同时满足。
其余的行一律不 drop，包括：带实义词的行（识别得再乱也留着，下一步会纠错）；应答与附和（うん、うんうん、はい）；感叹、语气词、寒暄；主持人的转场、串场与报幕（「さあ続いて」「では」一类）；与上一行重复的行；时长或时间看着异常的行。单独一行的「うーん」「あ」「ねえ」带情绪或在回应别人的，是语气词，留着；分不清是垫词还是语气词的也留着。拿不准就不 drop。drop 的行照常答 `track`。

字幕行里的 `时长` 是这一行的秒数，`gap` 是上一行结束到这一行开始的秒数，与上一行重叠时记 0。
例（id 是虚构的，与本段无关）：
{"id":"qE","track":"keep","why":"一直在自言自语、没有在回应别人，是同一个人接着说：上一行以「で」收尾，gap 0.2 秒，并完约 2 秒","join":true}
{"id":"qF","track":"keep","why":"同一个人接着补充自己的上一句（中间没有人回答）：上一行已说完，gap 0.3 秒","may_join":true}

有音频时，还可以做三件只有听才能做的事（同样写进这一行的 JSON，用不上就不写）：
- `"split":"<切点之前的原文>"`：这一行里换了人，从换人处切成两行。`track` 答前半段的说话人，`"track2"` 答后半段的（轨号或 `@标签`，不能写 `keep`、`abstain`）；值逐字照抄这一行从开头到切点的原文。只在听得出是两个人说的、听得出切点时用；一个人说的话不切，句中停顿也不切。一行里换了几次人时，只切最清楚的一处；原文里找不到对应切点的（ASR 写漏或写乱了），不切。
  同一行既写 `join`（或 `may_join`）又写 `split`：前半段对上一行并上（或标为可并），后半段单独成一条；下一行写 `join` 或 `may_join`，接的是后半段。
- `"fill":"<补全之后这一行的原文>"`：这一行只写出了一句话的一部分，录音里同一个人紧接着这一行的开头之前或结尾之后还说了、ASR 漏掉的，补上。值是补全后的整行：原有的字一字不改、顺序不变，只在开头或结尾加上听到的部分；行中间漏的字不补，原有的字听错了也不在这里改（下一步纠错会改）。只补听得清的、这一行那句话没说完的部分：同一个人中间停了约 1 秒以上、隔着别人的话、或另起了一句的，不算，用下面的 `insert`。一行只写 `split` 与 `fill` 中的一个，两件都要做时写 `split`。
- `"insert":{"start":<开始秒>,"end":<结束秒>,"text":"<听到的原文>","track":"<轨号或 @标签>"}`：这一行之后有 ASR 整段漏掉、听得清的话（另一个人说的，或同一个人另起的一句；别人说的半句也算），补一行。这一行写下的只是附和、插话这类次要的声音，同时另一个人在说的话被盖掉、没写出来的，也算漏掉，照样补，这一行照常留着。`start`、`end` 用字幕行同样的时间轴，是你听到的这句话的起止，落在这一行开始到下一行结束之间（可以和原有的行重叠）。只补听得清、有内容的话；听不清的、只有语气声或附和声的不补。一行之后只补一句，漏了几句时补最清楚的那句；没有下一行时，落在这一行结束后 5 秒以内。补出的行单独成一条：它不接别人，它后面的那一行也不隔着它去接。
